# Guía de TypeScript: De 0 a 100

## ¿Qué es TypeScript?

TypeScript es un lenguaje de programación de tipado estático opcional que compila a JavaScript. Fue creado por **Anders Hejlsberg** (arquitecto de Turbo Pascal y C#) en Microsoft y lanzado públicamente en octubre de 2012. Es un **superset de JavaScript**: todo JS válido es TS válido, y el compilador añade análisis de tipos en tiempo de desarrollo sin modificar el comportamiento runtime.

**Principios clave:**
- **Tipado estructural (duck typing en compilación)**: si dos objetos tienen la misma forma, son del mismo tipo — no importa el nombre de la clase
- **Inferencia de tipos**: TypeScript deduce tipos automáticamente sin necesidad de anotarlos siempre
- **Errores en compilación, no en runtime**: los errores de tipo se detectan antes de ejecutar
- **Sin costo runtime**: los tipos se borran en la compilación; el JS generado no tiene overhead de tipos

**¿Dónde se usa?**
- **Frontend web**: React, Vue, Angular, Svelte — todos con soporte TS nativo
- **Backend**: Node.js con Express, Fastify, NestJS, Hono, tRPC
- **Full-stack**: Next.js, Nuxt, Remix, SvelteKit — frameworks que integran frontend y backend
- **Infraestructura**: AWS CDK, Terraform CDK, Pulumi están escritos en TypeScript
- **Herramientas**: Vite, Astro, Turborepo, Playwright, Prisma, Drizzle
- **Mobile**: React Native, Capacitor, NativeScript

**¿Quién lo usa?** Microsoft (VS Code, Teams), Google (Angular), Figma (aplicación de escritorio), Slack (desktop y web), Airbnb, Asana, Notion, Vercel, Linear.

Fuente: [TypeScript Handbook — The Basics](https://www.typescriptlang.org/docs/handbook/2/basic-types.html), [TypeScript GitHub — History](https://github.com/microsoft/TypeScript/wiki/TypeScript-Repository-Overview)

## ¿Cómo empezar? Instalación en todos los entornos

### npm (Node.js — necesario para compilar)

Primero instala Node.js desde [nodejs.org](https://nodejs.org/) (versión LTS recomendada). Luego:

```bash
# Instalación global del compilador
npm install -g typescript

# Verificar
tsc --version

# En un proyecto
npm init -y
npm install --save-dev typescript @types/node
npx tsc --init  # crea tsconfig.json
```

### npx (ejecutar sin instalar global)

```bash
npx tsc --version
npx tsc archivo.ts        # Compila un archivo
npx tsc --init --strict   # Crea tsconfig con strict mode
```

### ts-node (ejecutar TS directamente en Node)

```bash
npm install -g ts-node
ts-node script.ts  # Compila y ejecuta al vuelo
```

### tsx (alternativa moderna a ts-node, más rápida)

```bash
npm install -g tsx
tsx script.ts    # Usa esbuild bajo el capó
```

### Bun (runtime nativo con TS incorporado)

```bash
curl -fsSL https://bun.sh/install | bash
bun run archivo.ts           # Sin configuración
bun init                     # Inicia proyecto bun
```

Bun entiende TypeScript nativamente. No necesita `tsc` ni `tsconfig.json` para ejecutar archivos. Usa el runtime de JavaScriptCore de WebKit.

### Deno (runtime nativo con TS incorporado)

```bash
curl -fsSL https://deno.land/install.sh | sh
deno run main.ts                  # Sin configuración
deno run --allow-net main.ts      # Permisos explícitos
deno init                         # Inicia proyecto
```

Deno ejecuta TypeScript nativamente con el compilador TSC integrado. Usa URLs para imports en lugar de npm.

### Docker

```dockerfile
FROM node:22-slim
WORKDIR /app
COPY package*.json tsconfig.json ./
RUN npm ci
COPY . .
RUN npx tsc
CMD ["node", "dist/index.js"]
```

Usa `node:22-slim` como base (~130 MB). Build en dos etapas para producción:

```dockerfile
# Build stage
FROM node:22-slim AS build
WORKDIR /app
COPY package*.json tsconfig.json ./
RUN npm ci
COPY . .
RUN npx tsc

# Production stage
FROM node:22-slim
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
CMD ["node", "dist/index.js"]
```

## Primeros pasos y configuración del entorno

### tsconfig.json — el corazón de la configuración

Creado con `npx tsc --init`. Archivo central que controla cómo TypeScript compila:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "outDir": "./dist",
    "rootDir": "./src",
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "noUncheckedIndexedAccess": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

**Opciones críticas:**
- `strict: true` — activa todas las comprobaciones estrictas (noopUncheckedIndexedAccess no está incluido)
- `noUncheckedIndexedAccess: true` — al acceder a un índice de array/objeto, el tipo incluye `undefined`. `arr[0]` es `T | undefined`
- `target: "ES2022"` — a qué versión de JS compilar. ES2022 incluye top-level await, at(), hasOwn
- `module: "NodeNext"` — para módulos ES nativos con Node.js
- `declaration: true` — genera archivos `.d.ts` para librerías
- `skipLibCheck: true` — no comprueba tipos en `node_modules` (acelera build)

## Conceptos clave explicados a fondo

### Tipado estructural vs nominal

TypeScript usa **tipado estructural** (structural typing). Si dos tipos tienen la misma forma, son compatibles. No importa el nombre ni la herencia.

```typescript
interface Persona {
  nombre: string;
  edad: number;
}

interface Empleado {
  nombre: string;
  edad: number;
  salario: number;
}

const p: Persona = { nombre: "Ana", edad: 30 };
const e: Empleado = { nombre: "Luis", edad: 28, salario: 50000 };

// OK: Empleado tiene todas las propiedades de Persona
const p2: Persona = e;
```

Esto es diferente de lenguajes como Java o C# (**tipado nominal**), donde `Persona` y `Empleado` serían incompatibles aunque tengan los mismos campos. En TypeScript, mientras la estructura coincida, los tipos son compatibles.

### Inferencia de tipos

TypeScript deduce tipos automáticamente en la mayoría de los casos:

```typescript
let x = 5;           // x: number (inferido)
let nombre = "Ana";  // nombre: string (inferido)

// Inferencia en retorno de funciones
function suma(a: number, b: number) {
  return a + b;  // Tipo de retorno inferido: number
}

// Inferencia contextual
const nums = [1, 2, 3].map(n => n * 2);  // n inferido como number
```

No necesitas anotar todo. Las anotaciones son necesarias en:
1. Parámetros de función (si no hay contexto)
2. Declaraciones sin inicializador
3. Tipos de retorno que quieras forzar explícitamente

### Tipos primitivos vs literales

**Primitivos:** `string`, `number`, `boolean`, `symbol`, `bigint`, `null`, `undefined`

```typescript
const nombre: string = "Ana";
const edad: number = 30;
const activo: boolean = true;
```

**Literales (tipos que son valores concretos):**

```typescript
type Direccion = "norte" | "sur" | "este" | "oeste";
type Par = 2 | 4 | 6 | 8 | 10;
type SoloTrue = true;

const dir: Direccion = "norte";  // OK
// dir = "noroeste";  // Error: no es "norte" | "sur" | "este" | "oeste"
```

Con `as const`, TypeScript deduce literales en lugar de tipos generales:

```typescript
const config = {
  url: "https://api.example.com",
  timeout: 5000,
} as const;

// config.timeout es el literal 5000, no number
// config.url es "https://api.example.com", no string
```

### Interfaces vs Types

Ambos definen la forma de un objeto, pero con diferencias clave:

```typescript
// Interface — extensible por declaración merging
interface Usuario {
  nombre: string;
  email: string;
}

interface Usuario {
  edad?: number;  // Se fusiona con la anterior
}

// Type — no extensible, pero más expresivo
type Id = string | number;
type Estado = "activo" | "inactivo" | "pendiente";
type Callback<T> = (data: T) => void;
type Parcial<T> = { [K in keyof T]?: T[K] };
```

| Característica | Interface | Type |
|---|---|---|
| Declaración merging | Sí | No |
| Extender | `extends` | `&` (intersección) |
| Uniones | No | Sí |
| Mapped types | No | Sí |
| Tuplas | Describe con `[]` | Describe con `[]` |
| Rendimiento | Generalmente mejor | Bien |

**Regla práctica:** usa `interface` para objetos/API públicas; usa `type` para uniones, tuplas, y tipos computados.

### Uniones discriminadas (Discriminated Unions)

Una unión de objetos con una propiedad literal común (el discriminante). TypeScript puede estrechar el tipo basándose en esa propiedad:

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rectangle"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
  }
}
```

El switch/case con el discriminante `kind` permite a TypeScript estrechar el tipo en cada rama. No necesitas type guards manuales.

### Narrowing (estrechamiento de tipos)

TypeScript estrecha tipos automáticamente mediante varias técnicas:

```typescript
function procesar(valor: string | number | Date | null) {
  // typeof narrowing
  if (typeof valor === "string") {
    console.log(valor.toUpperCase());  // valor: string
  }

  // instanceof narrowing
  if (valor instanceof Date) {
    console.log(valor.getFullYear());  // valor: Date
  }

  // Truthy/falsy narrowing
  if (valor == null) {
    console.log("Es null o undefined");  // valor: null
  }

  // in narrowing
  if ("length" in valor) {
    console.log(valor.length);  // valor: string | (no entra Date)
  }
}
```

### Type Guards personalizados

Cuando el narrowing automático no es suficiente, escribes funciones que verifican tipos en runtime:

```typescript
interface Pajaro {
  tipo: "pajaro";
  volar: () => void;
}

interface Pez {
  tipo: "pez";
  nadar: () => void;
}

type Animal = Pajaro | Pez;

// Type guard
function esPajaro(animal: Animal): animal is Pajaro {
  return animal.tipo === "pajaro";
}

function mover(animal: Animal) {
  if (esPajaro(animal)) {
    animal.volar();  // TypeScript sabe que es Pajaro
  } else {
    animal.nadar();  // TypeScript sabe que es Pez
  }
}
```

### Genéricos

Los genéricos permiten escribir código reusable sin perder el tipo:

```typescript
// Función genérica básica
function identidad<T>(arg: T): T {
  return arg;
}

const num = identidad(42);     // T inferido como number
const str = identidad("hola"); // T inferido como string

// Genéricos con arrays
function primero<T>(arr: T[]): T | undefined {
  return arr[0];
}

// Múltiples type parameters
function zip<A, B>(a: A[], b: B[]): [A, B][] {
  return a.map((x, i) => [x, b[i]]);
}
```

### Constraints (restricciones en genéricos)

Limitas qué tipos puede aceptar un genérico con `extends`:

```typescript
interface Lengthwise {
  length: number;
}

function logLongitud<T extends Lengthwise>(arg: T): T {
  console.log(arg.length);  // Sabemos que tiene .length
  return arg;
}

logLongitud("hola");    // string tiene .length
logLongitud([1, 2, 3]); // array tiene .length
// logLongitud(42);     // Error: number no tiene .length

// Keyof constraint
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { nombre: "Ana", edad: 30 };
getProperty(user, "nombre");  // string
// getProperty(user, "email");  // Error: "email" no es keyof user
```

### Conditional Types

Tipos que dependen de una condición evaluada en tiempo de compilación:

```typescript
type IsString<T> = T extends string ? "sí" : "no";

type A = IsString<string>;  // "sí"
type B = IsString<number>;  // "no"

// Extraer tipos de una función
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type Fn = (x: number) => string;
type R = ReturnType<Fn>;  // string

// Distributive conditional types
type ToArray<T> = T extends unknown ? T[] : never;
type Result = ToArray<string | number>;  // string[] | number[]
```

### Mapped Types

Transforman un tipo existente en uno nuevo, propiedad por propiedad:

```typescript
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

type Optional<T> = {
  [K in keyof T]?: T[K];
};

type Nullable<T> = {
  [K in keyof T]: T[K] | null;
};

// Mapped type con modificación
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface Persona {
  nombre: string;
  edad: number;
}

// Equivale a:
// type GettersPersona = {
//   getNombre: () => string;
//   getEdad: () => number;
// }
```

### Template Literal Types

Construyen tipos a partir de manipulación de strings literales:

```typescript
type EventName = `on${Capitalize<string>}`;
type Handler = `handle${Capitalize<string>}`;

// Ejemplo real: rutas tipadas
type Route = `/api/${string}`;

// Extracción de parámetros de ruta
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParams<Rest>
    : T extends `${string}:${infer Param}`
      ? Param
      : never;

type R = ExtractParams<"/api/users/:userId/posts/:postId">;
// "userId" | "postId"
```

### `unknown` vs `any`

```typescript
let any_val: any = 42;
any_val.toUpperCase();  // Sin error (en runtime: TypeError)
any_val.prop.no.existe; // Sin error (en runtime: TypeError)

let unknown_val: unknown = 42;
// unknown_val.toUpperCase();  // Error: Object is of type 'unknown'

// Para usar unknown, debes verificar:
if (typeof unknown_val === "string") {
  unknown_val.toUpperCase();  // OK
}

// Cast necesario
const str = unknown_val as string;
```

`any` desactiva completamente el sistema de tipos. `unknown` es el tipo seguro: fuerza verificación antes de usar. **Nunca uses `any` explícitamente.** Configura `@typescript-eslint/no-explicit-any: "error"`.

### `never`

El tipo `never` representa valores que nunca ocurren. Es el **bottom type**:

```typescript
// Función que nunca retorna
function error(msg: string): never {
  throw new Error(msg);
}

// Bucles infinitos
function loop(): never {
  while (true) {}
}
```

`never` es útil para exhaustiveness checking en uniones discriminadas:

```typescript
type Color = "rojo" | "verde" | "azul";

function hexColor(c: Color): string {
  switch (c) {
    case "rojo": return "#FF0000";
    case "verde": return "#00FF00";
    case "azul": return "#0000FF";
    default:
      // Si añades un nuevo color y no lo manejas,
      // esto da error de compilación
      const _exhaustive: never = c;
      return _exhaustive;
  }
}
```

### `void`

`void` es el tipo de retorno de funciones que no devuelven un valor útil:

```typescript
function log(msg: string): void {
  console.log(msg);
  // No hay return, o return undefined implícito
}

// Diferencia clave:
// void: la función no debe usar el valor retornado
// undefined: la función retorna undefined explícitamente
type FnVoid = () => void;
type FnUndefined = () => undefined;
```

### Decoradores (experimentales y TC39)

**Decoradores experimentales (TypeScript 5.x legacy):**

```typescript
// tsconfig.json: "experimentalDecorators": true

function logMethod(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`Llamando ${propertyKey} con`, args);
    return original.apply(this, args);
  };
  return descriptor;
}

class Calculadora {
  @logMethod
  sumar(a: number, b: number): number {
    return a + b;
  }
}
```

**Decoradores TC39 (ES standard, desde TypeScript 5.0):**

```typescript
// Sin flags, nativo en target ES2022+

function logged<T extends (...args: any[]) => any>(
  target: T,
  context: ClassMethodDecoratorContext
) {
  return function (this: any, ...args: Parameters<T>) {
    console.log(`Llamando ${String(context.name)}`);
    return target.apply(this, args);
  };
}

class Calculadora {
  @logged
  sumar(a: number, b: number): number {
    return a + b;
  }
}
```

### `keyof`, `typeof`, `satisfies`

`keyof` — obtiene la unión de claves de un tipo:

```typescript
interface Persona {
  nombre: string;
  edad: number;
  email: string;
}

type Claves = keyof Persona;  // "nombre" | "edad" | "email"
```

`typeof` en contexto de tipo — obtiene el tipo de un valor en tiempo de compilación:

```typescript
const config = {
  url: "https://api.example.com",
  timeout: 5000,
};

type ConfigType = typeof config;
// { url: string; timeout: number; }
```

`satisfies` (TypeScript 4.9+) — verifica que un valor cumple un tipo sin cambiar su tipo inferido:

```typescript
// Sin satisfies
const palette: Record<string, string | string[]> = {
  rojo: "#FF0000",
  verde: "#00FF00",
  azul: ["#0000FF", "#00BFFF"],
};
palette.rojo.toUpperCase();  // Error: string | string[] no tiene .toUpperCase()

// Con satisfies — verifica pero mantiene el tipo estrecho
const palette2 = {
  rojo: "#FF0000",
  verde: "#00FF00",
  azul: ["#0000FF", "#00BFFF"],
} satisfies Record<string, string | string[]>;

palette2.rojo.toUpperCase();  // OK: TypeScript sabe que es string
palette2.azul.map(c => c);    // OK: TypeScript sabe que es string[]
```

### Módulos y `declare`

**Módulos ES en TypeScript:**

```typescript
// math.ts
export function sumar(a: number, b: number): number {
  return a + b;
}

export const PI = 3.1416;

// app.ts
import { sumar, PI } from "./math.js";  // .js en output, .ts en source
```

**`declare` — declarar algo que existe en runtime pero TypeScript no conoce:**

```typescript
// Declarar una variable global
declare const API_KEY: string;
// No genera código JS, solo informa al compilador

// Declarar módulos (para librerías sin tipos)
declare module "mi-lib-sin-tipos" {
  export function saludar(nombre: string): string;
}

// Ambient declarations
declare namespace MiGlobal {
  function init(): void;
}
```

### Archivos `.d.ts`

Los archivos `.d.ts` son **declaration files**. Contienen solo tipos, sin implementación. TypeScript los usa para entender librerías JS sin tipo:

```typescript
// ejemplo.d.ts
export interface Usuario {
  id: number;
  nombre: string;
  email: string;
}

export function obtenerUsuario(id: number): Promise<Usuario>;
```

Las librerías TS generan `.d.ts` automáticamente con `declaration: true`. Si una librería JS no tiene tipos, busca `@types/paquete` en DefinitelyTyped: `npm install --save-dev @types/express`.

### Strict Mode y `noUncheckedIndexedAccess`

**`strict: true`** activa 7 flags a la vez:

| Flag | Efecto |
|---|---|
| `strictNullChecks` | `null`/`undefined` no son asignables a otros tipos |
| `strictFunctionTypes` | Comprobación estricta de tipos en funciones (contravarianza) |
| `strictBindCallApply` | `bind`/`call`/`apply` con tipos correctos |
| `strictPropertyInitialization` | Las propiedades de clase deben inicializarse |
| `noImplicitAny` | Error si TS no puede inferir un tipo |
| `noImplicitThis` | Error si `this` no tiene tipo explícito |
| `alwaysStrict` | `"use strict"` en todo el JS emitido |

**`noUncheckedIndexedAccess`** — al acceder a un índice, el tipo incluye `undefined`:

```typescript
const arr: string[] = ["a", "b", "c"];
const first = arr[0];  // string | undefined (con noUncheckedIndexedAccess)
// string (sin noUncheckedIndexedAccess)

// Te fuerza a verificar
if (first !== undefined) {
  first.toUpperCase();  // OK: string
}
```

### Decoradores

TypeScript tiene dos sistemas de decoradores: los experimentales (`experimentalDecorators: true`) y los decoradores TC39 estándar desde TypeScript 5.0.

**Cómo funciona internamente (experimental):**

```typescript
// Esto:
@miDecorador
class MiClase {}

// Es equivalente a:
MiClase = miDecorador(MiClase) || MiClase;
```

**Decorador de método (experimental):**

```typescript
function medirTiempo(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    const inicio = performance.now();
    const resultado = original.apply(this, args);
    const fin = performance.now();
    console.log(`${propertyKey} tardó ${fin - inicio}ms`);
    return resultado;
  };
  return descriptor;
}

class Calculadora {
  @medirTiempo
  factorial(n: number): number {
    return n <= 1 ? 1 : n * this.factorial(n - 1);
  }
}
```

**Decoradores con argumentos (experimental):**

```typescript
function repetir(n: number) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = function (...args: any[]) {
      for (let i = 0; i < n; i++) {
        original.apply(this, args);
      }
    };
    return descriptor;
  };
}

class Saludos {
  @repetir(3)
  saludar() {
    console.log("Hola!");
  }
}
```

**Decoradores TC39 estándar (TypeScript 5.0+, sin flags):**

```typescript
function medirTiempo<This, Args extends any[], Return>(
  target: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Return>
) {
  return function (this: This, ...args: Args): Return {
    const inicio = performance.now();
    const resultado = target.call(this, ...args);
    const fin = performance.now();
    console.log(`${String(context.name)} tardó ${fin - inicio}ms`);
    return resultado;
  };
}

class Calculadora {
  @medirTiempo
  factorial(n: number): number {
    return n <= 1 ? 1 : n * this.factorial(n - 1);
  }
}
```

**¿Con qué se relaciona en otras tecnologías?**
- **Python**: `@decorador` — mismo concepto, misma sintaxis de azúcar
- **Java**: Anotaciones + Annotation Processors (aunque en Java es metaprogramación en compilación, no runtime)
- **JavaScript**: Decoradores TC39 — exactamente los mismos, TS está alineado
- **NestJS**: Los decoradores son la base del framework (`@Controller`, `@Get`, `@Injectable`)
- **Express.js**: Middleware `app.use((req, res, next) => ...)` funciona como decorador conceptual
- **AOP (Aspect-Oriented Programming)**: Los decoradores son la forma TypeScript de lograr AOP para logging, caché, autorización

**Decoradores que proporcionan librerías:**
- **NestJS**: `@Controller()`, `@Get()`, `@Post()`, `@Injectable()`, `@Module()`
- **TypeORM**: `@Entity()`, `@Column()`, `@PrimaryGeneratedColumn()`, `@ManyToOne()`
- **class-validator**: `@IsString()`, `@IsEmail()`, `@Min()`, `@Max()`
- **class-transformer**: `@Exclude()`, `@Expose()`, `@Transform()`
- **Angular**: `@Component()`, `@Injectable()`, `@Input()`, `@Output()`

### Variables, memoria y objetos

TypeScript hereda el modelo de memoria de JavaScript. Todo valor es un objeto (excepto primitivos), y las variables son referencias a objetos.

**Primitivos (inmutables, almacenados por valor):**

```typescript
let a = 5;
let b = a;  // Copia el valor
a = 10;
console.log(b);  // 5 (no cambia)

// Los primitivos se comparan por valor
console.log(5 === 5);  // true
console.log("hola" === "hola");  // true
```

**Objetos (mutables, almacenados por referencia):**

```typescript
const obj1 = { x: 1 };
const obj2 = obj1;  // Copia la referencia
obj1.x = 2;
console.log(obj2.x);  // 2 (comparten el mismo objeto)

// Se comparan por referencia
console.log({} === {});  // false (objetos distintos)
```

**Mutabilidad en TypeScript/JS:**

| Tipo | Mutabilidad | Ejemplo |
|---|---|---|
| `number` | Inmutable | `let x = 5; x += 1` — nuevo número |
| `string` | Inmutable | `let s = "hola"; s += "!"` — nueva cadena |
| `boolean` | Inmutable | `let b = true; b = false` — nuevo booleano |
| `object` | Mutable | `obj.prop = "valor"` — modifica el mismo objeto |
| `Array` | Mutable | `arr.push(1)` — modifica el mismo array |
| `Map`/`Set` | Mutable | `map.set(k, v)` — modifica el mismo mapa |
| `symbol` | Inmutable | Único, no modificable |

**Cómo JavaScript/TypeScript optimiza memoria:**

- **String interning**: El motor (V8, SpiderMonkey) cachea cadenas cortas e internas. Cadenas iguales pueden compartir memoria.
- **Object pooling**: V8 optimiza objetos con la misma "forma" (same hidden class). Añadir propiedades dinámicamente cambia la forma y ralentiza.
- **Array optimization**: Arrays homogéneos (todos del mismo tipo) son más rápidos que arrays heterogéneos. V8 los optimiza como arrays tipados internamente.

**¿Cuánto ocupa cada cosa? (aproximado en V8):**

```typescript
// Estos números son aproximados y dependen del motor
console.log(new Uint8Array(1).byteLength);  // 1 byte
console.log(new Array(100).fill(0).length); // ~800 bytes + overhead
```

Cada objeto JS tiene overhead: ~32-64 bytes para el objeto base (hidden class, propiedades inline). Un array de 1M números ocupa ~8 MB para las referencias + memoria de los números.

**Garbage collection en JS:**

JavaScript usa **GC generacional** (V8: Orinoco + Oilpan). No tiene reference counting como Python. El GC Mark-and-Sweep recorre el grafo de objetos desde las raíces (globales, DOM,栈) y recolecta los inalcanzables. Las generaciones jóvenes se recolectan con más frecuencia (Scavenger).

```typescript
// No puedes forzar GC en JS estándar
// Pero en Node.js:
if (global.gc) {
  global.gc();  // Forzar GC (requiere --expose-gc)
}
```

**¿Hay buffer overflow en TypeScript/JS?**
No en JS puro. Los arrays, strings y TypedArrays tienen bounds checking nativo. `arr[100]` en un array de 5 elementos retorna `undefined` (no corrompe memoria, no lanza error). El peligro real está en:
1. **TypedArrays mal usados**: `new Uint8Array(buffer, offset, length)` — si offset + length excede el buffer, lanza `RangeError`
2. **WebAssembly**: código WASM puede acceder a memoria lineal arbitraria si no se valida
3. **Node.js Buffers**: `Buffer.allocUnsafe(100)` puede contener datos previos (memoria no inicializada)
4. **Native addons**: módulos nativos (C++, Rust via napi) pueden tener buffer overflows si el código subyacente está mal escrito

Para JS puro, la sobreescritura de buffer no existe. El motor verifica todos los accesos.

**`Object.freeze` y `Readonly` para inmutabilidad:**

```typescript
import { deepFreeze } from 'some-lib'; // o implementación manual

// En tiempo de compilación
interface Config {
  readonly url: string;
  readonly timeout: number;
}

// En tiempo de ejecución
const config = Object.freeze({
  url: "https://api.example.com",
  timeout: 5000,
  // No se puede modificar en runtime
});
```

### Peculiaridades del lenguaje que debes conocer

**1. TypeScript no es JavaScript con tipos — es JS con un sistema de tipos**

TypeScript no añade funcionalidad runtime. No hay `reflect`, no hay type checking en runtime (los tipos se borran). El código que escribes se transforma en JS puro.

```typescript
// Esto:
interface Usuario { nombre: string }
function saludar(u: Usuario) { return u.nombre; }

// Compila a esto:
function saludar(u) { return u.nombre; }
// La interfaz desaparece completamente
```

**2. Los tipos son estructurales, no nominales**

```typescript
interface Persona { nombre: string; edad: number }
interface Empleado { nombre: string; edad: number; salario: number }

const p: Persona = { nombre: "Ana", edad: 30 };
const e: Empleado = { nombre: "Luis", edad: 28, salario: 50000 };

// Esto funciona porque Empleado es estructuralmente compatible
const p2: Persona = e;
```

Esto es distinto de Java/C# y más parecido a cómo funcionan los Protocols de Python (PEP 544).

**3. Branded types (tipos nominales simulados)**

Cuando necesitas distinción nominal (ej: dos IDs del mismo tipo base), usas branded types:

```typescript
type UserId = string & { readonly __brand: "UserId" };
type PostId = string & { readonly __brand: "PostId" };

function createUser(id: UserId) { /* ... */ }

const uid = "abc123" as UserId;
const pid = "abc123" as PostId;

createUser(uid);  // OK
// createUser(pid);  // Error: no es UserId
```

**4. `as const` — el mejor amigo del desarrollador**

```typescript
// Sin as const
const colores = { rojo: "#FF0000", verde: "#00FF00" };
// typeof colores = { rojo: string; verde: string }

// Con as const
const colores = { rojo: "#FF0000", verde: "#00FF00" } as const;
// typeof colores = { readonly rojo: "#FF0000"; readonly verde: "#00FF00" }
```

**5. Type Assertions (`as`) — úsalas con cuidado**

```typescript
const valor: unknown = "Hola mundo";
const longitud = (valor as string).length;  // OK, sabemos que es string

// Pero no mientas:
const num = 42;
// (num as string).length;  // Compila, pero en runtime es undefined
```

Prefiere `satisfies` y type guards antes que `as`.

**6. `this` en TypeScript**

TypeScript puede tipar `this` explícitamente:

```typescript
function saludar(this: { nombre: string }) {
  console.log(`Hola, ${this.nombre}`);
}

const obj = { nombre: "Ana", saludar };
obj.saludar();  // OK: this es el objeto
```

**7. `readonly` y `const` — diferencias**

- `const` es una declaración: la variable no se puede reasignar
- `readonly` es una propiedad: no se puede modificar después de la inicialización
- `as const` hace que todo el objeto sea deep readonly

```typescript
const obj: { readonly x: number } = { x: 5 };
// obj.x = 10;  // Error: x es readonly
// obj = {};    // Error: obj es const

const obj2 = { x: 5, y: { z: 10 } } as const;
// obj2.y.z = 20;  // Error: deep readonly
```

**8. Overloads de funciones**

TypeScript permite múltiples firmas para una misma función:

```typescript
function procesar(valor: string): string;
function procesar(valor: number): number;
function procesar(valor: boolean): boolean;
function procesar(valor: string | number | boolean): string | number | boolean {
  if (typeof valor === "string") return valor.toUpperCase();
  if (typeof valor === "number") return valor * 2;
  return !valor;
}
```

**9. Tuple variadic y labeled tuples**

```typescript
// Tuplas etiquetadas
type Rango = [inicio: number, fin: number];

// Tuplas variádicas
type StringNumber<T extends any[]> = [...T, string, number];
type Result = StringNumber<[boolean]>;  // [boolean, string, number]
```

**10. `this` parameter en callbacks**

```typescript
interface UIElement {
  onClick(callback: (this: void, event: Event) => void): void;
}
// this: void significa que el callback no debe usar this
```

## Ejemplo completo de POO en TypeScript

Este ejemplo une todos los conceptos de POO explicados arriba en un sistema realista de biblioteca multimedia. Léelo de arriba a abajo: cada clase añade una capa.

```typescript
import { randomUUID } from "node:crypto";

// ── Enums y tipos base ──

enum FormatoVideo {
  MP4 = "mp4",
  WEBM = "webm",
  AVI = "avi",
  MKV = "mkv",
}

interface Metadatos {
  readonly titulo: string;
  readonly duracionSegundos: number;
  readonly fechaCreacion: Date;
  readonly tags: string[];
}

// ── Clase abstracta base ──

abstract class Contenido {
  protected _reproducciones = 0;
  readonly id: string;

  constructor(
    protected _metadatos: Metadatos,
    id?: string
  ) {
    this.id = id ?? randomUUID();
  }

  get metadatos(): Metadatos {
    return this._metadatos;
  }

  get reproducciones(): number {
    return this._reproducciones;
  }

  reproducir(): string {
    this._reproducciones++;
    return `▶️ Reproduciendo ${this._metadatos.titulo}...`;
  }

  abstract obtenerInfo(): string;

  duracionFormateada(): string {
    const mins = Math.floor(this._metadatos.duracionSegundos / 60);
    const segs = this._metadatos.duracionSegundos % 60;
    return `${mins}:${segs.toString().padStart(2, "0")}`;
  }

  toString(): string {
    return `[${this.constructor.name}] ${this._metadatos.titulo}`;
  }
}

// ── Herencia simple ──

class Audio extends Contenido {
  constructor(
    metadatos: Metadatos,
    public readonly bitrateKbps: number
  ) {
    super(metadatos);
  }

  obtenerInfo(): string {
    return `🎵 ${this.metadatos.titulo} | ` +
      `${this.duracionFormateada()} | ` +
      `${this.bitrateKbps}kbps | ` +
      `${this.reproducciones} reproducciones`;
  }
}

class Video extends Contenido {
  private _subtitulos = false;

  constructor(
    metadatos: Metadatos,
    public readonly resolucion: string,
    public readonly formato: FormatoVideo
  ) {
    super(metadatos);
  }

  get subtitulos(): boolean {
    return this._subtitulos;
  }

  set subtitulos(valor: boolean) {
    this._subtitulos = valor;
  }

  obtenerInfo(): string {
    return `🎬 ${this.metadatos.titulo} | ` +
      `${this.resolucion} | ` +
      `${this.formato} | ` +
      `${this._subtitulos ? "CC" : "Sin subtítulos"}`;
  }
}

// ── Mixin (simulado con implements + helper) ──

interface Exportable {
  exportar(formato?: string): string;
}

function ExportableMixin<TBase extends abstract new (...args: any[]) => any>(
  Base: TBase
) {
  abstract class ExportableClass extends Base implements Exportable {
    exportar(formato: string = "json"): string {
      if (formato === "json") {
        return JSON.stringify(this, null, 2);
      }
      return `Exportación a ${formato} no soportada`;
    }
  }
  return ExportableClass;
}

class Podcast extends Audio {
  constructor(
    metadatos: Metadatos,
    bitrateKbps: number,
    public readonly episodio: number,
    public readonly anfitrion: string
  ) {
    super(metadatos, bitrateKbps);
  }

  obtenerInfo(): string {
    return `🎙️ Ep.${this.episodio}: ${this.metadatos.titulo} | ` +
      `con ${this.anfitrion} | ` +
      `${super.obtenerInfo()}`;
  }
}

// ── Composición ──

class ListaReproduccion implements Iterable<Contenido> {
  private _items: Contenido[] = [];

  constructor(public readonly nombre: string) {}

  agregar(item: Contenido): void {
    this._items.push(item);
  }

  quitar(indice: number): void {
    if (indice >= 0 && indice < this._items.length) {
      this._items.splice(indice, 1);
    }
  }

  reproducirTodo(): string[] {
    return this._items.map(item => item.reproducir());
  }

  infoCompleta(): string[] {
    return this._items.map(item => item.obtenerInfo());
  }

  get length(): number {
    return this._items.length;
  }

  [Symbol.iterator](): Iterator<Contenido> {
    return this._items[Symbol.iterator]();
  }

  toString(): string {
    return `📋 ${this.nombre} (${this._items.length} items)`;
  }
}

// ── Genéricos ──

class ContenedorMedio<T extends Contenido> {
  private items: T[] = [];

  agregar(item: T): void {
    this.items.push(item);
  }

  obtenerTodos(): T[] {
    return [...this.items];
  }
}

// ── Uso del sistema ──

const cancion = new Audio(
  { titulo: "Bohemian Rhapsody", duracionSegundos: 354, fechaCreacion: new Date(), tags: ["rock", "clásico"] },
  320
);

const pelicula = new Video(
  { titulo: "Inception", duracionSegundos: 8880, fechaCreacion: new Date(), tags: ["ciencia ficción", "thriller"] },
  "4K",
  FormatoVideo.MKV
);
pelicula.subtitulos = true;

const podcast = new Podcast(
  { titulo: "El futuro de la IA", duracionSegundos: 2700, fechaCreacion: new Date(), tags: ["tecnología", "IA"] },
  128,
  42,
  "Ana López"
);

// Polimorfismo
for (const contenido of [cancion, pelicula, podcast]) {
  console.log(contenido.obtenerInfo());
}

// Composición
const lista = new ListaReproduccion("Favoritos");
lista.agregar(cancion);
lista.agregar(pelicula);
lista.agregar(podcast);
console.log(lista.toString());
console.log(lista.reproducirTodo());
console.log(lista.infoCompleta());

// Genéricos
const contenedor = new ContenedorMedio<Audio>();
contenedor.agregar(cancion);
```

**Conceptos demostrados:**

| Concepto | Cómo aparece |
|---|---|
| Clase abstracta | `Contenido` con `abstract obtenerInfo()` |
| Herencia simple | `Audio(Contenido)`, `Video(Contenido)` |
| `super()` | `super(metadatos)` llama al constructor padre |
| Encapsulación | `_reproducciones` protegido; getters/setters |
| Polimorfismo | `obtenerInfo()` da resultados distintos según la clase |
| Interfaz | `Exportable` define contrato |
| Composición | `ListaReproduccion` contiene `Contenido[]` |
| Genéricos con constraints | `ContenedorMedio<T extends Contenido>` |
| Enums | `FormatoVideo` con valores string |
| Iterable | `[Symbol.iterator]()` para `for...of` |
| Readonly fields | `readonly id: string`, `readonly titulo: string` |

### Strategy

```typescript
type EstrategiaOrdenacion = (datos: number[]) => number[];

const ordenarAscendente: EstrategiaOrdenacion = (datos) =>
  [...datos].sort((a, b) => a - b);

const ordenarDescendente: EstrategiaOrdenacion = (datos) =>
  [...datos].sort((a, b) => b - a);

class Analizador {
  constructor(private estrategia: EstrategiaOrdenacion) {}

  analizar(datos: number[]): number[] {
    return this.estrategia(datos);
  }

  cambiarEstrategia(estrategia: EstrategiaOrdenacion): void {
    this.estrategia = estrategia;
  }
}

const a = new Analizador(ordenarDescendente);
console.log(a.analizar([3, 1, 4, 1, 5, 9]));  // [9, 5, 4, 3, 1, 1]
```

### Observer con EventEmitter

```typescript
import { EventEmitter } from "events";

type DatosSensor = { temperatura: number; humedad: number };

class Sensor extends EventEmitter {
  constructor(private nombre: string) {
    super();
  }

  emitirLectura(datos: DatosSensor): void {
    this.emit("lectura", datos);
  }
}

const sensor = new Sensor("sala");

sensor.on("lectura", (datos: DatosSensor) => {
```

### Adapter (tipado estructural)

```typescript
interface DBSistema {
  query(sql: string): Promise<unknown[]>;
}

class SistemaViejo {
  query(sql: string): unknown[] {
    return [{ resultado: "viejo" }];
  }
}

  async execute(query: string): Promise<unknown[]> {
    return [{ resultado: "nuevo" }];
  }
}

// Adaptador
class DBAdapter implements DBSistema {
  constructor(private backend: SistemaViejo | SistemaNuevo) {}

  }
```

### Chain of Responsibility

```typescript
abstract class Handler {
  private siguiente?: Handler;

  conectar(handler: Handler): Handler {
    this.siguiente = handler;
    return handler;
  }

  async manejar(solicitud: string): Promise<string | undefined> {
    const resultado = await this.procesar(solicitud);
    if (resultado === undefined && this.siguiente) {
      return this.siguiente.manejar(solicitud);
    }
    return resultado;
  }

  protected abstract procesar(solicitud: string): Promise<string | undefined>;
}

class Validador extends Handler {
  protected async procesar(solicitud: string): Promise<string | undefined> {
    if (solicitud.length < 3) return "Error: solicitud muy corta";
    return undefined;
  }
}

class Autenticador extends Handler {
  protected async procesar(solicitud: string): Promise<string | undefined> {
    if (!solicitud.includes("token")) return "Error: no autenticado";
    return undefined;
  }
}

class Cache extends Handler {
  protected async procesar(_solicitud: string): Promise<string | undefined> {
    return "Respuesta desde caché";
  }
}

// Cadena: Validador → Autenticador → Cache
const cadena = new Validador();
cadena.conectar(new Autenticador()).conectar(new Cache());

console.log(await cadena.manejar("hola"));        // Error: solicitud muy corta
console.log(await cadena.manejar("hola token"));  // Respuesta desde caché
```

## Polimorfismo en detalle

TypeScript tiene tres formas de polimorfismo. Todas coexisten en el mismo código.

### 1. Polimorfismo paramétrico (genéricos)

```typescript
function identidad<T>(valor: T): T {
  return valor;
}

// El mismo código funciona con cualquier tipo
identidad<string>("hola");
identidad<number>(42);
identidad<boolean>(true);

// Recipiente genérico
class Caja<T> {
  constructor(public contenido: T) {}

  obtener(): T {
    return this.contenido;
  }
}

const cajaString = new Caja("Hola");
const cajaNumber = new Caja(123);
```

### 2. Polimorfismo por subtipado (herencia)

```typescript
abstract class Forma {
  abstract area(): number;
}

class Circulo extends Forma {
  constructor(private radio: number) {
    super();
  }

  area(): number {
    return Math.PI * this.radio ** 2;
  }
}

class Rectangulo extends Forma {
  constructor(private ancho: number, private alto: number) {
    super();
  }

  area(): number {
    return this.ancho * this.alto;
  }
}

function mostrarArea(forma: Forma): void {
  console.log(`Área: ${forma.area().toFixed(2)}`);
}

mostrarArea(new Circulo(5));       // Área: 78.54
mostrarArea(new Rectangulo(3, 4)); // Área: 12.00
```

### 3. Polimorfismo estructural (duck typing en compilación)

```typescript
interface Imprimible {
  imprimir(): string;
}

class Documento {
  imprimir(): string {
    return "Imprimiendo documento...";
  }
}

class Foto {
  imprimir(): string {
    return "Imprimiendo foto 4x6...";
  }
}

class Impresora {
  imprimir(): string {
    return "Imprimiendo informe de estado...";
  }
}

function enviarAImpresion(objeto: Imprimible): void {
  console.log(objeto.imprimir());
}

// Todas funcionan porque tienen la misma estructura
enviarAImpresion(new Documento());  // Imprimiendo documento...
enviarAImpresion(new Foto());       // Imprimiendo foto 4x6...
enviarAImpresion(new Impresora());  // Imprimiendo informe de estado...
```

El polimorfismo paramétrico se resuelve en compilación, el de subtipado en runtime (herencia clásica), y el estructural también en compilación (es el sistema de tipos de TypeScript — no necesitas herencia, solo tener la misma forma).

## Concurrencia

TypeScript/JavaScript tiene un solo hilo de ejecución con un event loop asíncrono. La concurrencia se logra mediante asincronía (no paralelismo real), Web Workers en navegador y `worker_threads` en Node.js.

### Event Loop (el modelo de concurrencia)

```typescript
// El event loop procesa microtareas (Promises) antes que macrotareas (setTimeout)
console.log("1: Sincrónico");

setTimeout(() => console.log("2: Macrotarea (setTimeout)"), 0);

Promise.resolve().then(() => console.log("3: Microtarea (Promise)"));

console.log("4: Sincrónico");

// Output:
// 1: Sincrónico
// 4: Sincrónico
// 3: Microtarea (Promise)
// 2: Macrotarea (setTimeout)
```

### async/await (concurrencia cooperativa en un hilo)

```typescript
async function descargar(url: string): Promise<string> {
  const response = await fetch(url);
  return response.text();
}

async function main() {
  const urls = [
    "https://httpbin.org/delay/2",
    "https://httpbin.org/delay/1",
    "https://httpbin.org/delay/3",
  ];

  // Secuencial: ~6 segundos
  console.time("secuencial");
  for (const url of urls) {
    await descargar(url);
  }
  console.timeEnd("secuencial");

  // Concurrencia real con Promise.all: ~3 segundos
  console.time("concurrente");
  const resultados = await Promise.all(urls.map(descargar));
  console.timeEnd("concurrente");

  // Con Promise.allSettled (no falla si una promesa rechaza)
  const resultados2 = await Promise.allSettled(urls.map(descargar));
  for (const r of resultados2) {
    if (r.status === "fulfilled") {
      console.log(r.value.length);
    } else {
      console.error(r.reason);
    }
  }
}
```

### Web Workers (navegador)

```typescript
// worker.ts (archivo separado)
self.onmessage = (event: MessageEvent<number>) => {
  const n = event.data;
  // Cálculo CPU-bound
  const resultado = fibonacci(n);
  self.postMessage(resultado);
};

}

  type: "module",
});

};
```

### worker_threads (Node.js)

```typescript
// worker.ts
import { parentPort } from "node:worker_threads";

parentPort?.on("message", (n: number) => {
  const resultado = fibonacci(n);
  parentPort?.postMessage(resultado);
});

function fibonacci(n: number): number {
  return n < 2 ? n : fibonacci(n - 1) + fibonacci(n - 2);
}

// main.ts
import { Worker } from "node:worker_threads";
import { cpus } from "node:os";

function ejecutarEnWorker(n: number): Promise<number> {
  return new Promise((resolve, reject) => {
    const worker = new Worker(new URL("./worker.ts", import.meta.url));
    worker.postMessage(n);
    worker.on("message", resolve);
    worker.on("error", reject);
    worker.on("exit", (code) => {
      if (code !== 0) reject(new Error(`Worker exit code ${code}`));
    });
  });
}

// Usar todos los núcleos
async function main() {
  const nums = Array.from({ length: cpus().length }, (_, i) => 40 + i);
  const resultados = await Promise.all(nums.map(ejecutarEnWorker));
  console.log(resultados);
}
```

## Escala de aprendizaje: de 0 a 100

Cada nivel incluye lo que debes saber y un proyecto para fijar los conceptos.

### Nivel 0–15: Fundamentos absolutos
**Qué aprender:**
- Sintaxis básica: `let`, `const`, tipos primitivos (`string`, `number`, `boolean`)
- TypeScript Playground para practicar sin instalar
- Tipos inferidos vs anotaciones explícitas
- Funciones: parámetros tipados, retorno tipado
- Arrays: `number[]`, `string[]`, acceso por índice
- Objetos literales e interfaces básicas: `interface Usuario { nombre: string }`
- `tsc` básico: compilar un archivo `.ts` a `.js`
- **Conceptos clave**: TypeScript es JavaScript con tipos — los tipos se borran al compilar. El tipado es estructural: si dos objetos tienen la misma forma, son compatibles. `const` impide reasignación, no inmutabilidad. La inferencia es tu aliada: no anotes todo.

**Proyecto:** *Conversor de temperaturas* — función que convierte Celsius a Fahrenheit y viceversa. Interfaz para los parámetros. Tipos literales para las unidades (`"celsius" | "fahrenheit"`). Script CLI simple que lee argumentos con `process.argv`.

### Nivel 15–30: Union types, funciones y arrays avanzados
**Qué aprender:**
- Union types: `string | number`
- Type narrowing: `typeof`, truthy/falsy, `in`, `instanceof`
- Funciones: parámetros opcionales (`?`), default values, rest params
- Tuplas: `[string, number]`, labeled tuples
- `readonly` arrays y `ReadonlyArray<T>`
- `as const` para tipos literales profundos
- Enums (numéricos y string)
- `unknown` vs `any`: cuándo usar cada uno
- **Conceptos clave**: narrowing es automático (switch, typeof, truthy checks). `any` desactiva el checker — nunca lo uses. `unknown` es seguro pero fuerza verificación. `as const` convierte todo a tipos literales readonly.

**Proyecto:** *Validador de formularios* — función que valida diferentes tipos de campos (email, teléfono, url). Union type para los tipos de campo. Type guards personalizados. Tuplas para errores `[campo: string, mensaje: string]`. Enum para los tipos de validación. `readonly` arrays para los campos inmutables.

### Nivel 30–45: Interfaces, types, genéricos y POO
**Qué aprender:**
- `interface` vs `type` — diferencias y cuándo usar cada uno
- Extensión: `extends` en interfaces, `&` en types
- Interfaces con propiedades opcionales y `readonly`
- Genéricos básicos: `function identidad<T>(arg: T): T`
- Constraints: `<T extends { length: number }>`
- Clases: `constructor`, `public`/`private`/`protected`, `readonly`
- `abstract class` vs `interface` — diferencias
- `implements`: una clase puede implementar múltiples interfaces
- **Conceptos clave**: las interfaces soportan declaration merging; los types no. Los genéricos en TypeScript son como templates en C++ pero sin runtime (se borran). Las clases tienen type y value en el mismo nombre — las interfaces solo type.

**Proyecto:** *Gestor de tareas con herencia* — clases `TareaBase`, `TareaSimple`, `TareaConFecha`. Interfaz `Exportable` con método `exportar()`. Genéricos en un repositorio `Repositorio<T>` con métodos `agregar()`, `obtener()`, `eliminar()`. Clase abstracta `TareaBase` con `abstract completar(): void`. Enum `EstadoTarea`.

### Nivel 45–60: Tipos avanzados, generics profundos, utility types
**Qué aprender:**
- Utility types: `Partial<T>`, `Required<T>`, `Pick<T, K>`, `Omit<T, K>`, `Record<K, V>`
- `Readonly<T>`, `Exclude<T, U>`, `Extract<T, U>`, `NonNullable<T>`
- `ReturnType<T>`, `Parameters<T>`, `ConstructorParameters<T>`
- Mapped types: `{ [K in keyof T]: ... }`
- Conditional types: `T extends U ? X : Y`
- Template literal types: `` `get${Capitalize<string>}` ``
- `keyof`, `typeof`, `satisfies`
- `infer` keyword en conditional types
- Branded types
- **Conceptos clave**: los utility types no son magia — son mapped types y conditional types que vienen en la stdlib. `satisfies` verifica sin ensanchar. `infer` extrae tipos de otros tipos en conditional branches.

**Proyecto:** *API client tipado* — función genérica `createApiClient<T extends Record<string, any>>()` que retorna un objeto con métodos tipados para cada endpoint. Usa template literal types para las rutas. Conditional types para deducir el tipo de respuesta según el método HTTP. Utility types para parámetros opcionales. Branded type para `ApiKey`.

### Nivel 60–75: Backend, bases de datos y async
**Qué aprender:**
- Express/Fastify con TypeScript: handlers tipados, request/response types
- Zod o Valibot para validación de entrada
- Prisma o Drizzle: schema, queries tipadas, migrations
- async/await en profundidad: `Promise.all`, `Promise.allSettled`, `Promise.race`
- Error handling: `try/catch` con tipos, clases de error personalizadas
- Middleware pattern con tipos
- Variables de entorno con `zod` (validación al startup)
- **Conceptos clave**: el event loop de JS no tiene GIL — no hay bloqueo de CPU con asincronía bien hecha. `Promise.all` para concurrencia real (I/O-bound). Los decoradores son compile-time, no runtime. Zod infiere tipos automáticamente.

**Proyecto:** *API de recetas con Prisma* — Fastify + Prisma + PostgreSQL. Zod para validación de entrada. CRUD tipado para recetas e ingredientes. Búsqueda por ingrediente con query params tipados. Tests con vitest + `@fastify/inject`. Migraciones con Prisma Migrate.

### Nivel 75–90: Tiempo real, workers y producción
**Qué aprender:**
- WebSockets con `ws` y Socket.IO — tipado de eventos
- Workers: `worker_threads` en Node.js, Web Workers en navegador
- `p-limit` / `p-map` para concurrencia controlada
- Docker multi-etapa para apps TS (build + run)
- Zod en runtime: validación de datos externos
- Rate limiting, caching con Redis
- CI/CD: GitHub Actions con lint (ESLint), type-check (`tsc --noEmit`), test (vitest)
- Logger: `pino` o `winston` con tipos
- **Conceptos clave**: los tipos se borran en compilación — la validación runtime sigue siendo necesaria (Zod, Valibot). Los Workers permiten paralelismo real porque cada worker tiene su propio V8 isolate. `--strict` en tsconfig desde el día 1.

**Proyecto:** *Dashboard de monitorización en tiempo real* — API Fastify que recolecta métricas (CPU, RAM) usando `os` module. Socket.IO para broadcast de métricas a clientes conectados. Zod para validar los datos entrantes. worker_threads para recolectar métricas pesadas sin bloquear el event loop. Docker Compose con API + Redis. Tests de integración.

### Nivel 90–100: Arquitectura, sistemas distribuidos y edge
**Qué aprender:**
- tRPC: APIs tipadas de extremo a extremo sin schema
- Arquitectura limpia / hexagonal en TypeScript: casos de uso, repositorios, controladores
- Colas con BullMQ / RabbitMQ: jobs en background con tipado
- GraphQL con Pothos o GraphQL Yoga: schema-first, tipos inferidos
- Edge computing: Cloudflare Workers, Deno Deploy, Vercel Edge Functions
- OpenTelemetry: tracing y observabilidad
- Monorepos con Turborepo + Project References
- Publicar paquetes npm: `tsup` para build, `changesets` para versionado
- **Conceptos clave**: TypeScript en edge tiene limitaciones (sin Node.js APIs) — usa `workerd`, Deno, o Bun. tRPC elimina la necesidad de REST/GraphQL en apps full-stack. Los monorepos necesitan `composite: true` y `tsc --build`. Las librerías deben publicar `.d.ts` + `.js` (o `.mjs` + `.cjs` para dual ESM/CJS).

**Proyecto:** *Sistema de notificaciones distribuidas* — tRPC para comunicación entre servicios (o gRPC). BullMQ para colas de email y push. Edge Functions para webhooks de entrada. Monorepo con Turborepo (paquetes `core`, `api`, `workers`). OpenTelemetry para tracing. Desplegado en Docker Compose con monitoreo.

### CLI de notas cifradas (nivel 30)

```typescript
import { readFileSync, writeFileSync, existsSync } from "node:fs";
import { encrypt, decrypt } from "./crypto";

interface Nota {
  titulo: string;
  contenido: string;
  createdAt: string;
}

class Vault {
  private notas: Map<string, Nota> = new Map();

  constructor(private path: string) {
    this.cargar();
  }

  private cargar(): void {
    if (!existsSync(this.path)) return;
    const data = decrypt(readFileSync(this.path, "utf-8"));
    const parsed: Record<string, Nota> = JSON.parse(data);
    this.notas = new Map(Object.entries(parsed));
  }

  private guardar(): void {
    const data = JSON.stringify(Object.fromEntries(this.notas));
    writeFileSync(this.path, encrypt(data));
  }

  agregar(titulo: string, contenido: string): void {
    this.notas.set(titulo, { titulo, contenido, createdAt: new Date().toISOString() });
    this.guardar();
  }

  obtener(titulo: string): Nota | undefined {
    return this.notas.get(titulo);
  }

  listar(): string[] {
    return [...this.notas.keys()];
  }
}
```

### Web scraper concurrente (nivel 60)

```typescript
import { JSDOM } from "jsdom";
import pLimit from "p-limit";

interface Articulo {
  titulo: string;
  url: string;
  fuente: string;
}

async function scrapeNews(url: string): Promise<Articulo[]> {
  const response = await fetch(url, {
    headers: { "User-Agent": "Mozilla/5.0" },
  });
  const html = await response.text();
  const dom = new JSDOM(html);
  const document = dom.window.document;

  return Array.from(document.querySelectorAll("article h2 a, .headline a"))
    .map(el => ({
      titulo: el.textContent?.trim() ?? "",
      url: el.getAttribute("href") ?? "",
      fuente: url,
    }))
    .filter(a => a.titulo && a.url);
}

async function main(sources: string[]): Promise<Articulo[]> {
  const limit = pLimit(5);
  const results = await Promise.allSettled(
    sources.map(url => limit(() => scrapeNews(url)))
  );

  return results.flatMap(r =>
    r.status === "fulfilled" ? r.value : []
  );
}

const articles = await main([
  "https://news.ycombinator.com",
  "https://dev.to",
]);
console.log(articles.slice(0, 10));
```

## Hacks y tips de productividad

**1. `satisfies` — verifica sin ensanchar**

```typescript
// Quieres que cada color sea string o string[], pero mantener el tipo concreto
const palette = {
  rojo: "#FF0000",
  verde: "#00FF00",
  azul: ["#0000FF", "#00BFFF"],
} satisfies Record<string, string | string[]>;

palette.rojo.toUpperCase();    // OK: string
palette.azul.map(c => c);     // OK: string[]
```

**2. Branded types para IDs**

```typescript
type UserId = string & { readonly __brand: "UserId" };
type ProductId = string & { readonly __brand: "ProductId" };

function getUser(id: UserId): Promise<User>;
function getProduct(id: ProductId): Promise<Product>;

// No puedes mezclar IDs accidentalmente
const uid = "abc" as UserId;
const pid = "abc" as ProductId;
// getUser(pid);  // Error de compilación
```

**3. Template literal types para routing**

```typescript
type Route = `/api/${string}`;

type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParams<Rest>
    : T extends `${string}:${infer Param}`
      ? Param
      : never;

type GetUsersParams = ExtractParams<"/api/users/:userId/posts/:postId">;
// "userId" | "postId"
```

**4. Utility types que deberías saber de memoria**

```typescript
// Partial — todas las propiedades opcionales
Partial<{ nombre: string; edad: number }>
// → { nombre?: string; edad?: number }

// Required — todas las propiedades requeridas
Required<{ nombre?: string; edad?: number }>
// → { nombre: string; edad: number }

// Pick — solo las propiedades seleccionadas
Pick<{ nombre: string; edad: number; email: string }, "nombre" | "email">
// → { nombre: string; email: string }

// Omit — todas excepto las seleccionadas
Omit<Usuario, "password" | "salt">

// Record — diccionario tipado
Record<string, number>
// → { [key: string]: number }

// Extract / Exclude — filtrado de uniones
type Status = "activo" | "inactivo" | "pendiente";
type Activo = Extract<Status, "activo">;
type InactivoOPendiente = Exclude<Status, "activo">;

// ReturnType / Parameters — tipos de funciones
type Fn = (x: number, y: string) => boolean;
type Ret = ReturnType<Fn>;     // boolean
type Params = Parameters<Fn>;  // [number, string]
```

**5. `as const` para configuraciones**

```typescript
export const HTTP_STATUS = {
  OK: 200,
  CREATED: 201,
  NOT_FOUND: 404,
  INTERNAL_ERROR: 500,
} as const;

type HttpStatus = typeof HTTP_STATUS[keyof typeof HTTP_STATUS];
// 200 | 201 | 404 | 500
```

**6. Zod para validación + tipos inferidos**

```typescript
import { z } from "zod";

const UsuarioSchema = z.object({
  nombre: z.string().min(2).max(100),
  email: z.string().email(),
  edad: z.number().int().positive().optional(),
});

type Usuario = z.infer<typeof UsuarioSchema>;
// { nombre: string; email: string; edad?: number }

// Validación runtime + type safety
const data = JSON.parse(body);
const usuario: Usuario = UsuarioSchema.parse(data);
```

```typescript
const elemento = document.getElementById("app")!;

const elemento = document.getElementById("app");
```

**10. Deep Partial con mapped types recursivos**

```typescript
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

interface Config {
  db: { url: string; port: number };
  server: { host: string };
}

type PartialConfig = DeepPartial<Config>;
// PartialConfig.db?.url es string | undefined
```
