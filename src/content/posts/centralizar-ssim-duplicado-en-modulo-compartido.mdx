# 🧹 Refactor SSIM: el viaje completo, de duplicado a compartido

Hay un momento incómodo que todos los que escribimos código conocemos: llevas semanas usando un script, un día lo abres para tocar una cosa, y te das cuenta de que **tienes el mismo algoritmo copiado en dos sitios**. No una versión aproximada: **exactamente el mismo código**, línea por línea.

Esta es la narración completa de cómo implementé el refactor: desde que detecté el problema hasta que commiteé la solución, pasando por el susto del `IndentationError` que se ocultaba en uno de los scripts.

---

## 🔍 Paso 1 — Cómo detecté el duplicado

Mis dos herramientas de imágenes vivían en `scripts/tools/`:

- **`optimize.py`** — optimiza imágenes raster (JPEG/PNG/WebP). Prueba calidades de compresión decrecientes y usa SSIM para decidir cuándo la pérdida de calidad es inaceptable.
- **`fix_images.py`** — redimensiona y limpia metadatos de las imágenes de los posts.

Vivían en el mismo directorio, hacían cosas complementarias, y **compartían el mismo motor**: el algoritmo SSIM (Structural Similarity Index), con sus funciones auxiliares y sus constantes de calibración.

¿Cómo lo detecté? No fue glamuroso: estaba añadiendo una función nueva a `optimize.py`, y al guardar, mi editor me mostró "simbols already defined" para `compute_ssim`. Ahí me paré. No es que hubiera dos `compute_ssim` en el mismo archivo — es que **dos archivos definían el mismo símbolo**, y no me había dado cuenta porque cada uno se usaba de forma independiente.

Hice un `grep` y confirmé lo que sospechaba:

```
# scripts/tools/optimize.py
def compute_ssim(img1, img2): ...
def _channel_stats(...): ...
def find_optimal_quality(...): ...
def strip_metadata(...): ...
def constrain_size(...): ...

# scripts/tools/fix_images.py
def _channel_stats(...): ...   # ¡copia idéntica!
def compute_ssim(...): ...     # ¡copia idéntica!
def find_optimal_quality(...): ...
def strip_metadata(...): ...
def constrain_size(...): ...
```

Ambos definían las mismas 5 funciones, las mismas 6 constantes (`MAX_WIDTH`, `SSIM_THRESHOLD`, `QUALITY_START`, `QUALITY_MIN`, `QUALITY_STEP`, `WEBP_METHOD`), incluso los mismos nombres de variables internas. Eran **dos copias byte a byte casi exactas** de ~130 líneas.

---

## 🤔 Paso 2 — ¿Por qué es un problema de verdad?

Antes de tocar nada, me obligué a justificar *por qué* valía la pena arreglarlo. El código duplicado no es un pecado si la duplicación es accidental y corta; pero aquí no lo era:

1. **Dos fuentes de verdad.** El SSIM está calibrado con un umbral (`SSIM_THRESHOLD = 0.98`) que decide "¿se nota la pérdida de calidad?". Si mañana ajusto ese umbral en `optimize.py` y lo olvido en `fix_images.py`, ambos scripts **empiezan a comportarse distinto en silencio**. No hay compilador que te avise: es un bug que no falla, simplemente degrada.
2. **El bug vive dos veces.** Corrijo un fallo en `compute_ssim` de un lado y el otro sigue roto. Cada fix es un *find-replace* manual que hay que repetir.
3. **Más código que mantener.** ~130 líneas duplicadas son ~130 líneas que se multiplican si la lógica crece.
4. **Tests ambiguos.** Los tests apuntaban a cada copia por separado. Si una versión divergía, los tests de la otra seguían pasando y no te enterabas de que el algoritmo ya no era "el mismo".

La moraleja que me repetí: **si dos scripts comparten un algoritmo, el algoritmo no pertenece a ninguno de los dos — pertenece a un tercer lugar.**

---

## 🗂️ Paso 3 — El diseño: un módulo compartido (`utils/image_ops.py`)

La decisión técnica fue la clásica y poco espectacular: extraer el algoritmo a un módulo de utilidades compartido. Pero había un detalle importante: **qué sacar y qué no**.

Comparé las dos copias y saqué la intersección exacta — ni más ni menos — para que los dos scripts siguieran haciendo lo mismo:

| Qué compartir | Por qué |
| --- | --- |
| `MAX_WIDTH`, `SSIM_THRESHOLD`, `QUALITY_START`, `QUALITY_MIN`, `QUALITY_STEP`, `WEBP_METHOD` | Las constantes de calibración. **Deben** ser una sola fuente de verdad. |
| `_channel_stats` | Cálculo de estadísticas por canal (media, varianza, covarianza). |
| `compute_ssim` | El índice SSIM propiamente (resize L, window 160×160, constantes C1/C2). |
| `find_optimal_quality` | El bucle que baja la calidad mientras el SSIM aguante el umbral. |
| `strip_metadata` + `constrain_size` | Preparación de imagen (limpiar metadatos, limitar ancho). |

El resultado fue `scripts/utils/image_ops.py` — un módulo de 111 líneas, focused en *una única responsabilidad*: el algoritmo SSIM y la preparación de imagen. Lo dejé separado de `utils/common.py` (que ya existía y mezcla helpers generales) precisamente para mantenerlo testeable y de un solo tema.

Cada script tool quedaría ahora con **su orquestación**: qué archivos, qué formatos, qué rutas de salida. Y nada de la teoría del SSIM.

---

## 🔧 Paso 4 — Migración de `optimize.py` (y el susto del `IndentationError`)

Empecé por `optimize.py`. El plan era simple: borrar las 5 funciones + 6 constantes locales y sustituirlas por un `import` explícito.

```
# ANTES
# /──── duplicated ~130 líneas: SSIM + constantes ────/

# DESPUÉS
from utils.image_ops import (
    compute_ssim, find_optimal_quality, strip_metadata, constrain_size,
    MAX_WIDTH, SSIM_THRESHOLD, QUALITY_START, QUALITY_MIN, QUALITY_STEP, WEBP_METHOD,
)
```

Y aquí vino **el susto que me demostró que el refactor ya tenía valor antes de terminar**: al quitar el bloque, mi editor me saltó un `IndentationError` en `optimize_svg`. Había dos `import` (`re` y `sys`) que estaban **dentro de la función, mal indentados**:

```python
def optimize_svg(path, out_dir, filename):
    # ...
    import re      # ← indentation incorrecta dentro de la función
    import sys     # ← aquí dentro
```

Los imports redundantes **rompían el script en tiempo de importación**: `optimize.py` no se ejecutaba en absoluto. Llevaba tiempo ahí, escondido, porque ese script no se probaba en los tests. No tenía nada que ver con mi refactor, pero al estar tocando ese archivo me lo topé, así que lo arreglé de paso:

```python
import re
import sys
# ...en el nivel de módulo, con el resto de imports
```

> Lección: cuando refactorizas, a veces te tropiezas con bugs preexistentes que el refactor expone. No son "daño colateral": **son bugs que ya estaban**, ahora visibles. Conviene arreglarlos en el mismo commit (quedan documentados juntos).

Después de esto, `optimize.py` pasaba de 196 a ~143 líneas: **~61 líneas menos**.

---

## 🔧 Paso 5 — Migración de `fix_images.py`

`fix_images.py` era la otra copia. Aquí el cambio fue un poco más delicado porque el bloque duplicado estaba incrustado a mitad del archivo (no al principio, como en `optimize.py`), justo después de la sección de cache y antes de las operaciones GIF/SVG.

Localicé el límite exacto del bloque con un script de transformación determinista:

- **Inicio**: la línea `def _channel_stats(`.
- **Fin**: la primera definición de módulo tras `def constrain_size(` que no era del bloque (en este caso `def process_gif_fallback(`).

Eliminé el bloque completo (que arrastraba también su cabecera de comentario de sección) y en su lugar puse el mismo `import` compartido, conservando el comentario de sección siguiente (`OPERACIONES COMPLEMENTARIAS GIF / SVG`) para no romper la estructura del archivo.

Resultado: `fix_images.py` pasó de 500+ líneas a **446 líneas** (~69 líneas menos), con el import compartido en la línea 92.

---

## 🧪 Paso 6 — Los tests (y un import que se me había olvidado)

Al terminar la migración, corrí la suite y salió un error que me paró en seco:

```
ERROR tests/test_fix_images.py
ImportError: cannot import name '_channel_stats' from 'scripts.tools.fix_images'
```

Claro: **el test seguía importando `_channel_stats`, `compute_ssim`, etc. desde `fix_images`**, la copia local que acababa de eliminar. El test no estaba roto por culpa del algoritmo — estaba roto porque apuntaba a la fuente equivocada.

La corrección fue la más coherente con el espíritu del refactor: **que el test apunte a la fuente canónica**, `scripts.utils.image_ops`, y deje en `fix_images` solo lo que realmente le pertenece (`slugify`, `build_srcset`, `generate_placeholder`):

```python
from scripts.utils.image_ops import (
    compute_ssim, _channel_stats, strip_metadata, constrain_size,
)
from scripts.tools.fix_images import (
    slugify, build_srcset, generate_placeholder,
)
```

Este paso me recordó algo importante del testing: **cuando mueves código a un módulo compartido, los tests que lo verifican también deben moverse a ese módulo**. Si dejas los tests apuntando a la copia local, el refactor "funciona" (los tests pasan) pero la duplicación real se mantiene en los imports de los tests.

---

## ✅ Paso 7 — Validación antes de commitear

Mi criterio era innegociable: **tras el refactor, todo debe funcionar igual que antes**. La validación fue en tres capas:

1. **`python3 -m py_compile`** de los tres módulos (`image_ops.py`, `optimize.py`, `fix_images.py`) — los tres compilaron sin errores. Como el `IndentationError` de `optimize.py` se había arreglado, este paso era ahora realmente útil.
2. **Comparar firmas y valores** entre la copia original y el módulo compartido: mismas firmas de función, mismos valores de constantes. Si una firma cambia, cambia el comportamiento; aquí **nada cambió**.
3. **`pytest -q`**: **168 tests pasando** ✅.

Solo después de esto commiteé. El commit (4 archivos, +127/−118) fue descriptivo y específico, reflejando exactamente qué se movía:

```
refactor: centralizar algoritmo SSIM en utils/image_ops.py

- Extraer _channel_stats, compute_ssim, find_optimal_quality, strip_metadata
  y constrain_size (con sus constantes) a scripts/utils/image_ops.py
- optimize.py y fix_images.py consumen ahora el SSIM compartido,
  eliminando la duplicación (~130 líneas)
- Reparar IndentationError preexistente en optimize.py (imports re/sys
  dentro de optimize_svg -> a nivel de módulo)
- Actualizar tests/test_fix_images.py para importar el SSIM desde la
  fuente canónica compartida

168 passed
```

## 🎓 Lo que me llevo (aplicable a tu código también)

1. **La duplicación de algoritmos es un problema incluso si "funciona"**: el problema no es que falle hoy, es que *divergirá* en silencio cuando alguien toque una copia.
2. **Antes de refactorizar, define qué es la intersección exacta.** Extraer de más rompe cosas; extraer de menos deja duplicación. Comparé las dos copias línea a línea y saqué solo lo común.
3. **Refactorizar expone bugs preexistentes** (mi `IndentationError`). No los escondas: arréglalos y documéntalos en el mismo commit.
4. **Los tests también deben migrar a la fuente canónica.** Si no, la duplicación sobrevive en los imports de los tests.
5. **Valida con tres capas**: compilación, comparación de firmas/valores, y suite completa. Solo entonces, commit.

En mi caso, el refactor no solo eliminó ~130 líneas de duplicación: me destapó un script que no se ejecutaba, alineó los tests con la fuente de verdad, y dejó ambos scripts listos para evolucionar sin pisarse entre sí. **Eso vale más que las líneas ahorradas.**
