## 1. Clonado y Configuración (Obtener proyectos)

### Clonar e iniciar repos
* **`git clone`**:
    * `--depth <N>`: **Shallow clone**. Solo descarga los últimos N commits (ideal para ahorrar espacio y tiempo).
    * `--branch <nombre>` (`-b`): Clona una rama específica.
    * `--single-branch`: Descarga solo la rama indicada y no el resto de ramas del servidor.
    * `--filter=blob:none`: **Blobless clone**. Baja el historial pero no el contenido de archivos viejos hasta que los pidas.
    * `--recurse-submodules`: Clona el repo y todos sus submódulos automáticamente.
    * `--sparse`: Habilita el checkout parcial (para ver solo ciertas carpetas en monorepos).

* **`git init`**:
    * `--bare`: Crea un repositorio sin working directory (para servidores centrales).
    * `--template=<ruta>`: Usa una plantilla de archivos iniciales (hooks, config).
    * `--separate-git-dir=<ruta>`: Guarda la carpeta `.git` en una ubicación externa.
    * `-b <nombre>`: Define el nombre de la rama inicial (ej. `main` en lugar de `master`).

### Configuración global y local
* **`git config`**:
    * `--global`: Configura para todo el usuario (nombre, email, editor).
    * `--local` (default): Configura solo para el proyecto actual.
    * `--list` (`-l`): Muestra toda la configuración activa (combina global + local).
    * `--get <clave>`: Consulta el valor de una clave concreta.
    * `--unset <clave>`: Elimina una clave de la configuración.
    * `--edit` (`-e`): Abre el archivo de configuración en el editor por defecto.
    * `--add <clave> <valor>`: Añade un valor adicional a una clave multivalor.
    * `--show-origin`: Muestra de qué archivo viene cada valor de configuración.

## 2. Gestión de Cambios (El día a día)

### Preparar y gestionar archivos
* **`git add`**:
    * `-A` (`--all`): Añade **todos** los cambios (nuevos, modificados y eliminados) de todo el repo.
    * `-u` (`--update`): Añade solo archivos **ya rastreados** que hayan sido modificados o eliminados (no incluye archivos nuevos).
    * `-p` (`--patch`): Revisa interactivamente cada cambio del archivo y te deja elegir qué partes incluir (imprescindible para commits limpios).
    * `-n` (`--dry-run`): Simula qué se añadiría sin hacer nada realmente.
    * `-i` (`--interactive`): Modo interactivo con subcomandos (status, update, revert, add untracked, patch, diff).
    * `--intent-to-add` (`-N`): Registra el archivo como rastreado pero vacío, útil para ver diffs de archivos nuevos.
    * `--refresh`: Actualiza el índice sin añadir nada nuevo; útil tras cambiar permisos.
    * `--ignore-removal`: Ignora archivos eliminados del working tree (no los saca del index).
    * `--renormalize`: Reaplica el tratamiento de finales de línea (`core.autocrlf`) a todos los archivos.
    * `--chmod=(+|-)(x|r)`: Cambia los permisos de ejecución directamente en el stage.
    * `--verbose` (`-v`): Muestra el diff completo de lo que se añade al stage.

* **`git rm`**:
    * `--cached`: Elimina el archivo del control de versiones **pero lo deja en el disco** (deja de rastrearlo). Útil para archivos que deberían estar en `.gitignore`.
    * `-r`: Elimina carpetas recursivamente.
    * `-n` (`--dry-run`): Simula la eliminación.
    * `--ignore-unmatch`: No da error si el archivo no existe.
    * `--sparse`: Permite eliminar archivos dentro de áreas sparse-checkout.

* **`git mv`**:
    * `-f` (`--force`): Fuerza el movimiento aunque exista un archivo en el destino.
    * `-k`: Salta archivos fuente que no existen (sin error).
    * `-n` (`--dry-run`): Simula el movimiento.

* **`git restore`**:
    * `--staged` (`-S`): Saca archivos del stage (deshace un `git add`).
    * `--worktree` (`-W`): Restaura archivos en el working directory (descarta cambios locales).
    * `--source=<árbol>` (`-s`): Restaura desde un commit, rama o tag específico.
    * `-p` (`--patch`): Elige interactivamente qué partes restaurar.
    * `--ours` / `--theirs`: En conflictos de merge, elige nuestra versión o la de ellos.

### Commits y diferencias
* **`git commit`**:
    * `-m "mensaje"`: Añade el mensaje sin abrir el editor de texto.
    * `-a` (`--all`): Stage automático de archivos modificados/borrados (no incluye nuevos).
    * `--amend`: Edita el último commit (cambia el mensaje o añade archivos olvidados).
    * `--no-verify`: Salta los checks automáticos (hooks) de pre-commit.
    * `--reset-author`: Cambia la autoría del commit corregido al usuario actual.
    * `--date="now"`: Actualiza la marca de tiempo del commit.

* **`git diff`**:
    * `--staged` o `--cached`: Compara el stage contra el último commit.
    * `--stat`: Resumen numérico de líneas cambiadas por archivo.
    * `--name-only`: Muestra únicamente los nombres de los archivos afectados.
    * `-w`: Ignora cambios de espacios en blanco al comparar.
    * `--check`: Busca conflictos de espacios en blanco (tabs/espacios, trailing whitespace).
    * `--submodule`: Compara el estado de los submódulos.
    * `--color-words`: Compara palabra por palabra en lugar de línea por línea.
    * `--cached`: alias de `--staged`.
    * `<rama>..<otra>`: Compara dos ramas entre sí.
    * `<commit>...<commit>`: Compara los cambios desde el ancestro común (merge base).

* **`git stash` (Guardado temporal)**:
    * `push -m "nombre"`: Guarda cambios actuales en una pila temporal.
    * `pop`: Recupera los cambios y los elimina de la pila.
    * `apply`: Aplica los cambios pero los mantiene en la pila.
    * `list`: Muestra todo lo guardado en el "limbo".
    * `-u` (`--include-untracked`): Guarda también los archivos nuevos no rastreados.
    * `-a` (`--all`): Guarda **todos** los archivos, incluidos los ignorados por `.gitignore`.
    * `drop [<stash>]`: Elimina un stash específico de la pila.
    * `clear`: Vacía toda la pila de stashes.
    * `branch <rama> [<stash>]`: Crea una rama desde el commit del stash y aplica los cambios ahí.
    * `show [-p] [<stash>]`: Muestra los cambios del stash (con `-p` muestra el diff completo).

## 3. Sincronización y Remotos

### Subir, bajar y fusionar
* **`git push` / `git pull`**:
    * `-u` (`--set-upstream`): Vincula tu rama local con la remota.
    * `-f` (`--force`): Sobrescribe el historial remoto (peligroso).
    * `--force-with-lease`: Versión segura de force; no sobrescribe si hay cambios ajenos.
    * `--rebase` (en pull): Aplica tus cambios encima de los remotos (evita commits de merge).
    * `--all` (push): Sube **todas** las ramas locales al remoto.
    * `--prune` (push): Elimina del remoto las ramas que ya no existen en local.
    * `--tags` (push): Sube también todas las etiquetas.
    * `--delete <rama>` (push): Elimina una rama del remoto directamente.
    * `--mirror` (push): Refleja exactamente el estado local en el remoto (borra lo que sobre).
    * `--dry-run` (push): Muestra qué se subiría sin hacerlo realmente.
    * `--no-verify` (push): Salta los hooks de pre-push.
    * `--negotiation-tip=<commit>` (pull): Especifica qué commit usar como base de negociación.
    * `--ff-only` (pull): Solo avance rápido; aborta si requiere merge.
    * `--squash` (pull): Fusiona los cambios remotos como un único commit local.
    * `--autostash` (pull): Stash automático antes del pull y pop después.

* **`git remote`**:
    * `-v` (`--verbose`): Muestra las URLs de conexión.
    * `prune <nombre>`: Limpia ramas locales "fantasma" que ya no existen en el servidor.
    * `rename <viejo> <nuevo>`: Renombra un remote.
    * `add <nombre> <url>`: Añade un nuevo remote.
    * `remove <nombre>` (`rm`): Elimina un remote.
    * `set-url <nombre> <url>`: Cambia la URL de un remote existente.
    * `show <nombre>`: Muestra información detallada del remote.

* **`git fetch`**:
    * `--all`: Obtiene datos de **todos** los remotos configurados.
    * `--prune`: Elimina las referencias remotas locales que ya no existen en el servidor.
    * `--tags`: Descarga también todas las etiquetas.
    * `--prune-tags`: Elimina tags locales que ya no existen en el remoto.
    * `--depth <N>`: Fetch limitado a N commits (shallow).
    * `--unshallow`: Convierte un clon superficial a completo.
    * `--dry-run`: Muestra qué se traería sin descargarlo.
    * `-p` / `--prune`: Sinónimo de `--prune`.

* **`git merge`**:
    * `--no-ff`: Fuerza un commit de merge aunque el avance sea rápido (Fast-Forward). Crea un nodo visible en el historial.
    * `--ff-only`: Solo hace merge si puede ser Fast-Forward; si no, aborta.
    * `--squash`: Fusiona los cambios de la rama entrante como un **único commit** en la rama actual (sin historial).
    * `--abort`: Cancela el merge en curso y vuelve al estado anterior.
    * `--continue`: Continúa el merge tras resolver conflictos.
    * `-m "<mensaje>"`: Mensaje personalizado para el commit de merge.
    * `--strategy=<estrategia>`: Algoritmo de merge (`recursive`, `ours`, `octopus`, `ort` — el nuevo default).
    * `--strategy-option=<opción>`: Opciones de la estrategia (`ours`, `theirs`, `patience`, `diff-algorithm=histogram`).
    * `--no-commit`: Realiza el merge pero no crea el commit automático (para inspeccionar antes).

* **`git submodule`**:
    * `add <url> [<ruta>]`: Añade un submódulo al proyecto (clona y registra en `.gitmodules`).
    * `init`: Inicializa los submódulos registrados (descarga la config de `.gitmodules`).
    * `update --init --recursive`: Descarga/clona todos los submódulos (y sus submódulos anidados).
    * `status`: Muestra el estado de cada submódulo (commit actual, cambios pendientes).
    * `foreach "<comando>"`: Ejecuta un comando en **cada** submódulo (útil para `git pull` masivo).
    * `deinit [-f] <ruta>`: Desregistra un submódulo (opcional: borra su working tree).
    * `sync`: Sincroniza las URLs del submódulo con los cambios en `.gitmodules`.
    * `absorbgitdirs`: Mueve los `.git` de submódulos al superproyecto.
    * `set-branch -b <rama> <ruta>`: Cambia la rama de seguimiento de un submódulo.
    * `set-url <ruta> <url>`: Cambia la URL de un submódulo existente.

## 4. Navegación e Historial

### Explorar el historial
* **`git log`**:
    * `--oneline`: Resumen de un commit por línea.
    * `--graph`: Dibuja el árbol visual de ramas.
    * `--all`: Muestra el historial de todas las ramas.
    * `-p` (`--patch`): Muestra el código exacto que cambió.
    * `-S "<texto>"`: Busca texto específico dentro del código histórico.
    * `-L :<función>:<archivo>`: Rastrea la evolución de una función específica.
    * `--author="<nombre>"`: Filtra por autor.
    * `--no-merges`: Oculta los commits de fusión.
    * `--since=<fecha>` / `--after=<fecha>`: Commits desde una fecha (ej. `"2024-01-01"`, `"2 weeks ago"`).
    * `--until=<fecha>` / `--before=<fecha>`: Commits hasta una fecha.
    * `--grep=<patrón>`: Filtra commits cuyo mensaje coincida con el patrón.
    * `--all-match`: Todas las expresiones `--grep` deben coincidir (AND lógico).
    * `--invert-grep`: Muestra commits que **no** coinciden con `--grep`.
    * `--diff-filter=<ACDMRTUXB>`: Filtra por tipo de cambio (A=Added, C=Copy, D=Deleted, M=Modified, R=Renamed).
    * `--follow`: Sigue renombrados de un archivo a través del historial.
    * `--format="%h %s"`: Formato personalizado (`%h` hash corto, `%an` autor, `%ai` fecha ISO, `%d` refs).
    * `--simplify-by-decoration`: Solo commits con tags/ramas (ideal para ver hitos).

* **`git checkout` / `git switch`**:
    * `-b` / `-c`: Crea una rama nueva y salta a ella.
    * `-C`: Fuerza la creación/sobrescritura de la rama.
    * `-`: Vuelve a la rama anterior.
    * `-d` / `--detach`: Salta a un commit específico sin estar en ninguna rama.
    * `--discard-changes`: Cambia de rama borrando cambios locales sucios.
    * `--orphan <rama>`: Crea una rama huérfana sin historial (útil para reiniciar documentación, gh-pages, etc.).
    * `--guess`: Si el nombre no es una rama local, busca una rama remota con el mismo nombre y la checkout automáticamente.

* **`git branch`**:
    * `-d <rama>`: Elimina la rama (solo si está fusionada).
    * `-D <rama>`: Fuerza la eliminación aunque no esté fusionada.
    * `-m <viejo> <nuevo>`: Renombra la rama.
    * `-M <viejo> <nuevo>`: Fuerza el renombrado aunque exista el nuevo nombre.
    * `-a` (`--all`): Lista todas las ramas (locales + remotas).
    * `-r` (`--remotes`): Lista solo las ramas remotas.
    * `--merged` / `--no-merged`: Filtra ramas fusionadas o no fusionadas contra la actual.
    * `--sort=<clave>`: Ordena el listado por `-committerdate`, `authorname`, etc.
    * `-v` (`--verbose`): Muestra el último commit de cada rama.
    * `--show-current`: Muestra el nombre de la rama actual.
    * `--set-upstream-to=<remote>/<rama>`: Vincula la rama local al upstream.
    * `--edit-description`: Edita la descripción de la rama (visible en interfaces web).

* **`git tag`**:
    * `-a <nombre>` (`--annotated`): Crea una etiqueta con metadatos (autor, fecha, mensaje).
    * `-m "<mensaje>"`: Mensaje para la etiqueta anotada.
    * `-s <nombre>` (`--sign`): Firma la etiqueta con GPG.
    * `-d <nombre>` (`--delete`): Elimina una etiqueta local.
    * `-l` / `--list`: Lista etiquetas (acepta patrones como `v1.*`).
    * `--sort=<clave>`: Ordena el listado (`-v:refname` para orden semántico de versiones).
    * `--contains <commit>`: Muestra etiquetas que contienen un commit específico.
    * `--merged` / `--no-merged`: Filtra etiquetas fusionadas o no.
    * `--points-at <objeto>`: Lista etiquetas que apuntan a un commit específico.
    * `--format="%(refname) %(subject)"`: Formato personalizado de salida.

* **`git show`**:
    * `--stat`: Resumen de archivos cambiados y líneas añadidas/eliminadas.
    * `--name-only`: Solo nombres de archivos afectados.
    * `--name-status`: Nombres de archivos con estado (A/M/D).
    * `-s` (`--no-patch`): Omite el diff, solo muestra metadatos del commit.
    * `--pretty=<formato>`: Formato de salida (`oneline`, `short`, `full`, `fuller`, `format:...`).
    * `-q` (`--quiet`): Suprime el mensaje del diff.
    * `--no-notes`: No muestra notas asociadas al commit.
    * `--show-notes`: Muestra las notas (por defecto si existen).
    * Sin argumentos: muestra el último commit (`HEAD`).

* **`git shortlog`**:
    * `-s` (`--summary`): Solo el número de commits por autor, sin listar los mensajes.
    * `-n` (`--numbered`): Ordena por número de commits (descendente) en lugar de alfabéticamente.
    * `--since=<fecha>` / `--after=<fecha>`: Commits desde una fecha.
    * `--until=<fecha>` / `--before=<fecha>`: Commits hasta una fecha.
    * `--all`: Cuenta commits de todas las ramas.
    * `--no-merges`: Excluye commits de merge del recuento.
    * `-e` (`--email`): Muestra el email junto al nombre del autor.
    * `--format`: Formato personalizado (útil para changelogs).

* **`git describe`**:
    * `--tags`: Usa cualquier etiqueta (no solo las anotadas).
    * `--all`: Usa cualquier referencia (ramas, tags, HEAD).
    * `--abbrev=<N>`: Número de dígitos del hash abreviado (por defecto 7).
    * `--dirty[=<marca>]`: Añade `-dirty` (o la marca que elijas) si el working tree está sucio.
    * `--match=<patrón>`: Solo considera etiquetas que coincidan con el patrón glob.
    * `--always`: Muestra el hash abreviado si no hay etiquetas disponibles.

### Búsqueda en el historial
* **`git grep`**:
    * `-n` (`--line-number`): Muestra el número de línea de cada coincidencia.
    * `-i` (`--ignore-case`): Búsqueda insensible a mayúsculas/minúsculas.
    * `-w` (`--word-regexp`): Coincidencia solo de palabras completas.
    * `-c` (`--count`): Muestra el número de coincidencias por archivo.
    * `-l` (`--files-with-matches`): Solo los nombres de archivo que contienen el patrón.
    * `-L` (`--files-without-match`): Archivos que **no** contienen el patrón.
    * `-p` (`--show-function`): Muestra el nombre de la función que contiene la coincidencia.
    * `--and` / `--or` / `--not`: Operadores lógicos entre patrones.
    * `--cached`: Busca en el stage (índice).
    * `--no-index`: Busca fuera de un repositorio Git (como grep normal pero con sintaxis Git).

## 5. Reescritura y Recuperación (Avanzado)

### Reorganizar commits
* **`git rebase`**:
    * `-i` (`--interactive`): Interfaz para unir, renombrar, reordenar o borrar commits.
    * `--continue` / `--skip`: Continúa tras resolver conflictos o salta un commit problemático.
    * `--abort`: Cancela el rebase y vuelve al estado anterior.
    * `--onto <base> <desde> <hasta>`: Rebase avanzado que cambia la base de un rango de commits a otra rama.
    * `--rebase-merges`: Preserva los merges creados manualmente durante el rebase.
    * `--autosquash`: Busca commits con `fixup!`/`squash!` en el mensaje y los empareja automáticamente.
    * `--committer-date-is-author-date`: Conserva la fecha original del autor.
    * `-X theirs` / `-X ours`: En conflictos, prefiere siempre la versión de la rama que rebasas o la tuya.
    * `--update-refs`: Actualiza las ramas que apuntan a commits rebasados.

* **`git range-diff`**:
    * `--creation-factor=<N>`: Ajusta la sensibilidad para detectar commits nuevos (default 60).
    * `--no-dual-color`: Desactiva el coloreado dual (solo rojo/verde normal).
    * `--notes`: Incluye notas en la comparación.
    * Uso: `git range-diff <rama1>...<rama2>` o `git range-diff <a1>..<a2> <b1>..<b2>`.

* **`git format-patch`**:
    * `-1`, `-2`...: Número de commits a exportar (desde HEAD hacia atrás).
    * `--stdout`: Imprime en stdout en lugar de archivos.
    * `--output-directory=<dir>`: Carpeta de destino para los parches.
    * `--signoff`: Añade `Signed-off-by` al final del mensaje.
    * `--cover-letter`: Genera un parche `0000-cover-letter.patch` con resumen.
    * `--thread`: Añade headers de threading para hilos de email.

* **`git am`**:
    * `--continue`: Continúa tras resolver conflictos.
    * `--skip`: Salta el parche actual y continúa con el siguiente.
    * `--abort`: Cancela la aplicación de parches.
    * `--signoff`: Añade `Signed-off-by` (como `git format-patch --signoff`).
    * `-3` (`--3way`): Intenta fusión a 3 bandas si el parche falla.
    * `--reject`: Guarda las partes fallidas como `.rej` en lugar de abortar.

### Deshacer y navegar en el tiempo
* **`git reset`**:
    * `--soft`: Mueve HEAD pero mantiene cambios en el **Stage**.
    * `--mixed` (Default): Mueve HEAD y saca archivos del Stage al **Directorio**.
    * `--hard`: Borra todo. Vuelve al estado exacto del commit indicado.
    * `-p`: Reset interactivo para elegir partes específicas del archivo.
    * `--keep`: Mantiene los archivos con cambios sin seguimiento; aborta si hay conflicto.

### Recuperación
* **`git reflog`**: El historial de movimientos local para recuperar ramas o commits borrados.
* **`git cherry-pick <hash>`**:
    * `-n` (`--no-commit`): Aplica los cambios al stage sin crear commit (útil para cherry-pick múltiple).
    * `-x`: Añade una línea al mensaje indicando de dónde se cherry-pickeó.
    * `--signoff`: Añade `Signed-off-by`.
    * `-e` (`--edit`): Edita el mensaje del commit antes de confirmar.

## 6. Limpieza y Especialista
* **`git clean`**:
    * `-n`: Dry-run. Simulación de borrado.
    * `-f`: Fuerza la eliminación de archivos no rastreados.
    * `-fdx`: Borra archivos, directorios e ignorados por `.gitignore`.
    * `-X`: Borra **solo** los archivos ignorados por `.gitignore`.

* **`git blame`**:
    * `-L 10,20`: Analiza solo esas líneas.
    * `-w`: Ignora espacios en blanco.
    * `-M` / `-C`: Detecta si el código fue movido o copiado de otros archivos.

* **`git bisect`**:
    * `start`: Inicia la búsqueda binaria.
    * `bad` / `good`: Marca el commit actual como malo o bueno (`git bisect bad` o `git bisect good <commit>`).
    * `skip`: Salta un commit que no se puede probar.
    * `reset`: Sale del modo bisect y vuelve al commit original.
    * `run <script>`: Automatiza la búsqueda ejecutando un script que devuelva 0 (good) o 1 (bad).
    * `log`: Muestra el progreso del bisect (se puede reanudar después).
    * `replay <archivo>`: Reanuda un bisect desde un log guardado.
    * `--no-checkout`: No hace checkout de los commits (útil para probar archivos sin tocar el working tree).
    * `--term-old=<término>` / `--term-new=<término>`: Personaliza los términos (ej. `old`/`new` en lugar de `bad`/`good`).

* **`git revert`**:
    * `-n` (`--no-commit`): Revierte los cambios pero no crea commit (los deja en stage para revisar).
    * `-m 1` (`--mainline`): Para revertear un merge: indica qué padre conservar (1 = la rama actual).
    * `--no-edit`: No abre el editor; usa el mensaje por defecto.
    * `--signoff`: Añade `Signed-off-by`.
    * `--strategy=<estrategia>`: Estrategia de merge para la reversión.
    * `--cleanup=<modo>`: Limpieza del mensaje (`strip`, `whitespace`, `verbatim`).

## 7. Mantenimiento y Exportación
* **`git archive`**:
    * `--format=<formato>`: `zip`, `tar`, `tgz`, `tar.gz`.
    * `-o <archivo>` (`--output`): Archivo de salida.
    * `--prefix=<prefijo>/`: Añade una carpeta raíz al contenido exportado.
    * `HEAD`, `<tag>`, `<rama>`: Lo que se exporta.
    * `--remote=<url>`: Exporta desde un repositorio remoto.
    * `--worktree-attributes`: Respeta atributos exportados por `.gitattributes` (como `export-ignore`).

* **`git worktree`**:
    * `add <ruta> [<rama>]`: Crea un nuevo working tree con una rama.
    * `list`: Lista todos los working trees activos.
    * `remove <ruta>`: Elimina un working tree (solo si está limpio).
    * `lock` / `unlock <ruta>`: Bloquea/desbloquea un working tree para evitar que lo borren.
    * `prune`: Limpia referencias a working trees eliminados.
    * `--detach`: Crea el worktree en modo detached HEAD.

* **`git gc`**:
    * `--prune=<fecha>`: Elimina objetos sueltos más antiguos que la fecha (ej. `now`, `2.weeks.ago`).
    * `--aggressive`: Optimización intensiva (más lenta, mejor compresión).
    * `--auto`: Ejecuta GC solo si es necesario (por umbral de objetos sueltos/packs).
    * `--quiet`: Modo silencioso (sin salida).

* **`git fsck`**:
    * `--full`: Escanea todos los objetos del repositorio.
    * `--strict`: Comprobación más exhaustiva (modo estricto).
    * `--lost-found`: Restaura objetos huérfanos a `.git/lost-found/`.
    * `--unreachable`: Muestra objetos sin referencia.
    * `--dangling`: Muestra commits/árboles huérfanos (normalmente inofensivos).

* **`git repack`**:
    * `-a` (`--all`): Reempaqueta **todos** los objetos en un solo pack.
    * `-d`: Elimina los packs viejos tras crear el nuevo.
    * `--window=<N>`: Ventana de deduplicación (más alto = mejor compresión, más lento).
    * `--depth=<N>`: Profundidad máxima de delta (default 50).
    * `-F` (`--no-reuse-delta`): Recalcula deltas desde cero (más lento pero comprime mejor).

* **`git bundle`**:
    * `create <archivo> <revisiones>`: Crea un bundle con un rango de commits.
    * `verify <archivo>`: Verifica que el bundle sea válido.
    * `list-heads <archivo>`: Lista las referencias disponibles en el bundle.
    * `unbundle <archivo>`: Restaura el bundle en el repositorio.
    * `--version=<version>`: Versión del formato del bundle (v2 o v3).

* **`git count-objects`**:
    * `-v` (`--verbose`): Estadísticas detalladas: número de objetos, packs, espacio usado, etc.
    * `--human-readable`: Muestra tamaños en formato legible (KB, MB).

## 📂 Bonus: Configuración Global de `.gitignore`
Evita subir archivos basura de sistema o herramientas en todos tus proyectos locales:

```bash
# 1. Crear el archivo global
touch ~/.gitignore_global

# 2. Configurar Git para que lo use siempre
git config --global core.excludesfile ~/.gitignore_global

# 3. Ejemplo de contenido recomendado para ~/.gitignore_global:
# node_modules/
# .vscode/
# .idea/
# .DS_Store
# Thumbs.db

# .env
```
