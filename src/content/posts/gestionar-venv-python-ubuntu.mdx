Creating and activating Python virtual environments is something we do constantly, but always typing the same commands. In this post I'll show you how to create two aliases to reduce everything to a single command, explaining every step of the process.

---

## The problem

Every time you create a Python project, you have to do this:

```bash
# 1. Create the virtual environment
python3 -m venv .venv

# 2. Activate it
source .venv/bin/activate

# 3. When you're done, deactivate it
deactivate
```

That's 3 commands every time. If you work with multiple projects a day, they add up.

---

## The solution

Create two aliases in your shell:

| Command | What it does |
|---------|--------------|
| `mkvenv` | Creates `.venv` and activates it (2 in 1) |
| `act` | Activates existing `.venv` |

With this, instead of typing 2 commands, you type one.

---

## Step 1: Understand what an alias is

An alias is a **keyboard shortcut for the terminal**. You define a short word that replaces a long command.

```bash
# Without alias
python3 -m venv .venv && source .venv/bin/activate

# With alias
mkvenv
```

**Where are aliases stored?** In a shell configuration file. Every time you open a terminal, your shell reads that file and loads the aliases.

---

## Step 2: Find out which shell you're using

Depending on which shell you use, the file is different:

```bash
# Run this to find your shell
echo $SHELL
```

| Result | Shell | Configuration file |
|--------|-------|-------------------|
| `/bin/bash` | Bash | `~/.bashrc` |
| `/bin/zsh` | Zsh | `~/.zshrc` |

**On Ubuntu, bash is the default.** If you're not sure, use `~/.bashrc`.

---

## Step 3: Open the configuration file

```bash
# Open with nano (terminal editor)
nano ~/.bashrc
```

This opens the file in nano. You'll see many lines of configuration. Don't worry about what's there — you just need to go to the end.

---

## Step 4: Add the `mkvenv` function

Go to the end of the file:
- Press **Ctrl+End** (or **Ctrl+Shift+End**) to go to the end

Add this at the end of the file:

```bash
# ============================================
# Python aliases
# ============================================

# Creates and activates a virtual environment called .venv
mkvenv() {
    python3 -m venv .venv
    source .venv/bin/activate
}
```

**Why is this a function and not an alias?**

| Type | When to use it |
|------|----------------|
| **Alias** | When you run **a single command** |
| **Function** | When you run **multiple commands** in sequence |

`mkvenv` needs to run **two commands**: create the environment AND activate it. That's why it's a function.

---

## Step 5: Add the `act` alias

Just below the function above, add:

```bash
# Activates the .venv virtual environment in the current directory
alias act='source .venv/bin/activate'
```

**Why an alias and not a function?** Because we only need to run **a single command** (`source`).

---

## Step 6: Save the file

In nano:
1. Press **Ctrl+O** → It asks "File Name to Write". Press **Enter**
2. Press **Ctrl+X** → Exit

**Don't close the terminal.** The changes haven't been applied yet.

---

## Step 7: Apply the changes

To make the changes take effect **without closing the terminal**:

```bash
source ~/.bashrc
```

**What does `source` do?** It re-reads the configuration file and applies the changes in the current terminal.

**What happens if I don't run `source`?** You'd have to close and open the terminal again. Changes are applied automatically when you open a new terminal.

---

## Step 8: Verify it works

### Check that the alias is loaded

```bash
# Check if mkvenv exists
type mkvenv
# Expected output: mkvenv is a function

# Check if act exists
type act
# Expected output: act is aliased to 'source .venv/bin/activate'
```

### Test it in practice

```bash
# 1. Create a test folder
mkdir ~/test_venv
cd ~/test_venv

# 2. Create and activate the environment
mkvenv
# You should see: (.venv) user@ubuntu:~/test_venv$

# 3. Verify Python works inside the environment
python --version
# Should work without errors

# 4. Deactivate
deactivate

# 5. Activate again
act
# You should see: (.venv) user@ubuntu:~/test_venv$

# 6. Clean up (optional)
cd ~
rm -rf ~/test_venv
```

---

## Step 9: Understand why it always works

The `~/.bashrc` file is loaded **automatically** every time you:

1. Open a new terminal
2. Open a new tab in your terminal
3. Run `bash` or `source ~/.bashrc`

**You don't need to do anything else.** Once you save the aliases in `~/.bashrc`, they're always available.

---

## Final summary

| Command | What it does | Type | Location |
|---------|--------------|------|----------|
| `mkvenv` | Creates `.venv` and activates it | Function | `~/.bashrc` |
| `act` | Activates existing `.venv` | Alias | `~/.bashrc` |

**Important files:**
- `~/.bashrc` → Bash configuration (where you save aliases)
- `.venv/` → The virtual environment created (in each project)

**Useful commands:**
```bash
source ~/.bashrc    # Apply changes without closing terminal
type mkvenv         # Check if it's a function
type act            # Check if it's an alias
alias               # List all defined aliases
```

---

## Troubleshooting

| Problem | Cause | Solution |
|---------|-------|----------|
| `mkvenv: command not found` | You didn't save the alias or didn't run `source` | Run `source ~/.bashrc` |
| `bash: .venv/bin/activate: No such file` | The environment doesn't exist in that folder | Run `mkvenv` first |
| `function not found` | You saved in the wrong file | Verify you edited `~/.bashrc` |
| `Doesn't work after closing terminal` | You didn't save the file | Repeat steps 6-7 |

## Additional tips

### See all your aliases

```bash
alias
# Lists all defined aliases
```

### Remove an alias temporarily

```bash
unalias act        # For aliases
unfunction mkvenv  # For functions
```

### Make an alias more visible

Add color to the prompt when the venv is active:

```bash
# Add this in ~/.bashrc after the aliases:
if [[ -n "$VIRTUAL_ENV" ]]; then
    PS1="\[\e[32m\](.venv)\[\e[0m\] $PS1"
fi
```

### Create an alias to see which environments you have

```bash
# Add in ~/.bashrc:
alias venvs='find . -name "pyvenv.cfg" -exec dirname {} \;'
# Usage: venvs
# Lists all .venv directories in the current directory
```
