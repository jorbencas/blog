Cuando decides lanzar tu porfolio web, es fácil caer en la tentación de instalar un framework pesado, meter librerías de animaciones en 3D y preocuparte solo de que "se vea bonito". Sin embargo, el mercado actual y los motores de búsqueda exigen algo más: **rendimiento real, accesibilidad y semántica**.

En este artículo te cuento el *detrás de escena* de cómo optimicé mi porfolio personal para conseguir una puntuación perfecta en Google Lighthouse, sin sacrificar la estética.

---

## 🎨 1. La Psicología del Color: ¿Por qué esta paleta?

La primera impresión entra por los ojos, pero los colores deben responder a una estrategia, no a un impulso. Para este proyecto elegí una combinación que equilibra la tecnología con la calidez:

| Color | Código Hex | Propósito Psicológico / Técnico |
| :--- | :--- | :--- |
| **Azul Eléctrico** | `#0066cc` | Color dominante. Transmite profesionalidad, confianza, serenidad y es el estándar de la industria tech. |
| **Fondo Crema Cálido**| `#efe0d8d7`| Rompe con el típico blanco frío de hospital o el modo oscuro genérico. Da una sensación orgánica, premium y reduce la fatiga visual. |
| **Negro Puro** | `#111111` | Usado en textos principales para garantizar un contraste ultra alto (imprescindible para cumplir las normativas WCAG de accesibilidad). |

## 🏗️ 2. HTML Semántico y Accesibilidad (SEO Nativo)

Los robots de Google no "ven" los colores; leen el código. Reemplacé la típica estructura inundada de `<div>` por etiquetas semánticas que explican qué es cada cosa:

*   **`<header>` y `<nav>`**: Para la cabecera fija, indicando explícitamente a los lectores de pantalla que es la navegación principal mediante `aria-label="Navegación principal"`.
*   **`<main>` y `<section>`**: Delimitan las áreas clave de la página (Experiencia, Conocimientos, Proyectos), permitiendo a los motores de búsqueda indexar el contenido en orden de importancia.
*   **`<article>`**: Utilizado para cada tarjeta de experiencia laboral y presentación, indicando que son bloques de información independientes.
*   **Mejora en enlaces (`aria-label` y `title`)**: Los botones como el de "Descargar CV" o los iconos de redes sociales ahora llevan descripciones nativas detalladas para que cualquier usuario con discapacidad visual sepa exactamente a dónde dirigen.

## ⚡ 3. Rendimiento Gráfico: Forzando la GPU para evitar parpadeos

Uno de los mayores retos visuales apareció al combinar una cabecera con efecto de desenfoque (`backdrop-filter: blur`) con una lista de habilidades repleta de iconos en formato SVG con animaciones en `hover`. 

Al hacer scroll, los elementos vibraban o daban pequeños tirones. ¿La razón? El navegador calculaba las capas usando la CPU en tiempo real. Lo solucionamos aplicando **Aceleración por Hardware** en el archivo CSS:

```css
.knowledge ul li img {
  will-change: transform;       /* Avisa al navegador de futuros cambios */
  transform: translateZ(0);     /* Fuerza al renderizador a usar la tarjeta gráfica (GPU) */
}
```

Con estas dos líneas, el scroll pasó de ser tosco a correr a unos fluidos 60 FPS en cualquier dispositivo móvil.
📸 4. Estrategia de Imágenes: El mito del .webp

Usar el formato .webp es un gran paso, pero no es mágico si la imagen original mide 4000px. Para este proyecto, apliqué reglas estrictas de compresión:

    El Banner de Fondo: Redimensionado a un máximo de 1920px de ancho y comprimido por debajo de los 150 KB.

    El Avatar: Aunque la foto original tenía mucha resolución, en la web se muestra a un tamaño máximo de 140x140px. Se recortó a esa medida exacta y su peso final se redujo a escasos 15 KB.

    Atributos Nativos: Se añadieron dimensiones explícitas (width y height) en el HTML para evitar el Cumulative Layout Shift (CLS), es decir, que la página dé saltos mientras se carga.

🔄 5. Integración Dinámica: Consumiendo la API del Blog

Para mantener el porfolio actualizado de forma automática, añadí un script en JavaScript puro (index.js) que realiza una petición asíncrona (fetch) a la API del blog (desarrollado de forma externa con Astro).

El script inyecta dinámicamente las últimas publicaciones dentro de un contenedor dedicado:

``` JavaScript

// Ejemplo conceptual de la integración de la API
async function cargarUltimosPosts() {
  const container = document.getElementById('dynamic-posts-container');
  try {
    const response = await fetch('[https://api.tu-blog-ficticio.com/posts?limit=3](https://api.tu-blog-ficticio.com/posts?limit=3)');
    const posts = await response.json();
    
    container.innerHTML = posts.map(post => `
      <article class="post-card">
        <h3>${post.title}</h3>
        <p>${post.excerpt}</p>
        <a href="${post.url}" class="post-link">Leer más →</a>
      </article>
    `).join('');
  } catch (error) {
    container.innerHTML = '<p>No se pudieron cargar los artículos en este momento.</p>';
  }
}
```
    💡 Nota de arquitectura futura: Aunque este sistema mediante JavaScript del lado del cliente funciona perfectamente, para mejorar el presupuesto de rastreo (Crawl Budget) de Google, el siguiente paso evolutivo será traer estos posts durante la fase de compilación en el servidor aprovechando las bondades nativas de Astro.

🚀 Conclusión y Resultados

Optimizar un porfolio no consiste en usar herramientas complejas, sino en entender cómo consumen la web tanto los usuarios como las máquinas. Al corregir el orden de las secciones en el menú móvil, ajustar los espacios de scroll (scroll-padding-top) y limpiar la estructura semántica, la web no solo es visualmente atractiva, sino técnicamente impecable.
