# Guía de Rust: De 0 a 100

## ¿Qué es Rust?

Rust es un lenguaje compilado, tipado estáticamente, enfocado en seguridad de memoria **sin GC**, concurrencia sin carreras de datos y rendimiento C/C++. Creado por **Graydon Hoare** en 2006 en Mozilla Research, lanzado públicamente en 2010, estable desde 2015.

**¿Qué lo hace único?**
- **Ownership**: el compilador verifica en compile-time que no haya use-after-free, double free o data races. Sin GC ni gestión manual.
- **Zero-cost abstractions**: las abstracciones se compilan a código máquina tan eficiente como el escrito a mano.
- **Fearless concurrency**: el borrow checker previene data races en compilación.
- **FFI sin runtime**: integrable en cualquier runtime (embebido, kernel, WASM).

**¿Dónde se usa?**
- **Sistemas**: Linux kernel (Rust-for-Linux 6.1+), Fuchsia OS
- **Navegadores**: Firefox (Stylo, WebRender), Servo
- **Cloud**: AWS (Firecracker VMM, Lambda runtime), Cloudflare (Pingora), Dropbox (filesystem)
- **CLI/DevTools**: ripgrep, fd, bat, delta, zoxide, alacritty, starship
- **WebAssembly**: Figma, Shopify, Atlassian
- **Blockchain**: Solana, Polkadot, Near
- **Embebido**: Tock OS, Embassy, ESP-RS

**¿Quién lo usa?** Microsoft (Azure IoT), Google (Android/Fuchsia), Meta, Amazon, Discord, Figma.

Fuente: [Rust官方](https://www.rust-lang.org/learn), [Rust Blog](https://blog.rust-lang.org/), [Rust in Android](https://security.googleblog.com/2022/12/memory-safe-languages-in-android-13.html)

## Paradigmas

Rust es un lenguaje **multi-paradigma** con énfasis en funcional y sistémico. Puedes mezclar paradigmas según el problema.

### Imperativo

Rust tiene statements y expressions. Casi todo es una expresión (retorna un valor):

```rust
let x = if cond { 10 } else { 20 };  // if es expresión
let y = loop { break 42; };          // loop retorna valor
let z = match n {
    1 => "uno",
    _ => "otro",
};
```

### Funcional

Rust adopta varios conceptos funcionales:

- **Inmutabilidad por defecto**: `let` crea variables inmutables. Solo `let mut` permite mutación.
- **Iterators**: lazy, zero-cost, chainable (`map`, `filter`, `fold`, `flat_map`)
- **Closures**: `|args| expr`, capturan entorno por referencia/move, traits `Fn`/`FnMut`/`FnOnce`
- **Pattern matching exhaustivo**: `match` obliga a cubrir todos los casos
- **Option/Result como mónadas**: `map`, `and_then`, `or_else`, `unwrap_or_else` permiten encadenar sin anidar

```rust
let pares: Vec<i32> = (0..10)
    .filter(|x| x % 2 == 0)
    .map(|x| x * 2)
    .collect();

let r = Some(10)
    .map(|x| x * 2)
    .filter(|x| x > 5)
    .and_then(|x| if x < 100 { Some(x) } else { None });
```

### POO parcial

Rust no tiene clases ni herencia, pero ofrece:

- **Structs + `impl`**: datos + métodos (como clases sin herencia)
- **Traits como interfaces**: definen comportamiento compartido
- **Composición sobre herencia**: agregar campos en lugar de extender
- **No clases**: no hay `class`, `extends`, `super`, `protected`
- **Encapsulación**: `pub` controla visibilidad de campos y métodos

```rust
trait Volador { fn volar(&self); }

struct Pajaro { nombre: String }
struct Avion { modelo: String }

impl Volador for Pajaro { fn volar(&self) { println!("{} bate alas", self.nombre); } }
impl Volador for Avion { fn volar(&self) { println!("{} enciende motores", self.modelo); } }
```

### Concurrente

El **ownership** garantiza thread-safety en compilación:

- El borrow checker previene data races: no puedes tener `&mut` simultáneos entre threads
- Traits `Send`/`Sync`: el compilador verifica qué tipos son seguros entre threads
- `Rc<T>` no es `Send` (contador no atómico), `Arc<T>` sí
- `Mutex<T>` protege acceso concurrente con RAII

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let contador = Arc::new(Mutex::new(0));
let mut handles = vec![];
for _ in 0..10 {
    let c = Arc::clone(&contador);
    handles.push(thread::spawn(move || {
        let mut num = c.lock().unwrap();
        *num += 1;
    }));
}
for h in handles { h.join().unwrap(); }
println!("{}", contador.lock().unwrap()); // 10
```

### Sistémico

Rust da control de memoria sin GC:

- **Sin garbage collector**: la memoria se libera en compile-time con ownership
- **Zero-cost abstractions**: iterators, closures, genéricos se compilan a código tan eficiente como el escrito a mano
- **Control manual**: puedes elegir stack vs heap (`Box`), memoria compartida (`Rc`/`Arc`), representaciones con `repr(C)`
- **FFI sin runtime**: integrable en C, Python, JS, WASM, kernel

```rust
// Zero-cost: este código se compila a un loop óptimo
let suma: u32 = (0..1000).filter(|x| x % 2 == 0).map(|x| x * x).sum();
```

| Paradigma | Soporte en Rust |
|-----------|----------------|
| Imperativo | Statements, loops, mutabilidad explícita |
| Funcional | Inmutabilidad, iterators, closures, pattern matching, Option/Result |
| POO | Structs + impl, traits, composición, encapsulación |
| Concurrente | Ownership + Send/Sync, canales, Arc\<Mutex\> |
| Sistémico | Sin GC, control de memoria, zero-cost, FFI, no_std |

### Memoria: Stack vs Heap

| Aspecto | Stack | Heap |
|---------|-------|------|
| Velocidad | Instantáneo | Más lento (allocador) |
| Tamaño | Conocido en compile-time | Dinámico |
| Límite | Pequeño (8 MB típico) | Grandísimo |
| Tipos | Escalares, tuplas pequeñas, arrays fijos | Box, Vec, String, Rc, Arc |

**Regla general:** todo se almacena en stack por defecto. `Box<T>`, `Vec<T>`, `String`, `Rc<T>`, `Arc<T>` almacenan sus datos en heap.

### Ownership y RAII

El ownership garantiza:
- **No dangling pointers**: cada referencia tiene un lifetime verificado
- **No double free**: cada valor tiene exactamente un owner
- **No memory leaks** (en la práctica): RAII libera recursos al salir de ámbito

RAII (Resource Acquisition Is Initialization): el `Drop` trait se ejecuta automáticamente al salir del ámbito:

```rust
struct Archivo { fd: i32 }
impl Drop for Archivo {
    fn drop(&mut self) {
        println!("Cerrando archivo {}", self.fd);
    }
}
{
    let f = Archivo { fd: 42 };
}
```

**No garbage collector:** toda la gestión de memoria ocurre en compile-time. No hay pausas de GC, no hay runtime overhead de memoria.

## Conceptos clave

### Ownership, Borrowing y Lifetimes

**Tres reglas del ownership:**
1. Cada valor tiene un **único propietario**
2. Al salir del ámbito, el valor se **dropea** (libera)
3. El propietario puede mover (transferir) o prestar (borrow) el valor

```rust
// Move semantics
let s1 = String::from("hola");
let s2 = s1;             // s1 se mueve a s2
// println!("{s1}");     // ERROR: moved

// Clone (deep copy)
let s1 = String::from("hola");
let s2 = s1.clone();     // Copia explícita
println!("{s1} {s2}");   // OK ambos

// Copy types (stack)
let x = 5;
let y = x;               // Copy, no move (i32: Copy)
println!("{x} {y}");     // OK
```

**Borrowing:**

```rust
fn largo(s: &String) -> usize { s.len() }  // Presta, no mueve

let s = String::from("hola");
let l = largo(&s);
println!("{s} tiene {l}");  // s sigue vivo
```

**Reglas del borrow checker:**

| Situación | Permitido | Por qué |
|-----------|-----------|---------|
| Múltiples `&T` | ✅ | Solo lectura |
| Un `&mut T` | ✅ | Escritura exclusiva |
| `&T` + `&mut T` simultáneo | ❌ | Data race en potencia |
| Referencia a variable local | ❌ | Dangling pointer |

```rust
let mut s = String::from("hola");
let r1 = &s;      // OK
let r2 = &s;      // OK (múltiples inmutables)
// let r3 = &mut s; // ERROR: ya hay inmutables
println!("{r1} {r2}");  // Las inmutables dejan de usarse aquí
let r3 = &mut s;   // OK ahora
r3.push_str(" mundo");
```

**Lifetimes:**

```rust
// 'a: el output vive tanto como el input más corto
fn mas_largo<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

// Elisión: el compilador infiere lifetimes automáticamente
fn primera(s: &str) -> &str {    // fn primera<'a>(s: &'a str) -> &'a str
    s.split_whitespace().next().unwrap_or("")
}
```

**Diagrama conceptual:**

```
Stack:
  let s1 = String::from("hola")
  ┌──────────────┐
  │ s1: ptr ──────┼────→ Heap: ['h','o','l','a']
  │     len: 4    │
  │     cap: 4    │
  └──────────────┘

  let s2 = s1;  // MOVE
  ┌──────────────┐
  │ s1: inválido │
  │ s2: ptr ──────┼────→ Heap: ['h','o','l','a']
  └──────────────┘

  let r = &s2;   // BORROW
  ┌──────────────┐
  │ r: ptr ──────┼──→ s2.ptr → Heap
  └──────────────┘
```

**¿Qué previene el borrow checker?**

| Bug C/C++ | Cómo lo previene Rust |
|---|---|
| Use-after-free | Ownership: se dropea al salir de ámbito |
| Double free | Move: un solo owner |
| Buffer overflow | Bounds checking en indexación |
| Data race | `&mut T` es exclusivo entre threads |
| Dangling pointer | Lifetimes verificados |

**Consejo:** La primera semana peleas con el borrow checker. No te frustres. Cada error te enseña un patrón que antes permitías sin saberlo. Con el tiempo, *piensas en ownership* antes de escribir.

Fuente: [The Rust Book — Ownership](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html)

### String vs &str, Box, Rc, Arc, Cell, RefCell, Mutex

| Tipo | Propietario | Thread-safe | Almacenamiento |
|------|-------------|-------------|----------------|
| `String` | Sí | Sí | Heap, mutable, growable |
| `&str` | No | Sí | Referencia a string |
| `Box<T>` | Sí | Sí | Heap allocation simple |
| `Rc<T>` | Compartido | No | Reference counting single-thread |
| `Arc<T>` | Compartido | Sí | Reference counting atómico |
| `Cell<T>` | Interior mut | No | Copy in/out, sin runtime check |
| `RefCell<T>` | Interior mut | No | Borrow check en runtime |
| `Mutex<T>` | Interior mut | Sí | Lock en runtime |
| `RwLock<T>` | Interior mut | Sí | Múltiples readers/writer exclusivo |

```rust
// Box — heap allocation, tipos recursivos
enum Lista {
    Nodo(i32, Box<Lista>),
    Fin,
}

// Rc — reference counting single-thread
use std::rc::Rc;
let a = Rc::new(42);
let b = Rc::clone(&a);  // contador = 2

// Arc — reference counting multi-thread (atómico)
use std::sync::Arc;
let datos = Arc::new(vec![1, 2, 3]);
// Arc::clone(&datos) en cada thread

// RefCell — interior mutability (single-thread)
use std::cell::RefCell;
struct Logger { logs: RefCell<Vec<String>> }
impl Logger {
    fn log(&self, msg: &str) {
        self.logs.borrow_mut().push(msg.into());
    }
}

// Mutex — interior mutability multi-thread
use std::sync::{Arc, Mutex};
let contador = Arc::new(Mutex::new(0));
{
    let mut num = contador.lock().unwrap();
    *num += 1;
}  // Lock liberado automáticamente (RAII)
```

**Cuándo usar cada uno:**

| Escenario | Solución |
|---|---|
| Un propietario, heap | `Box<T>` |
| Múltiples owners, 1 thread | `Rc<T>` |
| Múltiples owners, multi-thread | `Arc<T>` |
| Mutabilidad interior, 1 thread | `RefCell<T>` |
| Mutabilidad interior, multi-thread | `Mutex<T>` / `RwLock<T>` |
| Lectura frecuente escritura rara | `RwLock<T>` |
| Thread-safe + mutabilidad | `Arc<Mutex<T>>` |

### async/await, Tokio, Send + Sync

**async/await en Rust es único: las Futures son lazy, no hacen nada hasta que se poll (await).** Esto permite ejecutar I/O sin bloquear threads.

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]  // Macro que transforma main en async + inicia runtime multi-thread
async fn main() {
    // spawn: lanza tarea en el thread pool (work-stealing)
    let handle = tokio::spawn(async {
        sleep(Duration::from_millis(100)).await;
        "tarea completada"
    });
    println!("{}", handle.await.unwrap());

    // join!: ejecuta múltiples tareas concurrentemente
    let (r1, r2) = tokio::join!(tarea_io(), tarea_io());
    println!("{r1}, {r2}");

    // select!: espera la primera tarea que termine
    tokio::select! {
        val = canal.recv() => println!("recibido: {val}"),
        _ = sleep(Duration::from_secs(1)) => println!("timeout"),
    }

    // timeout: límite de tiempo para una operación
    use tokio::time::timeout;
    match timeout(Duration::from_secs(5), operacion_lenta()).await {
        Ok(val) => println!("{val}"),
        Err(_) => eprintln!("timeout"),
    }
}

// Runtime single-thread (útil para WASM o embebido)
#[tokio::main(flavor = "current_thread")]
async fn main_single() {}

// Runtime manual
fn main() {
    let rt = tokio::runtime::Runtime::new().unwrap();
    rt.block_on(async { println!("Hola"); });
}
```

```rust
async fn tarea_io() -> String { sleep(Duration::from_millis(50)).await; "ok".into() }
```

|---------|-----|

**Send + Sync: la magia de concurrencia de Rust**

El borrow checker se aplica entre threads. La mayoría de tipos implementan `Send` y `Sync` automáticamente, pero algunos no:

```rust
// Send: el tipo se puede transferir entre threads de forma segura
// Sync: el tipo se puede compartir entre threads (&T es Send)

// NO son Send/Sync:
// - Rc<T>: el contador no es atómico
// - RefCell<T>: el contador de borrows no es atómico
// - *const T / *mut T: raw pointers no tienen garantías

// SÍ son Send + Sync:
// - Arc<T>: contador atómico
// - Mutex<T>, RwLock<T>: sincronización nativa
// - mpsc::Sender<T>: Send (pero Receiver no es Sync)
```

| Tipo | Send | Sync |
|------|------|------|
| `i32`, `bool`, `String` | ✅ | ✅ |
| `Rc<T>` | ❌ | ❌ |
| `Arc<T>` | ✅ (si T: Send+Sync) | ✅ |
| `RefCell<T>` | ✅ | ❌ |
| `Mutex<T>` | ✅ (si T: Send) | ✅ |
| `mpsc::Sender<T>` | ✅ | ❌ |
| `*const T` | ❌ | ❌ |
| `Pin<Box<T>>` | ✅ (si T: Send) | ✅ |

**Pin:** garantiza que un valor no se mueve en memoria. Las futures de Rust a menudo contienen auto-referencias, y `Pin` asegura que sean seguras. Normalmente no lo tocas directamente — async/await lo maneja internamente.

Fuente: [Tokio docs](https://tokio.rs/tokio/tutorial), [Async Book](https://rust-lang.github.io/async-book/)

| **Factory** | `From`/`TryFrom`/`FromStr` |
| **RAII** | `Drop` trait (nativo) |
| **Newtype** | Tuple struct `struct Email(String)` |
| **State** | `enum` + `match` exhaustivo |
| **Adapter** | `From`/`Into` |
| **Iterator** | `IntoIterator` / `Iterator` |

struct ServidorBuilder { host: String, port: u16, tls: bool }
impl ServidorBuilder {
    fn new(host: &str) -> Self { Self { host: host.into(), port: 8080, tls: false } }
    fn port(mut self, p: u16) -> Self { self.port = p; self }
    fn tls(mut self, e: bool) -> Self { self.tls = e; self }
    fn build(self) -> Servidor { Servidor { host: self.host, port: self.port, tls: self.tls } }
}

// RAII — Drop se ejecuta al salir de ámbito

enum Estado { Pendiente, EnProceso, Completado }
fn transicion(actual: &Estado, nuevo: Estado) -> Result<(), String> {
    match (actual, &nuevo) {
        (Pendiente, EnProceso) | (EnProceso, Completado) | (Pendiente, Completado) => { Ok(()) }
        (Completado, _) => Err("Completado no cambia".into()),
        _ => Err("Transición inválida".into()),

## Polimorfismo

Rust tiene tres formas, cada una con sus compensaciones.

### 1. Genéricos (monomorfización)

```rust
fn sonido<T: Sonido>(cosa: T) { println!("{}", cosa.hacer_sonido()); }
// Compilador genera N copias (1 por tipo concreto)
```

### 2. Trait objects (`dyn Trait`)

```rust
let cosas: Vec<Box<dyn Sonido>> = vec![Box::new(Perro), Box::new(Gato)];
// Indirección vtable, colección heterogénea
```

### 3. Enum dispatch

```rust
enum Animal { Perro(Perro), Gato(Gato) }
impl Animal {
    fn sonido(&self) -> String {
        match self { Animal::Perro(p) => p.hacer_sonido(), Animal::Gato(g) => g.hacer_sonido() }
    }
}
// Cero overhead, exhaustividad, pero conjunto cerrado de tipos
```

| | Genéricos | `dyn Trait` | Enum dispatch |
|---|---|---|---|
| Overhead | Cero | 1 indirección vtable | Cero |
| Binario | N copias | 1 copia | 1 copia |
| Colección heterogénea | No | Sí | No (enum fijo) |
| Extensible externamente | Sí | Sí | No |

**¿Cuál usar?** Enum dispatch para conjuntos cerrados; genéricos para máximo rendimiento; `dyn Trait` para colecciones heterogéneas.

```rust
use axum::extract::ws::{WebSocket, WebSocketUpgrade, Message};

async fn ws_handler(ws: WebSocketUpgrade) -> impl IntoResponse {
    ws.on_upgrade(move |socket| manejar(socket))
}

async fn manejar(mut socket: WebSocket) {
    while let Some(Ok(msg)) = socket.recv().await {
        match msg {
            Message::Text(t) => { socket.send(Message::Text(format!("Echo: {t}"))).await.unwrap(); }
            Message::Close(_) => break,
            _ => {}
        }
    }
}

// Broadcast con tokio::sync::broadcast
async fn ws_broadcast(ws: WebSocketUpgrade, tx: Arc<broadcast::Sender<String>>) -> impl IntoResponse {
    ws.on_upgrade(move |socket| async {
        let mut rx = tx.subscribe();
        loop {
            tokio::select! {
                msg = socket.recv() => { if let Some(Ok(Message::Text(t))) = msg { tx.send(t).ok(); } else { break; } }
                msg = rx.recv() => { if let Ok(t) = msg { socket.send(Message::Text(t)).await.unwrap(); } }
            }
        }
    })
}
```

    command: Commands,
}

#[derive(Subcommand)]

    Add { service: String, username: String, password: String },
    Get { service: String },

        serde_json::from_str(&std::fs::read_to_string("vault.json")?)?
    } else { Vault::default() };

        Commands::Add { service, username, password } => {
            vault.entries.insert(service.clone(), Entry { service, username, password });
            std::fs::write("vault.json", serde_json::to_string_pretty(&vault)?)?;

            None => println!("❌ No encontrado"),
        },
        Commands::List => { for (s, _) in &vault.entries { println!("  • {s}"); } }
    }
    Ok(())
}

### Web scraper asíncrono (nivel 60)

```rust
use reqwest::Client;
use scraper::{Html, Selector};
use tokio::sync::Semaphore;
use std::sync::Arc;

#[derive(Debug)]
struct Article { title: String, url: String, source: String }

async fn scrape(url: &str, client: &Client, sem: &Semaphore) -> Vec<Article> {
    let _permit = sem.acquire().await.unwrap();
    let resp = client.get(url).send().await.ok()?;
    let doc = Html::parse_document(&resp.text().await.ok()?);
    let sel = Selector::parse("a.title, a.storylink, h2 a").unwrap();
    Some(doc.select(&sel).filter_map(|el| {
        let title = el.text().collect::<String>().trim().to_string();
        let href = el.value().attr("href")?;
        let full = if href.starts_with("http") { href.into() } else { format!("{}{}", url.trim_end_matches('/'), href) };
        if title.is_empty() { None } else { Some(Article { title, url: full, source: url.into() }) }
    }).collect())
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::builder().user_agent("Mozilla/5.0").timeout(std::time::Duration::from_secs(10)).build()?;
    let sem = Arc::new(Semaphore::new(5));
    let urls = vec!["https://news.ycombinator.com", "https://blog.rust-lang.org/"];

    let mut handles = vec![];
    for url in urls {
        let (c, s) = (client.clone(), Arc::clone(&sem));
        handles.push(tokio::spawn(async move { scrape(url, &c, &s).await }));
    }
    for h in handles { for a in h.await.unwrap_or_default() { println!("{} - {}", a.source, a.title); } }
    Ok(())
}
```

## Hacks de productividad

**1. `dbg!` — depuración instantánea**
```rust
let r = dbg!(x * 2);  // [src/main.rs:1] x * 2 = 10
// Se puede insertar en cualquier expresión
```

**2. Patrones borrow checker**
```rust
// Iterar con índices para modificar
for i in 0..items.len() { if items[i] % 2 == 0 { items.push(items[i] * 2); } }

// Separar colección
let (even, odd): (Vec<_>, Vec<_>) = items.iter().partition(|&&x| x % 2 == 0);
```

**3. Newtype para type safety**
```rust
struct UserId(u64);
struct PedidoId(u64);
fn buscar_usuario(id: UserId) {}
// buscar_usuario(PedidoId(42));  // Error de tipos
```

**4. `#[derive(Debug)]`** — imprescindible en todo struct/enum.

**5. Clippy pedante:** `cargo clippy -- -W clippy::pedantic -W clippy::nursery`

**6. `cargo expand`** — expande macros procedurales: `cargo install cargo-expand && cargo expand`

**7. `cargo-watch`** — auto-rebuild: `cargo watch -x check -x test`

**8. `cargo-insta`** — snapshot testing.

**9. `include_str!` / `include_bytes!`** — embebe archivos en compilación:
```rust
const SQL: &str = include_str!("../migrations/001.sql");
const ICON: &[u8] = include_bytes!("../static/favicon.ico");
```

**10. Comandos del día a día:**
```bash
cargo check              # Verifica errores (rápido)
cargo clippy --fix       # Auto-fix de lints
cargo test -- --nocapture  # Tests con output
cargo tree               # Árbol de dependencias
cargo outdated           # Deps desactualizadas
cargo upgrade            # Actualiza
cargo audit              # Seguridad (cargo install cargo-audit)
cargo udeps              # Deps no usadas (cargo install cargo-udeps)
```

**11. `todo!()` y `unreachable!()`:**
```rust
fn pendiente() { todo!("implementar") }
fn dispatch() -> &'static str { match t { A => "a", B => "b", _ => unreachable!() } }
```

**12. Config global `~/.cargo/config.toml`:**
```toml
[alias]
check-all = "check --workspace"
test-all = "test --workspace"
[registries.crates-io]
protocol = "sparse"
```
