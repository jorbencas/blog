# Guía de Java: De 0 a 100
## ¿Qué es Java?

Java es un lenguaje de programación orientado a objetos, de tipado estático y fuerte, creado por **James Gosling** en **Sun Microsystems** y lanzado en **1995**. Su filosofía central es **"Write Once, Run Anywhere" (WORA)**: el código se compila a bytecode que se ejecuta en la Java Virtual Machine (JVM), lo que permite que un mismo programa corra en Windows, Linux, macOS y cualquier plataforma que tenga una JVM.

**Historia breve:**
- **1991**: James Gosling inicia el proyecto "Oak" en Sun Microsystems (inspirado en C++ pero más simple)
- **1995**: Lanzamiento oficial de Java 1.0 con el lema WORA
- **2006**: Sun libera Java como open source bajo licencia GPL — nace OpenJDK
- **2009**: Oracle adquiere Sun Microsystems por 7.400 millones de dólares
- **2014**: Java 8 — el cambio más grande: lambdas, Streams API, Optional, nueva API de fecha
- **2017**: Java 9 — módulos (JPMS / Project Jigsaw), JShell
- **2018+**: Ciclo de release cada 6 meses (Java 10, 11 LTS, 12, 13, 14, 15, 16, 17 LTS, 18, 19, 20, 21 LTS...)

**¿Dónde se usa?**
- **Empresarial / Backend**: Spring Boot, Jakarta EE — bancos, seguros, gobierno, comercio electrónico
- **Android**: El desarrollo nativo de Android usa Java (y Kotlin, que corre en la JVM). Más de 2500 millones de dispositivos activos
- **Big Data**: Apache Hadoop, Apache Spark, Apache Kafka, Elasticsearch, Apache Flink — todos escritos en Java
- **DevOps / Infraestructura**: Jenkins, Gradle, Maven, Tomcat, WildFly, Nexus, SonarQube
- **IoT / Embebido**: Java ME (Micro Edition), Raspberry Pi con Java
- **Juegos**: Minecraft (el videojuego más vendido de la historia) está escrito en Java

**¿Quién lo usa?** Google (Android, backend), Netflix (microservicios en JVM, Spring Cloud), Amazon (AWS SDK, backend), LinkedIn (backend original en Java), Twitter (migró partes a JVM), Spotify (backend con Java/Kotlin), Uber (sistema de tarifas en Java), NASA (instrumentos de control en Marte).

Fuente: [Oracle — History of Java](https://www.oracle.com/java/), [OpenJDK — About](https://openjdk.org/), [Dev.java — What is Java?](https://dev.java/)

## ¿Cómo empezar? Instalación en todos los entornos

### SDKMAN (recomendado para Linux/macOS/WSL)

SDKMAN es el gestor de versiones de JDK más usado. Instala, cambia y gestiona múltiples JDKs al instante, similar a pyenv o nvm.

```bash
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

sdk list java

sdk install java 21.0.2-temurin
sdk install java 17.0.10-temurin
sdk default java 21.0.2-temurin

java --version
javac --version
```

### Windows
1. Descarga el instalador **Eclipse Temurin JDK 21 LTS (MSI)** desde [adoptium.net](https://adoptium.net/)
2. Ejecuta el MSI y **marca "Set JAVA_HOME"** durante la instalación — esto es crítico
3. Verifica: abre `cmd` o PowerShell y ejecuta `java --version`
4. Alternativa vía **winget**: `winget install EclipseAdoptium.Temurin.21.JDK`
5. Alternativa vía **chocolatey**: `choco install openjdk21`

### macOS
- **Homebrew** (recomendado):
  ```bash
  brew install openjdk@21

  ```
- **Xcode Command Line Tools**: `xcode-select --install` (necesario para algunas herramientas)
- Verifica: `java --version`

```java
// Hola.java
public class Hola {
    public static void main(String[] args) {
        System.out.println("Hola mundo");
    }
}
```

```java
jshell> lista.stream().map(x -> x * x).forEach(System.out::println)
jshell> record Punto(int x, int y) {}
jshell> new Punto(3, 4)
jshell> /exit
```

Para salir: `/exit` o Ctrl+D.

## Paradigmas de programación en Java

Java es un lenguaje multiparadigma. Aunque nació como lenguaje orientado a objetos, soporta varios estilos de programación.

### Imperativo (statement-oriented)

El paradigma base: instrucciones secuenciales que modifican el estado del programa. Cada sentencia termina en `;` y se ejecuta en orden una tras otra.

```java
int suma = 0;
for (int i = 1; i <= 10; i++) {
    suma += i;
}
System.out.println(suma);
```

Es el estilo más intuitivo para quienes empiezan. El programador dicta paso a paso cómo se hace cada operación. Es el paradigma dominante en lenguajes como C, Pascal y el Java más básico.

### POO (puro — casi todo es objeto)

Java fue diseñado desde el inicio como lenguaje orientado a objetos. Salvo los tipos primitivos (`int`, `boolean`, `double`, etc.), todo es un objeto. El código se organiza en clases que encapsulan datos (atributos) y comportamiento (métodos).

```java
public class Coche {
    private String modelo;

    public Coche(String modelo) {
        this.modelo = modelo;
    }

    public void arrancar() {
        System.out.println(modelo + " arrancó");
    }
}
```

**Características clave:**
- **Encapsulación**: ocultar el estado interno mediante modificadores de acceso (`private`)
- **Herencia simple**: una clase solo puede extender una superclase (`extends`)
- **Polimorfismo**: el mismo mensaje produce comportamiento distinto según el objeto receptor
- **Composición**: objetos que contienen otros objetos (favorecida sobre herencia)

### Funcional parcial (Java 8+)

Java no es un lenguaje funcional puro, pero desde Java 8 incorpora elementos del paradigma funcional:

- **Lambdas**: funciones anónimas como ciudadanos de primera clase — `(x) -> x * 2`
- **Streams API**: procesamiento declarativo de colecciones (filter, map, reduce)
- **Functional interfaces**: interfaces con un único método abstracto, anotadas con `@FunctionalInterface`
- **Method references**: acceso directo a métodos como si fueran funciones — `System.out::println`
- **Inmutabilidad fomentada**: Records, `List.of()`, `Stream.toList()`

```java
list.forEach(x -> System.out.println(x));          // Lambda
list.forEach(System.out::println);                 // Method reference

var resultado = personas.stream()
    .filter(p -> p.edad() >= 18)
    .map(Persona::nombre)
    .sorted()
    .toList();
```

Las interfaces funcionales principales están en `java.util.function`:
- `Function<T,R>` — transforma T en R
- `Predicate<T>` — prueba una condición (devuelve boolean)
- `Consumer<T>` — consume un valor sin devolver resultado
- `Supplier<T>` — provee un valor sin tomar argumentos
- `UnaryOperator<T>` — Function donde T y R son el mismo tipo
- `BinaryOperator<T>` — combina dos T en un T

### Procedimental histórico

Antes de que se asentara el paradigma OOP, el código Java se escribía a menudo de forma procedimental: métodos `static` en clases utilitarias, sin instanciar objetos. Hoy solo se ve en código legacy, métodos `main()` y clases de utilidades (Math, Collections).

```java
// Estilo procedimental (legacy)
public class UtilMath {
    public static int sumar(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(sumar(3, 4));
    }
}
```

**Resumen de paradigmas:**

| Paradigma | Soportado desde | Uso principal |
|-----------|-----------------|---------------|
| Imperativo | Java 1.0 | Bloques básicos, bucles, condicionales |
| POO | Java 1.0 | Modelado de dominio, arquitectura |
| Funcional | Java 8 | Procesamiento de datos, pipelines |
| Procedimental | Java 1.0 (histórico) | Legacy, utilidades estáticas |

Fuente: [Java Language Specification](https://docs.oracle.com/javase/specs/), [Oracle — Lambda Expressions](https://docs.oracle.com/javase/tutorial/java/javaOO/lambdaexpressions.html)

## Tipos de datos y variables

### Primitivos vs Wrappers

Cada tipo primitivo tiene su correspondiente wrapper (clase envolvente) en el heap:

| Primitivo | Tamaño | Wrapper | Rango | Default | Cache |
|-----------|--------|---------|-------|---------|-------|
| `byte` | 8 bits | `Byte` | -128 a 127 | 0 | -128 a 127 |
| `short` | 16 bits | `Short` | -32.768 a 32.767 | 0 | -128 a 127 |
| `int` | 32 bits | `Integer` | -2³¹ a 2³¹-1 | 0 | -128 a 127 |
| `long` | 64 bits | `Long` | -2⁶³ a 2⁶³-1 | 0L | -128 a 127 |
| `float` | 32 bits | `Float` | ±3.4E-38 | 0.0f | No |
| `double` | 64 bits | `Double` | ±1.7E-308 | 0.0d | No |
| `boolean` | ~1 bit | `Boolean` | true/false | false | true/false |
| `char` | 16 bits | `Character` | 0 a 65.535 | '\u0000' | 0 a 127 |

```java
int primitivo = 42;    // Stack
Integer wrapper = 42;  // Heap + autoboxing
int vuelta = wrapper;  // Unboxing
```

**Autoboxing/unboxing (Java 5+):** conversión automática entre primitivo y wrapper. El compilador inserta llamadas a `valueOf()` y `xxxValue()` automáticamente.

```java
Integer a = 42;      // autoboxing: Integer.valueOf(42)
int b = a;           // unboxing: a.intValue()

// Ojo: en bucles grandes es caro
Integer suma = 0;
for (int i = 0; i < 1_000_000; i++) {
    suma += i;  // Crea 1M de objetos Integer!
}
```

**Integer caching:** `Integer.valueOf()` cachea valores entre -128 y 127. `Integer.valueOf(127) == Integer.valueOf(127)` da `true`, pero con 128 da `false`. Siempre usa `.equals()` para comparar wrappers.

### String

`String` es un objeto **inmutable**: cualquier operación que parezca modificarlo (concat, replace, substring) crea una nueva cadena.

```java
String literal = "hola";            // String Pool
String objeto = new String("hola"); // Heap (evitar a menos que sea necesario)
String internada = literal.intern(); // Fuerza entrada en pool

String concat = "a" + "b";  // El compilador optimiza literales
```

**String Pool:** las cadenas literales se almacenan en un pool dentro del heap. Si dos variables usan el mismo literal, apuntan al mismo objeto.

```java
String a = "hello";
String b = "hello";
System.out.println(a == b);  // true (misma referencia en pool)

String c = new String("hello");
System.out.println(a == c);  // false (objeto distinto en heap)
```

**StringBuilder / StringBuffer:** para concatenaciones múltiples en bucles o construcción de cadenas grandes.

```java
// StringBuilder — no sincronizado, más rápido (monohilo)
var sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append("linea ").append(i).append("\n");
}
String resultado = sb.toString();

// StringBuffer — sincronizado (thread-safe, más lento)
var sbf = new StringBuffer();
```

Regla general: usa `StringBuilder` en entorno monohilo y `StringBuffer` si varios hilos acceden concurrentemente.

### Arrays

Los arrays en Java son objetos. Son **covariantes**: `String[]` es subtipo de `Object[]`.

```java
int[] nums = {1, 2, 3};
String[] nombres = new String[5];
int[][] matriz = new int[3][4];

// Covarianza — permite esto en compilación
Object[] objs = new String[3];
objs[0] = "hola";   // OK
objs[1] = 42;       // ArrayStoreException en runtime!
```

`ArrayStoreException` es la consecuencia de la covarianza: la JVM verifica en runtime que el tipo del valor insertado sea compatible con el tipo real del array.

Los arrays tienen longitud fija. Para colecciones dinámicas usa `ArrayList`.

### var (inferencia de tipo local, JDK 10+)

`var` infiere el tipo de la variable a partir del inicializador en compilación. No es tipado dinámico.

```java
var lista = new ArrayList<String>();    // ArrayList<String>
var mapa = new HashMap<String, Integer>();
var resultado = calcularAlgo();

// ❌ No compila:
// var x;                  // necesita inicializador
// var y = null;           // tipo ambiguo
// var z = (a, b) -> a+b;  // lambda sin tipo explícito
```

### Records (JDK 16+)

Clases inmutables generadas automáticamente por el compilador. Proporcionan constructor, getters, `equals()`, `hashCode()`, `toString()` sin boilerplate.

```java
public record Persona(String nombre, int edad) {
    // Compact constructor — validación
    public Persona {
        if (edad < 0)
            throw new IllegalArgumentException("Edad negativa");
    }

    // Métodos adicionales
    public String saludo() {
        return "Hola, soy " + nombre;
    }
}
```

Los records son `final`, todos sus campos son `private final`, no pueden extender otras clases ni ser extendidos. Ideales para DTOs, value objects, claves en mapas, respuestas API.

### Enums (clases especiales)

En Java, `enum` es una clase completa. Pueden tener campos, métodos, constructores, implementar interfaces.

```java
public enum Dia {
    LUNES(true), MARTES(true), MIERCOLES(true),
    JUEVES(true), VIERNES(true), SABADO(false), DOMINGO(false);

    private final boolean laborable;

    Dia(boolean laborable) {
        this.laborable = laborable;
    }

    public boolean esLaborable() { return laborable; }
}

// Uso
Dia hoy = Dia.LUNES;
System.out.println(hoy.esLaborable());  // true
```

Los enums tienen métodos útiles: `values()`, `valueOf()`, `ordinal()`, `name()`. Son inherentemente serializables y resistentes a reflection.

### Optional (Java 8+)

Contenedor que puede o no contener un valor. Alternativa declarativa a `null`.

```java
Optional<String> opt = Optional.ofNullable(obtenerNombre());
opt.map(String::toUpperCase)
   .filter(s -> s.length() > 3)
   .orElse("defecto");
```

Optional no es un reemplazo universal de null. No uses Optional para: campos de clase, parámetros de métodos, colecciones, o serialización.

### Memoria: Stack vs Heap

```
Stack (por hilo ~1MB)               Heap (compartido)
┌─────────────────────┐             ┌─────────────────────────┐
│ Variables locales   │             │ Objetos, arrays         │
│ Referencias a       │────ref────▶│ String Pool             │
│ objetos del heap    │             │ Integer Cache (-128~127)│
│ Parámetros          │             │ Generational GC         │
│ Se libera al salir  │             │ Gestionado por GC       │
│ del método          │             │ Configurable (-Xms/-Xmx)│
└─────────────────────┘             └─────────────────────────┘
```

```java
public void ejemplo() {
    int x = 5;           // x → stack (valor directo)
    String s = "hola";   // s (ref) → stack; "hola" → heap (String Pool)
    Persona p = new Persona("Ana", 30);  // p (ref) → stack; Persona → heap
}
```

### Garbage Collection

La JVM gestiona la memoria automáticamente. El heap se organiza en generaciones:

```
Young Generation (Eden + S0 + S1) → Old Generation → Metaspace
```

**Generational GC:** los objetos nuevos se asignan en Eden (Young). Los que sobreviven varias colecciones se promocionan a Old (Tenured). La mayoría de los objetos muere joven (weak generational hypothesis).

**Recolectores principales:**

| Recolector | JDK | Descripción | Ideal para |
|-----------|-----|-------------|------------|
| **G1 GC** | Default JDK 9+ | Divide heap en regiones (~1-32 MB), prioriza las más sucias. Pausas predecibles configurables con `-XX:MaxGCPauseMillis=200` | Uso general |
| **ZGC** | JDK 15+ (prod) | Pausas < 1ms, heaps hasta 16 TB. Coloreado de punteros, reubicación concurrente | Latencia ultrabaja |
| **Shenandoah** | JDK 21+ (stable) | Compactación concurrente, pausas ultrabajas independientes del tamaño del heap | Apps sensibles a latencia |
| **Serial GC** | Siempre | Un solo hilo para todo el GC. Pausas largas pero mínimo overhead | Apps pequeñas, monohilo |
| **Parallel GC** | JDK 8 default | Múltiples hilos para Young y Old GC | Throughput máximo |

```bash
java -XX:+UseZGC -jar app.jar
java -XX:+UseShenandoahGC -jar app.jar
java -XX:+UseG1GC -XX:MaxGCPauseMillis=100 -jar app.jar
```

**¿Fugas de memoria en Java?** Sí: listeners no desregistrados, ClassLoader leaks (redeploys en Tomcat), `String.intern()` excesivo, conexiones no cerradas, referencias circulares con `finalize()`.

Fuente: [Oracle — Primitive Types](https://docs.oracle.com/javase/tutorial/java/nutsandbolts/datatypes.html), [Oracle — Garbage Collection Tuning](https://docs.oracle.com/en/java/javase/21/gctuning/), [Baeldung — GC Guide](https://www.baeldung.com/jvm-garbage-collectors)

## Control de flujo y modularidad

### Condicionales: if / else if / else

```java
if (condicion) {
    // se ejecuta si condicion es true
} else if (otraCondicion) {
    // se ejecuta si la primera es false y esta es true
} else {
    // se ejecuta si todas son false
}
```

Los condicionales aceptan cualquier expresión booleana. Java no tiene truthiness automático — la condición debe ser explícitamente `boolean`.

### Switch

**Switch tradicional (statement, JDK 1+):**

```java
switch (dia) {
    case "LUNES":
    case "MARTES":
        System.out.println("Entre semana");
        break;
    case "SABADO":
    case "DOMINGO":
        System.out.println("Fin de semana");
        break;
    default:
        System.out.println("Inválido");
}
```

Cuidado con el **fall-through**: si olvidas `break`, la ejecución continúa al siguiente caso.

**Switch expression (JDK 14+):**

```java
String tipo = switch (dia) {
    case "LUNES", "MARTES", "MIERCOLES", "JUEVES", "VIERNES" -> "laborable";
    case "SABADO", "DOMINGO" -> "finde";
    case null -> "nulo";
    default -> "invalido";
};
```

Las switch expressions usan `->` en lugar de `:` y no tienen fall-through. Pueden devolver un valor con `yield` si se usan bloques:

```java
String tipo = switch (dia) {
    case "LUNES" -> { yield "laborable"; }
    default -> "otro";
};
```

**Switch pattern matching (JDK 17+ preview, JDK 21+ stable):**

```java
static String formatear(Object obj) {
    return switch (obj) {
        case Integer i -> "Entero: " + i;
        case String s when s.length() > 10 -> "String largo";
        case String s -> "String: " + s;
        case null -> "nulo";
        default -> "desconocido";
    };
}
```

Los patrones pueden incluir guardas (`when`) y se evalúan en orden. El compilador verifica exhaustividad.

### Bucles

```java
// for clásico
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

// enhanced for (for-each, JDK 5+)
for (String s : lista) {
    System.out.println(s);
}

// while
while (condicion) {
    // se ejecuta mientras condicion sea true
}

// do-while (se ejecuta al menos una vez)
do {
    // se ejecuta al menos una vez
} while (condicion);

// forEach con Stream
lista.forEach(s -> System.out.println(s));
lista.forEach(System.out::println);

// forEach con Map
mapa.forEach((k, v) -> System.out.println(k + " -> " + v));
```

### break / continue con labels

Java permite etiquetar bloques para controlar la salida de bucles anidados:

```java
outer:
for (int i = 0; i < 5; i++) {
    for (int j = 0; j < 5; j++) {
        if (i == 2) continue outer;  // salta a la siguiente iteración de outer
        if (i == 4) break outer;     // sale completamente de outer
        System.out.println(i + "," + j);
    }
}
```

Es la alternativa de Java a `goto` — controlar estructuras sin perder legibilidad.

## Conceptos clave explicados a fondo

### JVM, JRE, JDK, bytecode, compilación JIT, garbage collection

El ecosistema Java tiene tres capas:

```
.java --(javac)--> .class (bytecode) --(JVM)--> código máquina
```

- **JDK (Java Development Kit)**: kit completo para desarrollar. Incluye compilador (`javac`), depurador (`jdb`), herramientas (JConsole, VisualVM, jlink, jpackage, javadoc) y la JRE
- **JRE (Java Runtime Environment)**: solo para ejecutar. Incluye la JVM y las librerías estándar. Desde Java 11 no existe como instalación independiente — usas `jlink` para crear runtimes mínimos
- **JVM (Java Virtual Machine)**: ejecuta bytecode. Especificación abstracta con implementaciones: HotSpot (Oracle/OpenJDK), OpenJ9 (Eclipse), GraalVM (polyglot)

**El viaje del código:**
```java
int suma = 1 + 2;
// javac lo compila a bytecode: iconst_1, iconst_2, iadd, istore_1
// La JVM interpreta bytecode. Las partes "calientes" (hot spots)
// se compilan a código nativo mediante JIT (Just-In-Time compilation)
```

**Compilación JIT:** Cuando la JVM detecta que un método se ejecuta muchas veces (hot spot), lo compila a código máquina nativo. La próxima llamada ejecuta código nativo directamente. Esto es lo que hace que Java sea rápido a largo plazo aunque la primera ejecución sea más lenta. Los perfiles de ejecución permiten optimizaciones como inline de métodos virtuales y eliminación de bounds checking.

**AOT con GraalVM:** Permite compilar Java a nativo con `native-image`. Arranque instantáneo (~0.1s vs ~3s), menos memoria (~10 MB vs ~100 MB). Ideal para serverless. Limitaciones: menos reflection, no todos los frameworks son compatibles (Spring Boot 3 sí).

**Garbage Collection:**

| Recolector | JDK | Descripción | ¿Para qué? |
|---|---|---|---|
| **G1 GC** | Default JDK 9+ | Divide heap en regiones, prioriza las más sucias. Pausas predecibles | Uso general |
| **ZGC** | JDK 15+ prod | Pausas < 1ms, heaps hasta 16 TB | Latencia ultrabaja |
| **Shenandoah** | JDK 21+ stable | Compactación concurrente, pausas ultrabajas | Apps sensibles a latencia |
| **Serial GC** | Siempre | Un hilo para GC | Apps pequeñas |
| **Parallel GC** | JDK 8 default | Múltiples hilos | Throughput máximo |

```bash
java -XX:+UseZGC -jar app.jar
java -XX:+UseShenandoahGC -jar app.jar
```

**¿Fuga de memoria?** Sí: listeners no desregistrados, ClassLoader leaks al redeployar, String.intern() excesivo, conexiones no cerradas.

Herramientas: VisualVM, JProfiler, Eclipse MAT, JFR (built-in), Async Profiler.

Fuente: [Oracle — JVM docs](https://docs.oracle.com/en/java/javase/), [Baeldung — GC Guide](https://www.baeldung.com/jvm-garbage-collectors)

### Variables, tipos primitivos vs objetos, autoboxing, stack vs heap

**Tipos primitivos:**

| Tipo | Tamaño | Rango | Default |
|---|---|---|---|
| `byte` | 8 bits | -128 a 127 | 0 |
| `short` | 16 bits | -32.768 a 32.767 | 0 |
| `int` | 32 bits | -2³¹ a 2³¹-1 | 0 |
| `long` | 64 bits | -2⁶³ a 2⁶³-1 | 0L |
| `float` | 32 bits | ±3.4E-38 | 0.0f |
| `double` | 64 bits | ±1.7E-308 | 0.0 |
| `boolean` | ~1 bit | true/false | false |
| `char` | 16 bits | 0-65.535 | '\u0000' |

**Primitivos vs Wrappers:**
```java
int x = 5;        // Primitivo — stack
Integer y = 5;    // Objeto — heap (autoboxing)
```

| Primitivo | Wrapper |
|---|---|
| `int` | `Integer` |
| `long` | `Long` |
| `double` | `Double` |
| `boolean` | `Boolean` |
| `char` | `Character` |

**Autoboxing y unboxing (Java 5+):**
```java
Integer a = 42;   // autoboxing: int -> Integer
int b = a;        // unboxing: Integer -> int

// Cuidado: autoboxing en bucles es costoso
Integer suma = 0;
for (int i = 0; i < 1_000_000; i++) {
    suma += i;  // Crea 1M de objetos Integer!
}
```

**Integer caching:** Java cachea `Integer` de -128 a 127. `a == b` da true para 127 pero false para 128. Siempre usa `.equals()`.

**String Pool:** literales se cachean. `"hola" == "hola"` -> true. `new String("hola")` crea nuevo objeto.

**Stack vs Heap:**
- **Stack**: por hilo. Variables locales, referencias. ~1MB. Se libera al salir del método
- **Heap**: compartido. Objetos y arrays. Gestionado por GC. Configurable (`-Xms`, `-Xmx`)

```java
public void ejemplo() {
    int x = 5;           // x -> stack
    String s = "hola";   // s (ref) -> stack; "hola" -> heap (String Pool)
}
```

**Clase y encapsulación:**

### Java Records (JDK 16+)

Los Records son clases inmutables para datos. El compilador genera constructor, getters, `equals()`, `hashCode()`, `toString()`.

```java
// Antes — mucho boilerplate
public final class Punto {
    private final int x;
    private final int y;
    public Punto(int x, int y) { this.x = x; this.y = y; }
    public int getX() { return x; }
    public int getY() { return y; }
}

// Con Record (JDK 16+)
public record Punto(int x, int y) {
    // Compact constructor — validaciones
    public Punto {
        if (x < 0 || y < 0)
            throw new IllegalArgumentException("Coordenadas no negativas");
    }

    public double distanciaAlOrigen() {
        return Math.sqrt(x * x + y * y);
    }
}

// Uso
var p = new Punto(3, 4);
p.x();         // 3 (getter, no getX())
p.toString();  // "Punto[x=3, y=4]"
p.equals(new Punto(3, 4));  // true
```

**¿Cuándo usar Records?** DTOs, value objects, claves en mapas, respuestas API. No pueden extender otras clases, son inmutables.

### Genéricos, wildcards, type erasure

Los genéricos son **invariantes** y se implementan mediante **type erasure**: en runtime `List<String>` y `List<Integer>` son ambos `List`.

```java
public class Caja<T> {
    private T contenido;
    public void guardar(T contenido) { this.contenido = contenido; }
    public T obtener() { return contenido; }
}

Caja<String> caja = new Caja<>();
caja.guardar("Hola");
String valor = caja.obtener();  // Sin cast
```

**Type Erasure:** en compilación `T` se reemplaza por `Object` (o el bound). El compilador inserta casts implícitos. No puedes hacer `new T()` ni `instanceof Caja<String>`.

**Wildcards:**
```java
// ? extends T (covarianza) — solo lectura
void sumar(List<? extends Number> nums) {
    for (Number n : nums) sum += n.doubleValue();
}

// ? super T (contravarianza) — solo escritura
void addInts(List<? super Integer> lista) {
    lista.add(42);
}
```

**PECS — Producer Extends, Consumer Super:** si solo lees usa `? extends`, si solo escribes usa `? super`.

```java
String contenido = Files.readString(path);
```

### FileChannel (NIO, alta velocidad)

Para operaciones de E/S intensivas con memoria mapeada.

```java
try (var channel = FileChannel.open(path, StandardOpenOption.READ)) {
    var buffer = ByteBuffer.allocate(1024);
    int bytesRead = channel.read(buffer);
    buffer.flip();
    while (buffer.hasRemaining()) {
        System.out.print((char) buffer.get());
    }
}

// Memoria mapeada (archivos muy grandes)
try (var channel = FileChannel.open(path, StandardOpenOption.READ)) {
    var mapped = channel.map(
        FileChannel.MapMode.READ_ONLY, 0, channel.size());
    // mapped es un MappedByteBuffer
}
```

### WatchService — vigilar cambios en el sistema de archivos

Escucha eventos de creación, modificación y borrado en directorios. Ideal para hot-reload, procesamiento de archivos entrantes, sincronización.

```java
try (var watcher = FileSystems.getDefault().newWatchService()) {
    Path dir = Path.of(".");
    dir.register(watcher,
        StandardWatchEventKinds.ENTRY_CREATE,
        StandardWatchEventKinds.ENTRY_MODIFY,
        StandardWatchEventKinds.ENTRY_DELETE);

    System.out.println("Vigilando: " + dir);

    while (true) {
        WatchKey key = watcher.take();  // Bloquea hasta que hay un evento
        for (WatchEvent<?> event : key.pollEvents()) {
            WatchEvent.Kind<?> kind = event.kind();
            Path filename = (Path) event.context();
            System.out.println(filename + " -> " + kind);
        }
        key.reset();  // Importante: resetear para seguir recibiendo eventos
    }
}
```

## Algoritmos y estructuras de datos

### Ordenación

```java
import java.util.*;

var list = new ArrayList<>(List.of(3, 1, 4, 1, 5, 9));
Collections.sort(list);     // Timsort — O(n log n), estable
Collections.reverse(list);  // Invierte el orden
Collections.shuffle(list);  // Aleatoriza

int[] array = {3, 1, 4, 1, 5, 9};
Arrays.sort(array);         // Dual-Pivot Quicksort — O(n log n)

// Ordenación paralela (ForkJoinPool)
Arrays.parallelSort(array);
```

- **`Collections.sort()`**: usa **Timsort** (O(n log n), estable). Es una mezcla de Merge Sort e Insertion Sort. Detecta secuencias ya ordenadas para minimizar comparaciones. Es el algoritmo de ordenación por defecto para objetos.
- **`Arrays.sort()`** para primitivos: usa **Dual-Pivot Quicksort** (O(n log n)) de Vladimir Yaroslavskiy, Jon Bentley y Joshua Bloch. Más rápido que el Quicksort clásico.
- **`Arrays.sort()`** para objetos: también usa Timsort.
- **`Arrays.parallelSort()`**: divide el array en partes, las ordena en paralelo y las fusiona. Aprovecha múltiples núcleos.

### PriorityQueue (heap)

Cola con prioridad implementada como heap binario. Por defecto es un **min-heap** (el elemento más pequeño tiene la prioridad más alta).

```java
// Min-heap (por defecto)
var minHeap = new PriorityQueue<Integer>();
minHeap.add(5); minHeap.add(1); minHeap.add(3);
System.out.println(minHeap.poll());  // 1
System.out.println(minHeap.poll());  // 3
System.out.println(minHeap.poll());  // 5

// Max-heap
var maxHeap = new PriorityQueue<Integer>(Comparator.reverseOrder());
maxHeap.add(5); maxHeap.add(1); maxHeap.add(3);
System.out.println(maxHeap.poll());  // 5

// Con objetos
var pq = new PriorityQueue<Persona>(
    Comparator.comparing(Persona::edad));
pq.add(new Persona("Ana", 30));
pq.add(new Persona("Luis", 25));
System.out.println(pq.poll().nombre());  // "Luis" (el de menor edad)
```

**Operaciones:** `add()`/`offer()` O(log n), `poll()` O(log n), `peek()` O(1), `remove()` O(n).

### Deque / ArrayDeque

`ArrayDeque` es una cola doblemente terminada (double-ended queue). Más rápida que `LinkedList` y `Stack`.

```java
var deque = new ArrayDeque<String>();

// Como cola (FIFO)
deque.addLast("primero");
deque.addLast("segundo");
deque.addLast("tercero");
deque.pollFirst();   // "primero"

// Como pila (LIFO)
deque.addFirst("inicio");
deque.addLast("final");
deque.pollLast();    // "final"
deque.pollFirst();   // "inicio"

// Métodos disponibles
deque.addFirst(e);    // lanza excepción si capacidad excedida
deque.offerFirst(e);  // devuelve false si capacidad excedida
deque.removeFirst();  // lanza NoSuchElementException si vacío
deque.pollFirst();    // devuelve null si vacío
deque.getFirst();     // lanza excepción si vacío
deque.peekFirst();    // devuelve null si vacío
```

### Tabla de complejidad Big O

| Colección | Get/Acceso | Add/Insert | Remove | Contains/Buscar | Iteración | Memoria extra |
|-----------|-----------|------------|--------|-----------------|-----------|---------------|
| `ArrayList` | O(1) | O(1)* | O(n) | O(n) | O(n) | Baja |
| `LinkedList` | O(n) | O(1) | O(1) | O(n) | O(n) | Alta (nodos) |
| `HashMap` | O(1) | O(1) | O(1) | O(1) | O(n) | Media (buckets) |
| `TreeMap` | O(log n) | O(log n) | O(log n) | O(log n) | O(n) | Media (árbol rojo-negro) |
| `LinkedHashMap` | O(1) | O(1) | O(1) | O(1) | O(n) | Media (orden de inserción/acceso) |
| `HashSet` | — | O(1) | O(1) | O(1) | O(n) | Media |
| `TreeSet` | — | O(log n) | O(log n) | O(log n) | O(n) | Media |
| `PriorityQueue` | O(1) (peek) | O(log n) | O(n) | O(n) | O(n) | Baja |
| `ArrayDeque` | O(1) | O(1) | O(1) | O(n) | O(n) | Baja |

* `ArrayList.add()` es O(1) amortizado — O(n) cuando necesita redimensionar el array interno.

**Reglas prácticas:**
- **HashMap vs TreeMap**: HashMap para casi todo (O(1)). TreeMap solo si necesitas ordenación.
- **ArrayList vs LinkedList**: ArrayList para casi todo (localidad de referencia). LinkedList solo si insertas/eliminas al inicio frecuentemente.
- **HashSet vs TreeSet**: HashSet para casi todo. TreeSet solo si necesitas ordenado.
- **Stack vs ArrayDeque**: `ArrayDeque` reemplaza a `Stack` (más rápida, no sincronizada).
- **Vector / Hashtable**: legacy, no usar.

## Ejemplo completo de POO en Java

Sistema de biblioteca multimedia que une todos los conceptos.

```java
import java.time.LocalDateTime;
import java.util.*;
import java.util.stream.Collectors;

// ── Record y Enum ──

enum FormatoVideo { MP4, WEBM, AVI, MKV }

record Metadatos(String titulo, int duracionSegundos,
                 LocalDateTime fechaCreacion, List<String> tags) {
    public Metadatos {
        if (duracionSegundos <= 0)
            throw new IllegalArgumentException("Duración debe ser positiva");
        if (tags == null) tags = List.of();
    }

    public Metadatos(String titulo, int duracionSegundos) {
        this(titulo, duracionSegundos, LocalDateTime.now(), List.of());
    }

    public String duracionFormateada() {
        return String.format("%d:%02d",
            duracionSegundos / 60, duracionSegundos % 60);
    }

    @Override public String toString() {
        return titulo + " (" + duracionFormateada() + ")";
    }
}

// ── Clase abstracta ──

abstract class Contenido {
    protected final Metadatos metadatos;
    private int reproducciones;

    public Contenido(Metadatos metadatos) {
        this.metadatos = metadatos;
        this.reproducciones = 0;
    }

    public Metadatos getMetadatos() { return metadatos; }
    public int getReproducciones() { return reproducciones; }

    public String reproducir() {
        reproducciones++;
        return "▶️ Reproduciendo " + metadatos.titulo() + "...";
    }

    public abstract String obtenerInfo();

    @Override public String toString() {
        return "[" + getClass().getSimpleName() + "] " + metadatos;
    }
}

// ── Herencia simple ──

class Audio extends Contenido {
    private final int bitrateKbps;

    public Audio(Metadatos metadatos, int bitrateKbps) {
        super(metadatos);
        this.bitrateKbps = bitrateKbps;
    }

    @Override public String obtenerInfo() {
        return String.format("🎵 %s | %s | %dkbps | %d reps",
            metadatos.titulo(), metadatos.duracionFormateada(),
            bitrateKbps, getReproducciones());
    }
}

class Video extends Contenido {
    private final String resolucion;
    private final FormatoVideo formato;
    private boolean subtitulos;

    public Video(Metadatos metadatos, String resolucion,
                 FormatoVideo formato) {
        super(metadatos);
        this.resolucion = resolucion;
        this.formato = formato;
    }

    public void setSubtitulos(boolean v) { this.subtitulos = v; }

    @Override public String obtenerInfo() {
        return String.format("🎬 %s | %s | %s | %s",
            metadatos.titulo(), resolucion, formato,
            subtitulos ? "CC" : "Sin subtítulos");
    }
}

// ── Interface ──

interface Exportable {
    default String exportar(String formato) {
        if ("json".equals(formato))
            return "{ \"tipo\": \"" + getClass().getSimpleName() + "\" }";
        return "Exportación a " + formato + " no soportada";
    }
}

// ── Herencia + Interface ──

class Podcast extends Audio implements Exportable {
    private final int episodio;
    private final String anfitrion;

    public Podcast(Metadatos m, int bitrate, int ep, String anfitrion) {
        super(m, bitrate);
        this.episodio = ep;
        this.anfitrion = anfitrion;
    }

    @Override public String obtenerInfo() {
        return String.format("🎙️ Ep.%d: %s | con %s | %s",
            episodio, metadatos.titulo(), anfitrion,
            super.obtenerInfo());
    }
}

// ── Composición ──

class ListaReproduccion {
    private final String nombre;
    private final List<Contenido> items = new ArrayList<>();

    public ListaReproduccion(String nombre) { this.nombre = nombre; }

    public void agregar(Contenido item) { items.add(item); }

    public List<String> infoCompleta() {
        return items.stream().map(Contenido::obtenerInfo).toList();
    }

    public List<String> reproducirTodo() {
        return items.stream().map(Contenido::reproducir).toList();
    }

    public int size() { return items.size(); }

    @Override public String toString() {
        return "📋 " + nombre + " (" + items.size() + " items)";
    }
}

// ── Uso ──

public class Main {
    public static void main(String[] args) {
        var cancion = new Audio(
            new Metadatos("Bohemian Rhapsody", 354), 320);

        var pelicula = new Video(
            new Metadatos("Inception", 8880), "4K",
            FormatoVideo.MKV);
        pelicula.setSubtitulos(true);

        var podcast = new Podcast(
            new Metadatos("El futuro de la IA", 2700),
            128, 42, "Ana López");

        // Polimorfismo
        for (var c : List.of(cancion, pelicula, podcast))
            System.out.println(c.obtenerInfo());

        // Composición
        var lista = new ListaReproduccion("Favoritos");
        lista.agregar(cancion);
        lista.agregar(pelicula);
        lista.agregar(podcast);
        System.out.println(lista);
        lista.reproducirTodo().forEach(System.out::println);
    }
}
```

**Conceptos demostrados:**

| Concepto | Cómo aparece |
|---|---|
| Clase abstracta | `Contenido` con `abstract obtenerInfo()` |
| Herencia simple | `Audio extends Contenido`, `Video extends Contenido` |
| Interface | `Exportable` con método `default` |
| Herencia + Interface | `Podcast extends Audio implements Exportable` |
| `super()` | `super(metadatos)` llama al constructor padre |
| Encapsulación | `private int reproducciones`, getters públicos |
| Polimorfismo | `obtenerInfo()` distinto según clase concreta |
| Composición | `ListaReproduccion` contiene `List<Contenido>` |
| Record | `Metadatos` con validación en compact constructor |
| Enum | `FormatoVideo` con valores constantes |
| Streams API | `items.stream().map(...).toList()` |

## Polimorfismo en detalle

Java tiene tres formas de polimorfismo:

### 1. Subtipo (herencia)

```java
interface Sonido { String sonido(); }

class Perro implements Sonido {
    public String sonido() { return "Guau"; }
}
class Gato implements Sonido {
    public String sonido() { return "Miau"; }
}

    public String sonido() { return "Brum"; }

hacerSonido(new Gato());   // Miau

```

### 2. Paramétrico (genéricos)

```java
interface Forma<T extends Number> { double area(); }

class Circulo implements Forma<Double> {
    private final double radio;
    public Circulo(double radio) { this.radio = radio; }
    public double area() { return Math.PI * radio * radio; }
}

class Rectangulo implements Forma<Double> {
    private final double ancho, alto;
    public Rectangulo(double a, double h) { this.ancho = a; this.alto = h; }
    public double area() { return ancho * alto; }
}

void mostrarArea(Forma<?> f) {
    System.out.printf("Área: %.2f%n", f.area());
}

mostrarArea(new Circulo(5));       // 78.54
mostrarArea(new Rectangulo(3, 4)); // 12.00
```

### 3. Ad-hoc (overloading)

```java

    }
```

### Adapter

```java
class SistemaViejo {
    public List<List<Object>> query(String sql) {
        return List.of(List.of("resultado"));
    }
}

class SistemaNuevo {
    public CompletableFuture<List<Object>> execute(String q) {
        return CompletableFuture.completedFuture(List.of("resultado"));
    }
}

class DBAdapter {
    private final Object backend;

    public DBAdapter(Object backend) { this.backend = backend; }

    public List<Object> query(String sql) {
        if (backend instanceof SistemaViejo v)
            return v.query(sql).stream()
                .flatMap(Collection::stream).toList();

            return n.execute(sql).join();
        throw new IllegalArgumentException();
```

```java
    for (int x = 0; x < width; x++) {
        int rgb = img.getRGB(x, y);
        int r = (rgb >> 16) & 0xFF;
        int g = (rgb >> 8) & 0xFF;
        int b = rgb & 0xFF;
        int gray = (r + g + b) / 3;
        int nuevoRGB = (255 << 24) | (gray << 16) | (gray << 8) | gray;
        img.setRGB(x, y, nuevoRGB);
    }
}
ImageIO.write(img, "PNG", new File("gris.png"));
```

### Virtual Threads (JDK 21 LTS)

Hilos ligeros gestionados por la JVM, no por el SO. Miles de virtual threads en un carrier thread.

```java
// Antes — threads de SO (pesados)
var pool = Executors.newFixedThreadPool(200);
for (int i = 0; i < 10_000; i++) {
    pool.submit(() -> {
        Thread.sleep(1000);
        return "ok";
    });
}

// Con virtual threads — 10,000 tareas
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> {
            Thread.sleep(1000);  // No bloquea: VT se parkea
            return "ok";
        });
    }
}

// Creación directa
Thread vt = Thread.ofVirtual()
    .name("mi-vt")
    .start(() -> System.out.println("Hola desde VT"));
```

¿Dónde brillan? I/O-bound (servidores web, BD, APIs). Spring Boot 3.2+: `spring.threads.virtual.enabled=true`. Limitaciones: no para CPU-bound, `synchronized` bloquea el carrier (usa `ReentrantLock`).

### ForkJoinPool (Java 7+)

```java
class SumaArray extends RecursiveTask<Long> {
    private static final int UMBRAL = 1000;
    private final int[] array;
    private final int inicio, fin;

    SumaArray(int[] array, int inicio, int fin) {
        this.array = array;
        this.inicio = inicio;
        this.fin = fin;
    }

    @Override
    protected Long compute() {
        if (fin - inicio <= UMBRAL) {
            long suma = 0;
            for (int i = inicio; i < fin; i++) suma += array[i];
            return suma;
        }
        int medio = (inicio + fin) / 2;
        var izq = new SumaArray(array, inicio, medio);
        var der = new SumaArray(array, medio, fin);
        izq.fork();
        return der.compute() + izq.join();
    }
}

long suma = ForkJoinPool.commonPool()
    .invoke(new SumaArray(datos, 0, datos.length));
```

| Cálculo CPU | ForkJoinPool, parallelStream | ML, procesamiento |
| Tareas programadas | ScheduledExecutorService | Cron jobs |
| Escalabilidad I/O | Virtual Threads (JDK 21+) | Servidores web |

```java
import java.io.*;

import java.security.*;
import java.util.*;

public class PasswordManager {
    private static final Path KEY_PATH = Path.of("vault.key");
    private static final Path VAULT_PATH = Path.of("vault.enc");
    private final SecretKey key;

    public PasswordManager() throws Exception {
        this.key = loadOrCreateKey();
    }

    private SecretKey loadOrCreateKey() throws Exception {
        if (Files.exists(KEY_PATH))
            return new SecretKeySpec(Files.readAllBytes(KEY_PATH), "AES");
        var gen = KeyGenerator.getInstance("AES");
        gen.init(256);
        var k = gen.generateKey();
        Files.write(KEY_PATH, k.getEncoded());
        return k;
    }

    public static String generatePassword(int length) {
        var chars = "ABCDEFGHIJKLMNOPQRSTUVWXYZ" +
            "abcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*";
        var random = new SecureRandom();
        var sb = new StringBuilder(length);
        for (int i = 0; i < length; i++)
            sb.append(chars.charAt(random.nextInt(chars.length())));
        return sb.toString();
    }
}
```

**8. `@Builder` de Lombok**
```java
@Data
@Builder
public class Config {
    private String host;
    private int puerto;
    @Builder.Default private boolean ssl = true;
}

var cfg = Config.builder()
    .host("localhost")
    .puerto(8080)
    .build();
```

**9. SLF4J + Logback**
```java
// @Slf4j con Lombok
log.debug("Procesando usuario: {}", id);
log.info("Operación completada");
log.error("Error procesando pedido {}", pedidoId, exception);
```

**10. jlink para runtime mínimo**
```bash
jlink --module-path $JAVA_HOME/jmods:target/classes \
      --add-modules com.miempresa.app \
      --output mi-app --compress 2 --strip-debug
./mi-app/bin/java com.miempresa.app.Main
```
