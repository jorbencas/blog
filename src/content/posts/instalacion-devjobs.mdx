Este post es **solo la instalación** del pipeline Sendo: el sistema que graba un directo, lo comprime y lo publica en un foro de Telegram.

> ¿Buscas entender **el código, los contenedores y el flujo de archivos**? Está explicado en [**Pipeline Sendo: directo → compresión → Telegram**](/myprojects/devjobs-automation-suite). Aquí solo se instala y se verifica.

---

## 1. Qué vas a instalar

El pipeline son **tres contenedores** que se comunican mediante carpetas y nombres de archivo:

| Contenedor | Servicio | Función |
|------------|----------|---------|
| `twitchrecorder-sendo` | Grabador | Detecta el directo, obtiene la keyword y graba |
| `ffmpeg_monitor-sendo` | Compresor | Comprime y, si toca, detecta episodios |
| `telegram-uploader-sendo` | Uploader | Sube a grupos/temas de Telegram y limpia |

> El monitor no fuerza 720p por defecto: conserva la resolución del directo. Si quieres escalar, añade `RESOLUTION=720` a las variables del servicio `monitor` en `ffmpeg-yt-dlp/docker-compose.yml`.

Las rutas de datos se crean con `DEVJOBS_DATA` (por defecto `/srv/devjobs-data`):

```text
/srv/devjobs-data/
├── grabaciones/
│   ├── AAAA/MM/          # originales
│   └── test/             # cola: *_completed.mp4
├── comprimidos/          # *_compressed.mp4 listos para subir
└── partes/               # trozos temporales de vídeos > 2 GB
```

> El resto de herramientas del repositorio (pipeline de YouTube, PDFs, scrapers) se instala por separado. Esta guía no las levanta.

## 2. Requisitos

- **Linux** o **WSL2** en Windows.
- **Docker Engine + plugin `docker compose` v2**. No sirve un `docker-compose` v1 antiguo.
- **Git**, `curl` y permisos de `sudo`.
- Una **cuenta de Telegram** que pueda publicar en el foro de destino.
- Espacio en disco suficiente: una grabación de varias horas puede ocupar bastante antes de comprimirse.

En WSL, guarda los datos en el sistema de archivos de Linux (`/srv` o `$HOME`). Si usas una ruta de Windows (`/mnt/c/...`), Docker la monta por 9p y el pipeline se vuelve mucho más lento.

## 3. Instalación automática recomendada

El instalador principal es idempotente: puedes relanzarlo sin miedo.

```bash
cd ~
git clone https://github.com/TU_USUARIO/devjobs.git
cd devjobs

# No lo ejecutes con sudo: el script pide sudo cuando lo necesita.
bash servicios/instalar_ubuntu.sh
```

Sustituye `TU_USUARIO` por tu usuario o por la URL de tu fork. Si ya tienes el repositorio clonado, salta el `git clone` y ejecuta el instalador desde su raíz.

Qué hace `instalar_ubuntu.sh`:

1. Prepara los repositorios de Ubuntu (incluido `old-releases` en versiones EOL).
2. Instala o repara **Docker Engine + `docker compose` v2**.
3. Añade tu usuario al grupo del socket de Docker.
4. Localiza el repo o lo clona si no lo encuentra.
5. Crea `${DEVJOBS_DATA}/grabaciones/test`, `comprimidos`, `partes` y `.native`.
6. Comprueba los secretos del uploader.
7. Construye las tres imágenes si faltan.
8. Arranca grabador y compresor; el uploader solo si están credenciales, `grupos.json` y sesión.
9. Instala el servicio `twitch-stream-pipeline.service`.
10. Instala los aliases, activa NTP y limita los logs de Docker.

Opciones útiles:

```bash
bash servicios/instalar_ubuntu.sh --help
bash servicios/instalar_ubuntu.sh --rebuild   # fuerza recompilar las imágenes
```

### Si Docker ya está instalado y solo quieres montar el pipeline

```bash
cd ~/devjobs
bash servicios/bootstrap_instalar.sh
```

Este bootstrap comprueba Docker, clona o reutiliza el repo, sustituye la ruta antigua por la de esta máquina, crea carpetas, revisa secretos, construye las imágenes, instala systemd y añade los aliases.

Si el monitor no tiene imagen todavía, constrúyela explícitamente:

```bash
docker compose -f ffmpeg-yt-dlp/docker-compose.yml build monitor
```

### Después de la instalación automática

El instalador puede terminar sin uploader si aún no existen las credenciales. El orden recomendado es:

```bash
# 1. Credenciales y sesión del uploader
bash servicios/pipe_credenciales.sh

# 2. Revisa la configuración de canales y destinos
#    TwitchRecorder/config.json
#    downloader_telegram/config/grupos.json

# 3. Recrea los contenedores para aplicar la configuración
source ~/.bashrc
pipe_recreate
```

El uploader usa una sesión de usuario de Telegram; no necesita el token de un bot.

## 4. Credenciales de Telegram

El uploader necesita tres cosas distintas:

| Cosa | De dónde sale | Dónde se guarda |
|------|---------------|-----------------|
| `api_id` + `api_hash` | https://my.telegram.org/apps | `downloader_telegram/config/config.bin` |
| Clave de cifrado | Se genera sola | `downloader_telegram/config/secret.key` |
| Sesión de usuario | Login con teléfono + código + 2FA | `downloader_telegram/sessions/uploader.session` |

Lo normal es que cada equipo use **sus propias credenciales y su propia sesión**. No copies `config.bin`, `secret.key` ni `*.session` si vas a usar otra cuenta: son el login de una cuenta concreta. Solo tiene sentido copiarlos si migras la misma cuenta y la máquina antigua deja de usarla.

### 4.1 Crear la app en Telegram

1. Entra en **https://my.telegram.org/apps** con la cuenta que va a subir los vídeos.
2. Crea una aplicación con cualquier nombre.
3. Copia el **`api_id`** (número) y el **`api_hash`** (cadena).

### 4.2 Generar credenciales y sesión con un solo script

```bash
cd ~/devjobs
bash servicios/pipe_credenciales.sh
```

El script:

1. Construye las imágenes de Telegram si faltan.
2. Pide `API ID` y `API HASH` si no existen.
3. Cifra las credenciales en `config/config.bin` y crea `config/secret.key`.
4. Pide teléfono, código y 2FA para crear `sessions/uploader.session`.
5. Ejecuta una verificación final sin subir nada.

### 4.3 Si migras la misma cuenta desde otro equipo

Copia estos archivos desde la máquina antigua:

```bash
scp USUARIO@MAQUINA_ANTIGUA:~/devjobs/downloader_telegram/config/config.bin \
    ~/devjobs/downloader_telegram/config/

scp USUARIO@MAQUINA_ANTIGUA:~/devjobs/downloader_telegram/config/secret.key \
    ~/devjobs/downloader_telegram/config/

scp USUARIO@MAQUINA_ANTIGUA:~/devjobs/downloader_telegram/config/grupos.json \
    ~/devjobs/downloader_telegram/config/

scp USUARIO@MAQUINA_ANTIGUA:~/devjobs/downloader_telegram/sessions/uploader.session \
    ~/devjobs/downloader_telegram/sessions/
```

Después valida la sesión:

```bash
bash servicios/pipe_verificar.sh
```

Si la sesión está corrupta o caducada:

```bash
bash servicios/pipe_setup.sh --reset
```

### 4.4 Verificar sin subir nada

```bash
bash servicios/pipe_verificar.sh
```

Comprueba que `config.bin` se descifra con `secret.key`, que `grupos.json` es válido y que `uploader.session` está autorizada.

## 5. Configurar los canales del grabador

El grabador lee `TwitchRecorder/config.json`. Ejemplo con datos ficticios:

```json
{
  "channels": {
    "canal_demo": {
      "enabled": true,
      "platform": [
        {
          "platform": "web",
          "url": "https://watch.example.com/",
          "kick_channel": "canal_demo",
          "detectar": true,
          "corte": false,
          "schedule": [
            { "days": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"], "time": "21:30" }
          ]
        },
        {
          "platform": "kick",
          "detectar": false,
          "corte": false,
          "schedule": [
            { "days": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"], "time": "22:00" }
          ]
        }
      ]
    },
    "canal_youtube_demo": {
      "platform": [
        {
          "platform": "youtube",
          "detectar": false,
          "corte": false,
          "schedule": [{ "days": ["Sunday"], "time": "19:00" }]
        }
      ]
    }
  },
  "record_path": "/recordings",
  "check_every": 30,
  "max_duration": "24:00:00",
  "retry_interval": 1,
  "copy_to_test": true,
  "test_path": "/recordings/test"
}
```

Lo mínimo que debes revisar:

- `platform`: orden de prioridad de las fuentes.
- `url`: solo para `web`.
- `enabled`: `false` desactiva el canal.
- `schedule`: días y horas. Si lo dejas vacío, el scheduler puede caer en el horario legacy (`days`/`start_time`); revisa `tw_logs` si no arranca cuando esperas.
- `detectar` / `corte`: si el monitor debe buscar episodios y recortar.
- `copy_to_test`: debe ser `true` para que el monitor reciba `*_completed.mp4`.

Los nombres de los días van en inglés (`Monday`, `Tuesday`, ...). La hora se interpreta con la zona horaria del contenedor (`TZ` en el compose del grabador).

Tras editar `config.json`:

```bash
pipe_recreate
```

El grabador recarga `config.json` en cada vuelta para incorporar canales nuevos, pero los cambios en un canal ya cargado pueden no aplicarse; recrear el contenedor evita dudas.

## 6. Configurar los destinos de Telegram

El uploader lee `downloader_telegram/config/grupos.json`. Ejemplo ficticio:

```json
{
  "default": -1000000000000,
  "grupos": [
    { "nombre": "serie_demo", "id": -1000000000001 }
  ],
  "foros": [
    {
      "id": -1000000000002,
      "nombre": "foro_demo",
      "general": 101,
      "temas": [
        { "nombre": "serie_a", "id": 102 },
        { "nombre": "serie_b", "id": 103 },
        { "nombre": "peliculas", "id": 104 }
      ]
    }
  ]
}
```

- `default`: grupo de respaldo si ninguna keyword coincide.
- `grupos`: chats sin temas.
- `foros`: grupos con foro. `general` es el tema de respaldo.
- `temas`: nombre del tema y su `topic_id`.

### Obtener los IDs reales

Con la sesión del uploader ya creada:

```bash
# Lista tus chats/grupos
bash servicios/pipe_chats.sh --creados

# Lista los temas de un foro concreto
bash servicios/pipe_topics.sh -1000000000002
```

Los IDs que imprime `pipe_topics` son los que van en `temas[].id`. El ID del foro va en `foros[].id`.

Tras editar `grupos.json`, reinicia el uploader:

```bash
docker restart telegram-uploader-sendo
```

El uploader carga `grupos.json` al arrancar, no en cada archivo.

## 7. Construir las imágenes

Si usaste el instalador, ya están construidas. Para hacerlo a mano:

```bash
cd ~/devjobs

docker compose -f TwitchRecorder/docker-compose.yml build
docker compose -f ffmpeg-yt-dlp/docker-compose.yml build monitor
docker compose -f downloader_telegram/docker-compose.yml build uploader
```

El servicio `telegram` del compose es el CLI interactivo, no el daemon.

## 9. Auto-arranque con systemd

`instalar_ubuntu.sh` ya crea y habilita el servicio. Para gestionarlo:

```bash
sudo systemctl status twitch-stream-pipeline.service
sudo systemctl restart twitch-stream-pipeline.service
sudo systemctl stop twitch-stream-pipeline.service
```

O con los aliases:

```bash
pipe_sys_status
pipe_sys_start
pipe_sys_stop
```

El servicio es de tipo `oneshot` con `RemainAfterExit=yes`: arranca los tres compose y los para al detenerse. Usa el usuario que ejecutó el instalador y añade el grupo `docker` como suplementario.

### Instalación manual del servicio

```bash
cd ~/devjobs

# Ajusta User= y las rutas absolutas del archivo a tu usuario y tu ruta.
# Añade SupplementaryGroups=docker si el archivo no lo trae.
sudo cp servicios/twitch-stream-pipeline.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now twitch-stream-pipeline.service
```

Revisa antes de copiarlo:

```bash
grep -E '^(User|WorkingDirectory|ExecStart|ExecStop)=' servicios/twitch-stream-pipeline.service
```

### WSL2

Si `systemctl` no funciona, activa systemd en `/etc/wsl.conf`:

```ini
[boot]
systemd=true
```

Luego, desde PowerShell:

```powershell
wsl --shutdown
```

Vuelve a entrar en WSL y comprueba:

```bash
systemctl is-system-running
```

## 10. Actualizar el pipeline

| Cambio | Comando |
|--------|---------|
| Código Python o Dockerfile | `pipe_rebuild` |
| `config.json`, `grupos.json` o variable de entorno | `pipe_recreate` |
| Solo el uploader | `docker restart telegram-uploader-sendo` |
| Parar todo | `pipe_down` |
| Volver a arrancar | `pipe_up` |

`pipe_rebuild` hace build y `--force-recreate` de los tres servicios. Tarda más, pero es el único que garantiza que el código nuevo está dentro de la imagen. Ojo: `pipe_down` hace `down` en los tres compose.

## 11. Problemas habituales

| Problema | Causa probable | Solución |
|----------|----------------|----------|
| `permission denied` al usar Docker | Tu sesión no tiene el grupo del socket | Cierra sesión y entra de nuevo, o `newgrp docker` |
| `docker compose` no existe | Docker v1 o plugin ausente | Instala `docker-compose-plugin`; comprueba `docker compose version` |
| El uploader no arranca | Faltan `config.bin`, `secret.key`, `grupos.json` o `uploader.session` | Ejecuta `pipe_credenciales.sh` para credenciales/sesión, crea `grupos.json` y luego `pipe_recreate` |
| `--verificar` falla | La clave no descifra `config.bin` o la sesión caducó | Revisa `secret.key`/`config.bin`; si la sesión caducó, `pipe_setup.sh --reset` |
| No graba ningún directo | Canal desactivado, sin `schedule` o fuente mal configurada | Revisa `config.json` y `tw_logs` |
| Graba pero el monitor no coge el vídeo | El archivo no se llama `*_completed.mp4` | Comprueba `copy_to_test` y `grabaciones/test` |
| El vídeo se mueve a `.corruptos` | `ffprobe` no lo lee o dura menos de 60 s | Revisa la grabación y los logs del monitor |
| El uploader no rutea al tema correcto | Keyword y nombre del tema no coinciden | Ajusta `temas` en `grupos.json` o prueba con `pipe_test` |
| El vídeo sale como documento | Faltan atributos de vídeo o thumbnail | Revisa los logs del uploader y `ffprobe` |
| Telegram rechaza la subida | El archivo supera el límite y no se dividió | Comprueba el tamaño y los logs de partición; el monitor debería dejarlo por debajo de `TAMANO_MAX_MB` |
| Se llena el disco | Logs o grabaciones antiguas | El instalador limita logs; revisa `grabaciones/` y `comprimidos/` |
| La hora no coincide | Contenedor con `TZ` incorrecta o host desincronizado | Ajusta `TZ` y activa NTP (`timedatectl set-ntp true`) |

Para un diagnóstico más detallado:

```bash
plogs
docker logs --tail 100 twitchrecorder-sendo
docker logs --tail 100 ffmpeg_monitor-sendo
docker logs --tail 100 telegram-uploader-sendo
```
