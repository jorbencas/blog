Tech Pulse es un pipeline completo de automatización: scraping de 627 fuentes, resúmenes con IA, notificaciones Telegram (noticias cada 30 minutos y estrenos al topic «report img»), newsletter por email, tips de IT y herramientas IA. Pero para que funcione, necesitas configurar varias API keys. Cada una tiene su propósito y te explico cómo obtenerlas.

---

## 1. Por qué Tech Pulse (y no otra cosa)

| Herramienta | Qué hace | Limitación |
|-------------|----------|------------|
| **Feedly** | Lee RSS | No filtra por relevancia, no genera resúmenes IA |
| **Google News** | Noticias tech | No scraping directo, no personalizable |
| **Herramientas manuales** | Scraping a medida | Requieren mantenimiento constante |
| **Tech Pulse** | Scraping + IA + notificaciones + web | Todo automatizado, 627 fuentes, 224 tests |

**¿Por qué Python?** Ecosistema de scraping (requests, beautifulsoup), IA (google-generativeai), flexibilidad para integrar todo en un solo pipeline.

**¿Por qué Gemini?** Gratis tier generoso, buena calidad en español, resúmenes naturales. Fallback a Ollama/Qwen local si falla.

**¿Por qué GitHub Actions?** CI/CD gratis, cron integrado, secrets seguros, despliegue automático a Surge.sh/Vercel.

## 3. Obtener la API Key de Gemini

**Qué es:** Una clave que le da acceso a tu script a los modelos de IA de Google (Gemini). Se usa para generar resúmenes de noticias, tips de programación y herramientas IA.

**Cómo obtenerla:**

1. Ve a [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
2. Inicia sesión con tu cuenta de Google (la misma que usas para Gmail)
3. Haz clic en **"Create API Key"**
4. Selecciona un proyecto (o crea uno nuevo — da igual cuál)
5. Copia la API key que empieza por `AIza...`
6. **Guarda esa key** — la necesitarás en el paso 8

**¿Es gratis?** Sí, el tier gratuito permite 1500 requests/día. Tech Pulse hace ~100 requests/día, así que sobra.

**¿Qué pasa si no la configuro?** El sistema usa fallback: primero intenta Gemini, si falla usa una base de datos local de definiciones. Los tips y herramientas funcionan igual, pero con menos variedad.

## 4. Obtener el token de Telegram

**Qué es:** La "contraseña" de tu bot de Telegram. Se usa para enviar notificaciones de noticias.

**Cómo obtenerlo:**

1. Abre Telegram (en el móvil o en el escritorio) y busca [@BotFather](https://t.me/BotFather)
2. Envía `/newbot` (escribe `/newbot` y dale a enviar)
3. BotFather te preguntará: **"¿Cómo se llamará tu bot?"** — Escribe un nombre descriptivo, ej: "Tech Pulse Bot"
4. BotFather te preguntará: **"¿Cuál será el username?"** — Debe terminar en `bot`. Ejemplo: `techpulse_bot`
5. BotFather te dará un token como `8580222159:AAE4e21gzeq6q...`. **Copia y guarda ese token inmediatamente**
6. Si pierdes el token, puedes pedirlo de nuevo con `/mybots` → selecciona tu bot → "API Token"

**¿Y el chat_id?** Es el ID del canal o grupo donde quieres recibir notificaciones. Para obtenerlo:

**Opción A (grpib):**
1. Añade tu bot al grupo de Telegram
2. Envía un mensaje al grupo
3. Abre `https://api.telegram.org/botTU_TOKEN/getUpdates` en el navegador
4. Busca `"chat":{"id":-1001234567890}` — ese número es tu chat_id

**Opción B (simple):**
1. Crea un canal privado en Telegram
2. Añade tu bot como administrador
3. Envía un mensaje al canal
4. Usa el mismo método de arriba para obtener el chat_id

**¿Por qué no funciona sin chat_id?** Porque Telegram necesita saber **dónde** enviar el mensaje. Sin chat_id, el bot no tiene destino.

## 5. Obtener la API Key de Mailgun

**Qué es:** Un servicio de envío de emails transaccionales. Se usa para enviar la newsletter diaria con resúmenes de noticias.

**Cómo obtenerla:**

1. Ve a [signup.mailgun.com](https://signup.mailgun.com/)
2. Crea una cuenta (gratis: 100 emails/día durante 30 días, luego $1/mes)
3. En el dashboard, ve a **Sending** → **API Keys**
4. Copia la API key (empieza por `key-...`)
5. En **Domains**, verifica un dominio (o usa el dominio de prueba `sandbox...mailgun.org`)

**¿Es indispensable?** No. Si no configuras Mailgun, el newsletter no se envía pero el resto funciona (gestor web, Telegram, tips).

**¿Qué pasa si uso el dominio de prueba?** Solo puedes enviar emails a direcciones que hayas verificado en Mailgun. Para envíos reales, necesitas un dominio propio.

## 6. Clonar y configurar

```bash
# 1. Clonar el repo
git clone https://github.com/jorbencas/test_githubActions.git
cd test_githubActions

# 2. Crear entorno virtual
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
# .venv\Scripts\activate   # Windows

# 3. Instalar dependencias
pip install -r requirements.txt
```

**¿Qué instala?** Todas las dependencias necesarias: requests, beautifulsoup4, google-generativeai, telethon, etc.

## 7. Configurar variables de entorno

Crea el archivo `.env` en la raíz del proyecto:

```bash
cat > .env << EOF
# Gemini API (recomendado — para resúmenes y tips)
GEMINI_API_KEY=AIzaSy...tu_api_key

# Telegram (opcional — para notificaciones)
TELEGRAM_BOT_TOKEN=8580222159:AAE4e21gzeq6q...
TELEGRAM_CHAT_ID=-1004332325883

# Mailgun (opcional — para newsletter email)
MAILGUN_API_KEY=key-...tu_api_key
MAILGUN_DOMAIN=tudominio.com
EMAIL_USER=tu@email.com
EOF
```

### Por qué cada variable

| Variable | Para qué | Si no la pones |
|----------|----------|----------------|
| `GEMINI_API_KEY` | Resúmenes IA, tips, herramientas | Fallback a DB local (funciona pero con menos variedad) |
| `TELEGRAM_BOT_TOKEN` | Enviar notificaciones | Notificaciones Telegram deshabilitadas |
| `TELEGRAM_CHAT_ID` | Destino de notificaciones | Notificaciones Telegram deshabilitadas |
| `MAILGUN_API_KEY` | Enviar newsletter email | Email deshabilitado |
| `MAILGUN_DOMAIN` | Dominio de envío | Email deshabilitado |
| `EMAIL_USER` | Email destino | Email deshabilitado |

### Dónde va el archivo

En la raíz de `test_githubActions/`:

```

├── .env                    ← AQUÍ
├── requirements.txt
├── scripts/
└── ...
```

## 8. Probar el scraping

```bash
# Scraping completo (todas las 627 fuentes — tarda ~30 min)
python -m scripts.scrapers.scrape_news --tier full

# Scraping ligero (solo quick sources, ~15 min)
python -m scripts.scrapers.scrape_news --tier light

# Scrapear herramientas de GitHub
python -m scripts.scrapers.scrape_tools
```

**¿Qué genera?** Archivos JSON en `files/`:
- `noticias_historico.json` — Todas las noticias scrapeadas
- `herramientas.json` — Herramientas de GitHub

**¿Cuánto tarda?** El scraping completo tarda ~30 minutos. El ligero ~15 minutos. Es normal porque hay 627 fuentes que consultar.

**¿Qué pasa si falla alguna fuente?** El sistema tiene fallbacks: si una fuente falla, la salta y sigue con las demás. No se detiene por un error individual.

## 9. El gestor de fuentes (web)

La web es estática: no hay nada que generar. `public/index.html` es el **gestor de fuentes** (alta/baja de fuentes, filtros por tipo y proyecto, búsqueda, export JSON) y `public/data/fuentes.json` es el snapshot con las 636 fuentes.

```bash
# Previsualizar en local
python -m http.server -d public
# Abrir http://localhost:8000 en el navegador
```

**¿Cómo se despliega?** El workflow `dashboard_update` publica en [Surge](http://jorbencasdownloaderdocument.surge.sh) en cada push que toca `public/**`. Si cambias fuentes desde la web: **⬇ Exportar JSON** → reemplaza `public/data/fuentes.json` → push.

## 13. Uso en GitHub Actions (recomendado)

El proyecto está diseñado para ejecutarse automáticamente via GitHub Actions. Los workflows ya están configurados:

| Workflow | Frecuencia | Qué hace |
|----------|------------|----------|
| `scrape_all_workflow.yml` | Cada hora | Scraping de fuentes quick |
| `scraper_workflow.yml` | Sábados 07:00 UTC | Pipeline semanal: noticias + herramientas + recap del blog |
| `daily_content.yml` | Cada 3 horas | Generar tips de IT y herramientas IA |
| `daily_resources.yml` | Diario (06:00 UTC) | Actualizar resources del blog |
| `send_email_workflow.yml` | Diario (09:00 UTC) | Enviar newsletter |
| `send_telegram_workflow.yml` | Cada 30 minutos | Enviar noticias a Telegram |
| `formulatv_telegram.yml` | Cada 15 minutos | Enviar estrenos al topic «report img» |
| `movie_scrapers.yml` | Cada 3 horas | Scrapers de películas concretas |
| `dashboard_update.yml` | Push a `public/**` | Desplegar el gestor de fuentes a Surge |
| `tests.yml` | Push/PR a master | Ejecutar pytest |

### Configurar GitHub Secrets

En tu fork del repo, ve a **Settings** → **Secrets and variables** → **Actions** y añade:

| Secret | Valor |
|--------|-------|
| `GEMINI_API_KEY` | Tu API key de Gemini |
| `TELEGRAM_BOT_TOKEN` | Token del bot |
| `TELEGRAM_CHAT_ID` | ID del chat/grupo |
| `MAILGUN_API_KEY` | API key de Mailgun |
| `MAILGUN_DOMAIN` | Dominio de Mailgun |
| `EMAIL_USER` | Email destino |

**¿Por qué GitHub Secrets y no `.env`?** Porque GitHub Actions no puede leer archivos `.env`. Los secrets se inyectan como variables de entorno durante la ejecución del workflow.

## Troubleshooting

| Problema | Causa | Solución |
|----------|-------|----------|
| `ModuleNotFoundError` | Falta instalar dependencias | `pip install -r requirements.txt` con venv activado |
| `GEMINI_API_KEY not set` | No configurada | Añadir al `.env` o configurar en GitHub Secrets |
| `Rate limit exceeded` | Demasiadas peticiones | Esperar o reducir frecuencia de scraping |
| `Telegram send failed` | Token o chat_id incorrecto | Verificar en `.env` o GitHub Secrets |
| `Connection refused` (Mailgun) | API key incorrecta | Verificar en dashboard de Mailgun |
| `No module named 'bs4'` | Falta beautifulsoup | `pip install beautifulsoup4` |
| `Timeout` | scraping tarda mucho | Normal en `--tier full`; usar `--tier light` para probar |
