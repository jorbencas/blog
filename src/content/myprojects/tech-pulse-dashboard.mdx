## 1. El Planteamiento del Problema

El ecosistema tecnológico publica decenas de noticias, vídeos y recursos cada día. Seguir el ritmo manualmente es imposible. Herramientas como Feedly o Google News son genéricas, no filtran por relevancia técnica real ni ofrecen resúmenes inteligentes.

Se necesitaba un sistema que:
- Recolectara automáticamente contenido de 330+ fuentes (YouTube, blogs tech, RSS, GitHub Topics, Product Hunt)
- Clasificara y deduplicara el contenido en tiempo real
- Generara resúmenes por noticia y un recap semanal con IA
- Desplegara un dashboard SSR interactivo con filtros combinables
- Enviara notificaciones por Telegram cada 30 minutos con audio TTS
- Enviara una newsletter diaria con resúmenes curados

## 2. La Solución Arquitectónica

**Tech Pulse** nace como un pipeline completo de automatización orquestado por GitHub Actions, construido en Python asíncrono con scripts modulares independientes.

### Capas del Sistema

- **Capa de Extracción (Scraping):** Arquitectura de extractores especializados:
  - `YouTubeExtractor` — parsea JSON `ytInitialData` directamente (vídeos, shorts, livestreams)
  - `WebExtractor` — BeautifulSoup con selectores CSS personalizados por fuente + `extraer_rss()` para feeds XML (RSS 2.0 y Atom) + `extraer_herramientas()` para GitHub Topics, Collections, Repos y Product Hunt
  - `ScraperPro` facade con semáforo de concurrencia (5 peticiones simultáneas)
  - `AvatarRepository` — caché de avatares de canales YouTube con fallback a UI Avatars

- **Capa de Procesamiento IA:** Integración con Gemini API para:
  - Resumen semanal con análisis de tendencias (modelo `gemini-2.5-pro`)
  - Resumen individual por noticia (vía `extraer_texto_articulo()` + `resumir_noticia()`)
  - Traducción de títulos al español en lote
  - Generación de imágenes para posts con Imagen

- **Capa de Persistencia:** Historial JSON con deduplicación automática por URL normalizada y título similar. Sin límite de entradas.

- **Capa de Distribución:**
  - Dashboard HTML SSR desplegado en Surge.sh (Python genera el HTML completo)
  - Newsletter HTML con diseño responsive vía Mailgun
  - Notificaciones Telegram cada 30 min con audio edge-tts (voz española)
  - Posts en markdown para blog Astro vía PR automático

### Pipeline de Contenido

Cada script es independiente y orquestable por separado. La estructura se reorganizó en subdirectorios modulares:

4. `python -m scripts.publishers.send_email` → Mailgun (diario 09:00 UTC)
5. `python -m scripts.publishers.send_telegram` → Telegram con TTS (cada 30 min)

## 3. Retos Técnicos y Decisiones de Diseño

### Arquitectura Modular vs Monolito

Originalmente todo el scraping vivía en un único `downloadFile.py`. Se refactorizó a scripts independientes agrupados en subdirectorios (`scrapers/`, `publishers/`, `tools/`, `utils/`) para permitir ejecución selectiva por workflow y facilitar el mantenimiento. Cada script tiene sus propias dependencias y puede ejecutarse en solitario con `python -m scripts.subdir.script`.

### Deduplicación Inteligente

La función `deduplicar_items()` en `common.py` elimina duplicados en dos niveles:
- **URL normalizada:** quita `?utm_*`, `#fragment`, trailing `/`, normaliza `http` → `https`
- **Título similar:** compara el prefijo al 85% del título más corto para detectar la misma noticia con variaciones

```python
def normalizar_url(url: str) -> str:
    url = url.split("?")[0].split("#")[0].rstrip("/")
    return url.replace("http://", "https://").lower()
```

### Deduplicación Cross-File en Resources

`manage_resources.py` implementa `deduplicate_all_files()` con un `global_seen_urls` que deduplica no solo dentro de cada archivo, sino **entre todos los archivos** del blog. Si una URL aparece en `resources.mdx` y también en `resources3.mdx`, se elimina la duplicada manteniendo la primera aparición.

```python
global_seen_urls: set = set()
for archivo in archivos:
    urls_archivo = set()
    for line in lines:
        url = _extraer_url_card(line)
        if url in global_seen_urls:
            continue  # duplicado cross-file → eliminar
        global_seen_urls.add(url)
```

### Fix de Cards Malformados

Nueva función `fix_malformed_cards()` detecta y repara ResourceCard tags con `/` en lugar de `/>`:

```python
# Malformed: <ResourceCard ... />
# Fixed:    <ResourceCard ... />
```

Se integra en `fix_all_files()` y se ejecuta automáticamente con `--fix-spacing`.

### Refactor SOLID del Frontend JavaScript

El dashboard client-side se reescribió siguiendo principios SOLID:

- **Store Observable:** Un `store` con `get()`/`set()`/`on()` elimina 10+ variables globales y el monolítico `onTipoFuenteChange()` que manejaba todos los eventos juntos.
- **Fábrica genérica de chips:** `renderChips()` + `renderCanalChips()` reemplazan 8 funciones de renderizado duplicadas.
- **Helpers puros:** `limpiarFuente()`, `tipoFuente()`, `itemEnSemana()`, `faviconSrc()` — cero efectos secundarios, fáciles de testear.
- **Filtros unificados:** `aplicarFiltrosNoticias()` / `aplicarFiltrosVideos()` operan sobre el DOM reaccionando a cambios del store mediante suscripciones.
- **Sin memory leaks:** `on()` devuelve una función `unsubscribe` que elimina el handler del array de listeners.

### Externalización de Configuración

Todo el JSON embebido, prompts de IA, plantillas HTML y valores por defecto se movieron a `constants_downloadfile.py`:
- **Prompts de IA:** `PROMPT_RESUMIR_LOTE`, `PROMPT_RESUMIR_NOTICIA`, `PROMPT_RECAP_SEMANAL`, `PROMPT_TRADUCIR_TITULOS` como templates `.format()`.
- **Config JS:** canales YouTube, tabs multimedia, opciones de filtro, URL del dashboard — se inyectan vía `data.json`.
- **Plantillas:** Telegram (`TELEGRAM_MENSAJE_TEMPLATE`), email (`EMAIL_ROW_TEMPLATE`), fallbacks.
- **Constantes de dict keys:** Todos los strings de acceso a diccionarios (`"enlace"`, `"fuente"`, `"titulo"`, `"yt"`, etc.) son constantes con nombre. Si en el futuro cambia un key del schema, se edita una sola línea.

### Reorganización de Scripts (Julio 2026)

Los scripts se reorganizaron de la raíz del proyecto a subdirectorios modulares:

- **`utils.py` → `scripts/utils/common.py`**: Renombrado para evitar sombreado de módulos con `utils/` del sistema

- **`tests/`**: Migrados desde `blog/tests/python/` (101 tests pytest)
- **Todos los workflows actualizados** para usar `python -m scripts.subdir.script` en lugar de `python script.py`
- **Nuevo workflow `tests.yml`**: Ejecuta pytest en cada push/PR a master
- **Eliminados `scrape_social.py` y `scrape_trends.py`**: Redes sociales (Instagram, X/Twitter, Threads, TikTok) y Google Trends removidos del ecosistema
- **Dashboard migrado a SSR**: Python genera `index.html` completo, JavaScript solo maneja interactividad (~135 líneas)

### Fix de Pipeline de Imágenes (Julio 2026)

Se corrigió un bug en `fix_images.py` que eliminaba el `import ResponsiveImage` de posts del blog:

- **Causa**: el script borraba el import siempre y solo lo re-agregaba si encontraba `<ResponsiveImage` en el contenido
- **Solución**: nueva lógica condicional que preserva el import cuando el componente se usa:
  - Si componente existe + import falta → agregar import después del frontmatter
  - Si componente NO existe + import existe → eliminar import
  - Si ambos existen → no hacer nada (mantener)

### Node.js 22 Upgrade (Julio 2026)

El workflow `test.yml` se actualizó de Node.js 20 a 22, requerido por Astro 6.4 que soporta `>=22.12.0`.

### Renderizado SSR del Dashboard

Python genera un `index.html` completo con todo el contenido pre-renderizado (noticias, vídeos YouTube, ranking GitHub). JavaScript (`script.js`) es mínimo (~135 líneas) y solo maneja:

- **Filtros combinables:** categoría (IA, Programación, DevOps, etc.), tipo (Tech/RSS), fuente RSS específica, canal, semana
- **Chips con favicon:** cada chip de canal/fuente muestra avatar o favicon via Google S2 (`//www.google.com/s2/favicons?domain=...`)
- **Ranking GitHub Stars:** top 20 repos ordenados por estrellas extraídos de GitHub Topics/Collections, con filtro por nombre/lenguaje
- **Sección de Referencia Tech:** panel colapsable con Skills, LLMs, Lenguajes, Frameworks y Librerías ordenados por categoría — datos inyectados desde Python, sin hardcode en JS
- **Badges con clases CSS unificadas:** `.badge-tech`, `.badge-rss`, `.badge-cat`
- **Config externalizada:** canales, tabs, opciones de filtro se inyectan directamente en el HTML desde Python

### Telegram con Audio por Noticia

`send_telegram.py` envía cada noticia nueva como mensaje separado con:
- Resumen IA de 3-4 líneas generado por Gemini en español
- Títulos traducidos automáticamente al español vía `traducir_titulo()` con Gemini
- Audio TTS con edge-tts (voz `es-ES-AlvaroNeural`) — resumen de todos los titulares una vez al día
- Control de duplicados vía `telegram_sent.json` + `telegram_voice_sent.json`
- Texto del audio limpio de emojis para mayor claridad

> **Actualizado julio 2026:** Eliminadas todas las fuentes de redes sociales (Instagram, X/Twitter, TikTok, Threads, Google Trends). El ecosistema monitoriza actualmente **330 fuentes** en **7 categorías**.

## 5. Puesta en Marcha Local

```bash
git clone https://github.com/jorbencas/test_githubActions.git
cd test_githubActions
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Scrapear noticias (tier completo)
python -m scripts.scrapers.scrape_news --tier full

# Scrapear herramientas
python -m scripts.scrapers.scrape_tools

# Ejecutar tests

```
