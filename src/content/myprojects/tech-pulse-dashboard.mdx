## 1. El Planteamiento del Problema

Cada día aparecen decenas de noticias, vídeos y recursos nuevos en el mundo de la tecnología. Sigue el ritmo manualmente es imposible: tienes que revisar YouTube, RSS, blogs, GitHub, Product Hunt... y al final te pierdes lo más importante.

**Mi motivación:** Empecé a hacer un blog de tecnología y me di cuenta de que necesitaba contenido fresco constantemente. Pero no quería copiar y pegar de otros sitios: quería curar, filtrar y resumir lo mejor. El problema es que revisar 400+ fuentes cada día a mano era un trabajo de tiempo completo.

Así que hice **Tech Pulse**: un sistema que hace todo automáticamente. Recolecta contenido de más de 400 fuentes, lo clasifica con inteligencia artificial, genera resúmenes y lo manda por Telegram y email. Yo solo tengo que leer lo que me interesa.

## El problema

El ecosistema tecnológico publica decenas de noticias, vídeos y recursos cada día. Seguir el ritmo manualmente es imposible. Herramientas como Feedly o Google News son genéricas, no filtran por relevancia técnica real ni ofrecen resúmenes inteligentes.

Se necesitaba un sistema que:
- Recolectara automáticamente contenido de 400+ fuentes (YouTube, blogs tech, RSS, GitHub Topics, Product Hunt)
- Clasificara y deduplicara el contenido en tiempo real
- Generara resúmenes por noticia y un recap semanal con IA
- Desplegara un dashboard SSR interactivo con filtros combinables
- Enviara notificaciones por Telegram cada 30 minutos con audio TTS a las 21:00 UTC
- Enviara una newsletter diaria con resúmenes curados y videos
- Incluyera herramientas Markdown offline (PDF, diapositivas, tablas, snippets, cheatsheet)

## La solución

**Tech Pulse** nace como un pipeline completo de automatización orquestado por GitHub Actions, construido en Python asíncrono con scripts modulares independientes.

### Capas del Sistema

- **Capa de Extracción (Scraping):** Arquitectura de extractores especializados:
  - `YouTubeExtractor` — parsea JSON `ytInitialData` directamente (vídeos, shorts, livestreams)
  - `WebExtractor` — BeautifulSoup con selectores CSS personalizados por fuente + `extraer_rss()` para feeds XML (RSS 2.0 y Atom) + `extraer_herramientas()` para GitHub Topics, Collections, Repos y Product Hunt
  - `ScraperPro` facade con semáforo de concurrencia (5 peticiones simultáneas) + soporte para **fuentes duales** (YouTube + web scraping simultáneo)
  - `AvatarRepository` — caché de avatares de canales YouTube con Google Favicons

- **Capa de Procesamiento IA:** Integración con Gemini API para:
  - Resumen semanal con análisis de tendencias (modelo `gemini-2.5-pro`)
  - Resumen individual por noticia (vía `extraer_texto_articulo()` + `resumir_noticia()`)
  - Traducción de títulos al español en lote (**solo items nuevos** — flag `traducido` persiste en JSON)
  - Generación de imágenes para posts con Imagen
  - **Resúmenes persistidos** en `noticias_historico.json` para evitar re-procesamiento

- **Capa de Persistencia:** Historial JSON con deduplicación automática por URL normalizada y título similar. Sin límite de entradas. Caché de Telegram con TTL de 7 días.

- **Capa de Distribución:**
  - Dashboard HTML SSR desplegado en Surge.sh (Python genera el HTML completo)
  - Newsletter HTML agrupada por fuente con sección de videos vía Mailgun
  - Notificaciones Telegram cada 30 min (**solo noticias, sin vídeos**) + **audio TTS a las 21:00 UTC con TODAS las noticias del día**
  - Posts en markdown para blog Astro vía PR automático

Todos los scripts se ejecutan con `python -m` desde la raíz del proyecto:

1. `python -m scripts.scrapers.scrape_news --tier full` → `files/noticias_historico.json` (web + YouTube + RSS)
2. `python -m scripts.scrapers.scrape_tools` → `files/herramientas.json` (GitHub Trending + Product Hunt + 52 Topics)
3. `python -m scripts.publishers.generate_weekly --blog-path blog` → `auto-news/` (recap MD) + `public/` (dashboard HTML)
4. `python -m scripts.publishers.send_email` → Mailgun (diario 09:00 UTC)
5. `python -m scripts.publishers.send_telegram` → Telegram solo noticias + audio TTS (cada 30 min, audio 21:00 UTC)
6. `python scripts/backfill_traducido.py` → Marca items existentes como traducidos (una vez)

## 3. Retos Técnicos y Decisiones de Diseño

### Arquitectura Modular vs Monolito

Originalmente todo el scraping vivía en un único `downloadFile.py`. Se refactorizó a scripts independientes agrupados en subdirectorios (`scrapers/`, `publishers/`, `tools/`, `utils/`) para permitir ejecución selectiva por workflow y facilitar el mantenimiento. Cada script tiene sus propias dependencias y puede ejecutarse en solitario con `python -m scripts.subdir.script`.

### Fuentes Duales: YouTube + Web Scraping

Cuando una fuente tiene tanto `url` como `yt` (como MoureDev, Midudev, Carlos Azaustre, Xataka), `ScraperPro.extraer()` ahora extrae de **ambas fuentes simultáneamente** usando `asyncio.gather()`. Los items de YouTube van a la sección Multimedia, los de web scraping a Noticias, y ambos muestran chips de filtro en ambas secciones.

```python
elif YT_KEY in info and URL_KEY in info:
    yt_url = info[YT_KEY]
    web_url = info[URL_KEY]
    yt_results, web_results = await asyncio.gather(
        self._extraer_yt(session, nombre, yt_url),
        self._extraer_web(session, nombre, web_url, info),
    )
    results = yt_results + web_results
```

### Traducción Inteligente — Solo Items Nuevos

Se eliminó la re-traducción masiva. Ahora cada item tiene un flag `traducido=True` que persiste en `noticias_historico.json`. Solo se traducen items nuevos:

- `traducir_titulos_ia()` en `common.py` — salta items con `traducido=True`
- `send_telegram.py` — usa título ya traducido si existe
- `send_email.py` — salta traducción si ya está traducido
- Resúmenes se persisten en `n['resumen']` para evitar re-summarización
- `backfill_traducido.py` — migración una vez para marcar 6,612 items existentes

### Deduplicación Inteligente

La función `deduplicar_items()` en `common.py` elimina duplicados en dos niveles:
- **URL normalizada:** quita `?utm_*`, `#fragment`, trailing `/`, normaliza `http` → `https`
- **Título similar:** compara el prefijo al 85% del título más corto para detectar la misma noticia con variaciones

```python
def normalizar_url(url: str) -> str:
    url = url.split("?")[0].split("#")[0].rstrip("/")
    return url.replace("http://", "https://").lower()
```

### Deduplicación Cross-File en Resources

`manage_resources.py` implementa `deduplicate_all_files()` con un `global_seen_urls` que deduplica no solo dentro de cada archivo, sino **entre todos los archivos** del blog. Si una URL aparece en `resources.mdx` y también en `resources3.mdx`, se elimina la duplicada manteniendo la primera aparición.

### Fix de Cards Malformados

Nueva función `fix_malformed_cards()` detecta y repara ResourceCard tags con `/` en lugar de `/>`:

```python
# Malformed: <ResourceCard ... />
# Fixed:    <ResourceCard ... />
```

Se integra en `fix_all_files()` y se ejecuta automáticamente con `--fix-spacing`.

### Refactor SOLID del Frontend JavaScript

El dashboard client-side se reescribió siguiendo principios SOLID:

- **Store Observable:** Un `store` con `get()`/`set()`/`on()` elimina 10+ variables globales y el monolítico `onTipoFuenteChange()` que manejaba todos los eventos juntos.
- **Fábrica genérica de chips:** `renderChips()` + `renderCanalChips()` reemplazan 8 funciones de renderizado duplicadas.
- **Helpers puros:** `limpiarFuente()`, `tipoFuente()`, `itemEnSemana()`, `faviconSrc()` — cero efectos secundarios, fáciles de testear.
- **Filtros unificados:** `aplicarFiltrosNoticias()` / `aplicarFiltrosVideos()` operan sobre el DOM reaccionando a cambios del store mediante suscripciones.
- **Sin memory leaks:** `on()` devuelve una función `unsubscribe` que elimina el handler del array de listeners.

### Externalización de Configuración

Todo el JSON embebido, prompts de IA, plantillas HTML y valores por defecto se movieron a módulos especializados:
- **Prompts de IA:** `PROMPT_RESUMIR_LOTE`, `PROMPT_RESUMIR_NOTICIA`, `PROMPT_RECAP_SEMANAL`, `PROMPT_TRADUCIR_TITULOS` como templates `.format()` en `constants_templates.py`.
- **Config JS:** canales YouTube, tabs multimedia, opciones de filtro, URL del dashboard — se inyectan vía `data.json`.
- **Plantillas:** Telegram (`TELEGRAM_MENSAJE_TEMPLATE`), email (`EMAIL_ROW_TEMPLATE`, `EMAIL_SOURCE_HEADER`, `EMAIL_VIDEO_ROW`), fallbacks — todo en `constants_templates.py`.
- **Constantes de dict keys:** Todos los strings de acceso a diccionarios (`"enlace"`, `"fuente"`, `"titulo"`, `"yt"`, etc.) son constantes con nombre. Si en el futuro cambia un key del schema, se edita una sola línea.
- **Fuentes:** `constants_sources.py` contiene el dict `FUENTES` con 400+ fuentes, separado del resto de configuración.

## 6. Markdown Tools (Agosto 2026)

Desde el dashboard se accede a una sección de **Markdown Tools** — 5 herramientas offline que funcionan 100% en el navegador:

- **Markdown a PDF** — Convierte Markdown a PDF con tablas, listas, bloques de código y encabezados estilizados (pdfmake). Limitaciones documentadas en la UI: máx. 50 páginas, máx. 500 filas por tabla, sin syntax highlighting en PDF.
- **Diapositivas** — Crea presentaciones estilo Reveal.js desde Markdown, separando slides con `---`. Navegación con flechas y modo fullscreen.
- **Tabla Markdown** — Genera tablas Markdown a partir de datos tabulares (TSV, CSV, JSON) con alineación configurable.
- **Snippets de Código** — Extrae y formatea fragmentos de código con numeración de líneas.
- **Cheatsheet** — Referencia rápida de Markdown: encabezados, texto, listas, tablas, emojis, shortcodes.

### Arquitectura

- **Python generator:** `mdtools/build.py` genera 6 páginas HTML usando `constants_mdtools.py` (string templates con `{placeholders}`, mismo patrón que `HTML_TEMPLATE`)
- **CSS modular:** 6 archivos (base, nav, editor, tools, dark-theme, responsive) con variables CSS y soporte `prefers-color-scheme`
- **JS client-side:** markdown-it (Web Worker), pdfmake (Web Worker), navegación, generación de tablas y snippets
- **Deploy compartido:** mdtools se genera en `public/mdtools/` y se despliega junto con el dashboard en el mismo dominio Surge.sh
- **Nav integrada:** enlace "← Dashboard" en mdtools, enlace "Markdown Tools" en el dashboard
